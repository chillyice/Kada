      毫秒（按住超过此值 = 长按）
      这些形态分别是什么意思

      单次键 = 单击后该键应用到下一个按键（修饰键是常见用法：「单次 Ctrl」= 下一次按键带 Ctrl；非修饰键 = 替你按住它到下一个按键）；粘滞键 = 单击锁定、再击解锁（「粘滞 Shift」连打几个大写、侧键做「按住说话」）。短按 = 快速点击输出该键（双击/三击为连击不同义）；长按 = 按住超过阈值输出该键。这些形态与普通改键互斥，都留空则用「改为」。例：CapsLock 短按 Esc、长按 Ctrl。

      切层键（长按进入层 / 长按锁定层）在「层」页签里设。

      输入触发词后按 空格 / 回车 / Tab 自动回删并展开；留空替换文本 = 删除该触发词。

      条目只在归属层被切层键打开时生效；「基础层」= 始终生效。切层键在改键里设「长按进入层 / 长按锁定层」。

      两种切层键的区别

      「长按进入层」= 按住切层键期间该层才生效，松手退回（层内放和弦/序列得一边按住切层键一边凑键，很难按）；「长按锁定层」= 长按一下切到该层并保持生效、再长按一下退出，适合层内放和弦/序列的用法。两者与「长按」互斥。

      文本扩展不参与键位层：它按输入内容匹配，与当前哪一层无关。

      条件不成立时等价于「这条不存在」：落到下一条同触发键的条目，没有就放行原键。

      外观与提示
      这两个浮窗的细节

      「输入状态悬浮指示」显示当前激活层与注入中的修饰键（按住 / 粘滞 / 单次），没有东西生效时自动消失；托盘图标右键悬停也能看到同一句摘要。关掉它就只剩托盘提示。长按锁定层会一直挂着这条指示——这是有意的，锁定层生效期间基础层按键会被遮蔽，「看不见状态」正是最容易被误判成「按键失灵」的时候。

      「快捷键提示框」把所有已启用的快捷键按层列出来（基础层在最上）。鼠标放上去会让位（穿透 + 变淡，不挡住你正点的页面），停在上面 2 秒才恢复可交互；拖面板任意位置移动；滚轮调大小、Ctrl+滚轮调透明度（缩小字号能一屏塞下更多条目）；列表太长时 Shift+滚轮 或拖滚动条滚动。位置、大小、透明度都随配置保存，下次启动还在原地。点窗口上的 × 关掉后，回到本页重新勾选、或点托盘图标的「快捷键提示」都能再打开。

      通用行为
      输入与响应
      超时与注入的细节

      命令 / 脚本动作超过「动作超时」会被连子进程一起强制终止并记进消息中心（脚本挂住会永久占住这条触发的执行线程，所以默认 30 秒）。想中止正在跑的动作，去「消息」页点「停止执行」。

      「序列等待」/「和弦等待」超时都会把被吞掉的键原样补回（序列照常打出来、和弦按单个普通键输入）。默认 1000 毫秒：手慢嫌不够就调大，误触嫌等太久就调小；填 0 = 不限时（一直等到断链 / 成员抬起）。

      「文本注入」默认「剪贴板粘贴」整段一次到位、中文最稳，但会短暂占用并恢复剪贴板，且被吞粘贴的程序（多数游戏、部分终端）无视；「逐字直发」逐个字符合成按键、不经过剪贴板，专治吞粘贴的目标程序，代价是长文本逐字送、极速输入个别程序可能丢字。

      键位层
      层是怎么生效的

      层让同一按键在不同状态下干不同事：切层键把某层「打开」后，该层的快捷键 / 改键才生效；归属「基础层」的条目始终生效。切层键 = 改键里设「长按进入层」（按住期间生效）或「长按锁定层」（长按切换、保持生效，层内放和弦 / 序列用这种）。

      输入层环境
      正在检测…
      这是干什么的

      有些厂商软件（Logi Options+ / G HUB / 雷云 等）会把某个按键转交给它自己：设备从此不再把这个键放进标准报文，系统的输入栈里根本没有这次按下——Kada 的钩子收不到，任何底层工具都收不到。这类接管只影响被转交的键（常见是鼠标侧键 / 额外键），键盘快捷键不受影响。

      认出这类软件后，Kada 会在「消息 → 冲突」里给一条提示（只在你的配置真用到鼠标键时才提示，避免打扰）。要让它放行：在厂商软件里把该按键设为「无操作 / 默认功能」，或直接退出它。详见「帮助 → 为什么按了没反应」。

      这个开关关掉后完全不再探测（提示与检测都停）；「重新检测」用于退出厂商软件后立刻刷新结论（结论本身有 3 秒缓存）。

      配置与数据
      导出配置 把整份配置存成 JSON，用于备份或换机器
      导入配置 从 JSON 文件合并或替换（替换前自动留档一份）
      载入示例配置 把内置示例合并进来（只增不删、不碰本机设置）
      片段市场 浏览索引里的片段，一键合并进配置（装之前先给你看清里面是什么）
      同步存档 未设置 —— 选一个目录（如 OneDrive）即可自动存一份
      手动同步 立即同步 = 把当前配置再写一份过去；从存档恢复 = 用目录里的那份合并 / 覆盖回来
      导入与分享的规则

      改动即时保存并生效。导入可选「合并」（只新增，触发键撞车的条目跳过、本机设置不动）或「替换」（整份覆盖，导入前自动留档），无效配置会被忽略并逐条列出。

      分享给别人：列表里选中若干条目（行内 ⋯ / 右键 → 导出为片段），或目录行 ⋯ → 导出该目录为片段，得到一个只含这几条的 JSON 文件——对方用这里的「导入配置 → 合并」就能加进来，不会覆盖他自己的配置。片段不含设置、也不含目录分组（目录是本机的）。

      片段市场没有服务端：索引就是一个放在网上、能下载到的 JSON 文件，索引里每条再指向一个片段文件。想收录自己的片段，把导出的片段文件按索引格式加进索引即可（内置索引在本仓库 snippets/，由 scripts/build-snippet-index.mjs 生成）。

      同步存档：选一个目录（如你的 OneDrive 文件夹），之后每次配置落盘都会在那目录里自动存一份 kada-config.json（保留一份 .bak）。换机器时在新机器的设置里选同一个目录，点「从存档恢复」即可把配置搬过去（可选合并或替换）。走的是本地文件夹、不登录任何账号——云端上传下载由 OneDrive 客户端自己负责。

      为什么按了没反应

      「配置看着没问题，按下去就是没反应」有几种完全不同的成因。按这个顺序排查，每一步都能自己确认：

      1. 先看「消息 → 冲突」页：触发键重复、被系统快捷键占用、本平台监听不到的键，都会在那里列出来（这些是配置层面的问题，改配置就能解决）。
      2. 再确认这一层是不是生效的：归属某层的条目，只在那个层被激活时生效；按住式切层键要按住才管用。屏幕下方的状态指示会告诉你「当前有没有东西生效」。
      3. 最后看输入环境：设置页的「输入层环境」会探测有没有会抢走按键的厂商软件在跑。见下。

      厂商软件把按键「转交」走了（最常见的一种）

      罗技这类设备支持把某个按键转交（divert）给厂商代理：代理设置过之后，设备固件不再把这个键放进标准报文，改用私有协议只发给代理。结果是——这次的按下在系统里根本不存在，Kada 的低层钩子看不到，内核驱动同样看不到，任何底层工具都无能为力。（本文档不涉及对抗：没有可拦截的事件。）

      怎么认出来：这类接管通常只吃掉部分键。典型指纹是「中键能用、侧键不能用」——因为中键在厂商软件里常是直通（默认行为），而侧键被指派成了厂商自己的动作（如「浏览器后退」）。

      三种处置，任选：

      1. 在厂商软件里让位（推荐）：把那个按键的指派改成「无操作 / 默认功能 / 未指派」。它就会回到标准报文，Kada 立刻能收到，厂商软件也不用退出。
      2. 退出厂商软件：退出即放弃接管，按键立刻回到标准报文。代价是它提供的其它功能（手势、设备切换等）也没了。
      3. 让 Kada 当那个客户端（规划中，见 docs/底层输入能力规划.md 档位 C）：由 Kada 直接告诉设备「别转交这个键」。尚未实现。

      设置页「输入层环境」的「重新检测」可以立刻复核结论：退出厂商软件后再点一次，探测结果应随之变化。

      其它两种「没反应」

      • 提权窗口里注入不进去：钩子看得见按键，但 Windows 不让普通权限的进程往管理员窗口注入（UIPI）。表现是「按了，动作执行了，但目标窗口里没有文字 / 按键」。这是另一件事，规划见档位 B。
      • Linux 上被别的改键工具抢了设备：keyd / input-remapper 这类工具会独占抓取 /dev/input，与 Kada 互相抢占——谁先抓到谁说了算。两者只能留一个。

      变量：提取与引用

      一条快捷键可挂多个动作，按顺序执行。有的动作会把结果「存成变量」，后面的动作用 {变量名} 或 {变量名.字段} 引用。变量只在本次触发内有效，触发结束即清空，不落盘、不跨触发。

      本节讲通用语法；某个动作具体产出什么、字段怎么命名，鼠标悬在那个动作「存为变量」右侧的 ? 上就能看到。

      三种提取方式

      动作存成什么怎么引用
      执行命令（填「存为变量」）文本：标准输出 + 退出码{变量名} 得输出全文、{变量名.exit_code} 得退出码
      文件/目录 → 获取文件属性文件对象（多个字段）{变量名} 得完整路径、{变量名.字段} 得字段
      应用 → 查询运行状态布尔 true / false{变量名}

      引用语法

      • {变量名}：取整体值——文件属性得完整路径、布尔得 true/false、命令结果得输出全文。
      • {变量名.字段}：取字段。文件属性有 name/path/dir/stem/ext/size/modified/is_dir；命令结果有 exit_code（0=成功）。
      • 未知变量/字段原样保留成 {...}，不会报错、不会中断。

      文件属性字段

      • name 文件名、path 完整路径、dir 所在目录、stem 主名、ext 扩展名、size 大小(字节)、modified 修改时间、is_dir 是否目录。

      实战：把文件复制到「盘符不定」的移动硬盘

      盘符每次插上都不固定（今天 E:、明天 F:），但你知道硬盘卷标。思路：先按卷标查盘符 → 存变量 → 复制动作里用变量拼路径。

      第 1 步：执行命令，按卷标取盘符

      动作类型「执行命令」→ PowerShell，命令：

      (Get-Volume -FileSystemLabel '我的硬盘').DriveLetter

      「存为变量」填 drive。卷标 '我的硬盘' 换成你硬盘的实际卷标（资源管理器里看到的名字）。这句只输出一个字母，如 E。

      第 2 步：复制文件，用变量拼目标路径

      动作类型「文件/目录操作 → 复制」：原始路径 C:\工作\待备份，目标路径 {drive}:\备份\。

      触发后 {drive} 被替换成当天盘符，实际执行 E:\备份\。

      更稳的写法：先确认硬盘在，再复制

      1. 执行命令取盘符 → 存入 drive。
      2. 条件判断：变量字段不等于，变量名 drive、字段留空、值留空（盘符查到才继续）。
      3. 复制 → 目标路径 {drive}:\备份\。

      常见问题

      变量能跨快捷键、或下次触发再用吗？

      不能。变量只在当前这一次触发、按顺序执行的动作里有效，触发结束即清空。

      命令输出带了换行或空格，会影响路径吗？

      不会。「存为变量」会去掉命令输出的首尾空白与换行，只留内容本身。

      取盘符的命令在 CMD 里怎么写？

      可用 wmic logicaldisk where "VolumeName='我的硬盘'" get DeviceID，但输出带表头需自行清洗；推荐用 PowerShell。

      命令的退出码（成功/失败）能拿到吗？

      能。{变量名.exit_code} 得到退出码（0=成功，非 0=失败）；{变量名} 仍是标准输出全文。可配合「条件判断」做「命令失败则…」的分支。

      占位符写错了（变量不存在）会怎样？

      不会报错，{写错的变量名} 会原样保留在字符串里，等于没替换。执行后到「消息」页看结果即可排查。

      变量名有什么限制？

      任意非空字符串即可，别含 {}、.、空白；建议用简单英文/拼音（如 drive、f）。
