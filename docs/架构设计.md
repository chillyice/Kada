# Kada 架构设计

> 系统分层、一次按键的完整流转、关键机制与跨平台策略。动架构前重读本文档。

## 1. 分层与模块分域

```
┌─────────────────────────────────────────────────────────┐
│  UI（kada-ui，Vite + TS）                                │
│  快捷键 / 改键 / 宏录制 —— 通过 Tauri command 读写配置     │
└───────────────────────┬─────────────────────────────────┘
                        │ invoke (get/set_config, set_paused, start/stop_record)
┌───────────────────────▼─────────────────────────────────┐
│  桌面壳（src-tauri，crate `kada`）                        │
│  KadaState / decide / Recorder / 托盘常驻                 │
└───────────────┬──────────────────────────┬──────────────┘
                │ 喂入 Ev                   │ 调用 simulate
┌───────────────▼──────────────┐  ┌────────▼─────────────┐
│ 钩子引擎（kada-hook）          │  │ 核心逻辑（kada-core） │
│ win.rs / linux.rs / simulate │  │ Key/Modifier/Shortcut│
│ 全局键盘事件监听 + 拦截 + 注入  │  │ 解析/匹配/配置模型    │
└──────────────────────────────┘  └──────────────────────┘
```

- **kada-core**：零重量纯逻辑，无平台依赖、可独立单测。键模型 + 快捷键解析/匹配 + 配置模型（JSON 序列化）。是跨平台一致性的锚点。
- **kada-hook**：平台钩子引擎，把 OS 键盘事件翻译成统一 `KeyEvent`，回调决定 `Action`（`Allow/Block/Replace`），注入由 `simulate` 完成。Windows（`WH_KEYBOARD_LL`）与 Linux（evdev + uinput）两后端，接口对齐。
- **src-tauri（`kada`）**：配置驱动的壳。启动加载 JSON → 钩子接入配置匹配 → 托盘常驻。命令层承载 UI 读写配置。跨平台事件管道用自有 `Ev`，各平台钩子都喂给 `decide`/`Recorder`。

## 2. 一次按键的旅程（以快捷键为例）

1. OS 键盘事件进入钩子（Windows 低层钩子回调 / Linux evdev 事件循环）。
2. 钩子翻译成 `KeyEvent::Down { key, mods, repeat }`，交给壳注册的 handler。
3. 壳若在录制中 → 事件进 `Recorder` 时间线、放行。否则先过 tap-hold 状态机（`taphold_step`）：命中 tap-hold 键则吞掉并延迟判定（短按/长按/长按切层），被吞键不进 `decide`。
4. 其余事件读配置经 `decide` 判定：
   - 改键命中 → `HookAction::Replace(to)`（吞原键、注入目标键）。
   - 快捷键命中 → 异步 `fire(action)` + `HookAction::Block`。
   - 否则 → `HookAction::Allow`（放行），并继续喂给 `on_hotstring` 累积热串缓冲。
5. 钩子按 `Action` 执行：`Allow` 放行 / `Block` 吞掉（登记 `SWALLOWED` 连 keyup 一起吞）/ `Replace` 登记并注入目标键。
6. 注入走 `simulate`：文本用剪贴板 + `Ctrl+V`；组合键全部按下 → 稍停 → 逆序松开。

## 3. 关键机制

### 3.1 幽灵按键防护（吞键 + 改键）

- 决定吞掉的键登记进 `SWALLOWED`；后续该键的 keyup 一并吞掉，避免"吞了 down 却漏了 up"产生幽灵按键。
- `Replace` 维护 `REPLACED_DOWN`（原键 → 目标键）：按住原键期间只注入一次目标键 down，抬起时注入目标键 up，保持"按下-抬起"配对；自动重复不重复注入。
- Windows 注入事件带 `LLKHF_INJECTED` 一律放行，杜绝自我回环；Linux 事件全走 uinput 虚拟键盘，天然无回环。

### 3.2 修饰键状态与方向修正

- Windows：`GetKeyState` 实时读修饰键（事件键自身方向手动修正，避开队列滞后）；Linux：按事件流维护 `MODS_DOWN`（吞键/改键不动真实状态位）。
- 两后端都做"事件键若是修饰键则包含其自身"的方向修正，保证 `Ctrl+Ctrl` 等边缘组合的语义一致。

### 3.3 快捷键匹配（宽松超集规则）

`matches(e, s)` = 主键一致 **且** 事件修饰键 ⊇ 快捷键修饰键。按下 `Ctrl+Shift+K` 也命中 `Ctrl+K`，避免用户多按一个 Shift 就触发失败。改键优先于快捷键（先消耗原生键）。

### 3.4 宏录制器

- 把全局键盘事件转录成 `Action` 时间线：重复 down 折叠；事件间时差 ≥20ms 补 `PauseMs`；组合键合并成一条 `Keys`，键名落盘为可读字符串（`key_name`）。
- 录制中快捷键/改键全暂停（所有事件进时间线并放行）；结束补全仍按住键的 keyup。

### 3.5 文本注入（剪贴板）

`type_text` 用剪贴板 + `Ctrl+V`：对中文等 Unicode 最稳；副作用是短暂占用并恢复剪贴板。目标程序吞粘贴（游戏/终端）的极端场景后续可加 `KEYEVENTF_UNICODE` 直发兜底（两者加开关）。

### 3.6 窗口懒创建（冷启动零 WebView）

启动时不创建任何窗口（`tauri.conf.json` 的 `windows` 为空）：主窗口由 `show_main_window()` 按需建出（托盘菜单「打开」/托盘双击/`show_output` 弹窗三处入口），气泡窗口由 `ensure_toast()` 在首次触发快捷键时建出。二者都是「已存在则复用、不存在才 `WebviewWindowBuilder` 建」。气泡窗口首触发存在「事件早于前端监听器注册」的竞态，靠后端 `KadaState.toast` 暂存载荷 + 前端加载后 `get_toast_payload` 拉取兜底。托盘图标不受影响：`default_window_icon` 取自 `bundle.icon` 而非 `windows` 数组。

### 3.7 快速唤醒（被动双击检测）

`detect_wake` 在事件决策前运行：监听 `Settings::wake_key`（默认 Alt）的两次独立 down（间隔 ≤400ms、非自动重复），命中即唤出主窗口。设计成**被动**（只唤出窗口、不拦截按键），因为唤醒键常是修饰键，拦截会破坏 Alt+Tab / Alt+字母。配套修改：钩子层 `detect_repeat` 对修饰键/CapsLock 永不判重复，保证快速连按的两击都送达 handler。

### 3.8 系统快捷键冲突探测（三层）

`get_conflicts` 返回三类冲突：① 内部冲突（`detect_conflicts`：重复触发键/改键遮蔽/超集重叠）；② 系统快捷键清单（`SYSTEM_SHORTCUTS` 精确匹配，跨平台）；③ Windows `RegisterHotKey` 瞬时试探真实占用（注册成功即注销，错误码 1409=已被占用）。后两层补足「硬编码清单漏报/误报」，让用户录入组合键时即时看到「已被系统/其他应用占用」的警告。

### 3.9 tap-hold 与多层（改键状态机）

- `Remap` 从「原始键 → 目标键」扩展为六种形态：普通改键（`to`）、tap-hold（`tap` 短按 / `hold` 长按，阈值 `tap_timeout_ms` 默认 200ms）、切层键（`hold_layer` 长按进入层、松开退回）、单次修饰（`oneshot`）、粘滞修饰（`sticky`）、tap-dance（`tap2`/`tap3` 双击/三击）。运行时按 `sticky > oneshot > tap-hold > 普通 to` 互斥判定。
- `taphold_step` 在 `decide` 之前运行：按下 `from` 吞掉并进入待定，短按（阈值内松开）按模式输出——普通 tap-hold 输出 `tap`、含 `tap2`/`tap3` 进入 `TapDanceState`（等待窗累计击数、超时懒提交）、`oneshot` 武装单次修饰、`sticky` 切换粘滞修饰；**roll 判定**=待定期按下其它键立即判 hold，缓解「短按慢一个阈值」的手感损失；`hold` 是修饰键时并入注入修饰集，让「长按 CapsLock=Ctrl 后按 K」命中 `Ctrl+K`。
- 注入修饰统一走「物理注入（`simulate`）+ 后续键 mods 补全」通道，`ModsState` 分三类：`hold`（长按期间、`from` 松开释放）、`sticky`（锁存、再次单击 `from` 解锁）、`oneshot`（武装待释放、下一个非修饰键释放；roll/长按当普通 hold 修饰）。补全 = `hold ∪ sticky ∪ oneshot`。
- 层语义统一「激活层条目优先、基层层条目兜底」（`match_shortcut`/`match_plain_remap`/`find_taphold_rule` 三处共用）；`active_layer` 是运行时态、由切层键 momentary 驱动，非持久化。
- 键序列已把「键盘时序状态机」思路落地为纯逻辑 `SequenceTracker`（见 3.12）；oneshot/sticky/multi-tap 复用同一套 tap-hold 时序状态机（`TapHoldPending` 待定态 + `TapDanceState` 连击等待态 + `ModsState` 注入通道），避免各自实现一套时序逻辑打架。

### 3.10 文本扩展（hotstring 缓冲）

`on_hotstring` 在 `decide` 放行的事件上运行：可打印字符（`key_to_char`）累积成最近 N 字符滑动窗口（`MAX_HOTSTRING_BUFFER=64`）；空格/回车/Tab 触发后缀命中时，异步回删触发词（发 N 次 Backspace）再注入替换文本；方向键/功能键等非可打印键打断缓冲；最长触发词优先（`match_expansion`）。动态片段 `{date}`/`{time}`/`{clipboard}` 由 `resolve_hotstring` 展开。

### 3.11 前台应用/窗口条件

`Condition::matches(vars, frontmost)` 新增 `frontmost: Option<&FrontmostContext>` 参数。前台上下文在触发时（`fire` 异步线程起点）由 `frontmost_context()` 抓取：Windows 用 `GetForegroundWindow` + `GetWindowTextW` + `OpenProcess`/`QueryFullProcessImageNameW` 取标题与进程名；Linux 暂返回 `None`（Wayland 无通用查询协议，X11 可走 `_NET_ACTIVE_WINDOW` 待后续）。无上下文时三类前台条件一律不成立（避免 `NotFrontmostApp` 误判为真）。

### 3.12 键序列 / leader key（时序状态机）

- **触发模型**：`Trigger = Combo(Shortcut) | Sequence(Vec<Shortcut>)`。序列以空格分隔多步（`"F9 J K"`），首步即 leader 键；解析（`Trigger::parse`）与匹配时序（`SequenceTracker`）都收在 `kada-core`，纯逻辑可单测，壳层只负责超时/Esc 判定与注入。
- **`SequenceTracker`（核心）**：`advance` 维护「候选序列 + 已匹配步数」。空候选时命中任一序列首步即建候选（leader 吞掉）；推进时命中下一步的候选前进、任一走完返回 `Complete(下标)`、全断链重置返回 `NoMatch`；共享同一 leader 的多条序列（`"F9 J K"`/`"F9 J L"`）一并建候选自然共存。
- **`sequence_step`（壳层）**：在 `taphold_step` 之后、`decide` 之前运行，只处理非重复 Down。`Escape` 取消进行中的序列并吞掉；超时（`SequenceState.timeout`，默认 `DEFAULT_SEQUENCE_TIMEOUT_MS=1000`）过期重置、事件照走；`Advance` 吞掉等待下一键、`Complete` 复用 `fire` 触发、`NoMatch` 放行继续走 `decide`（断链的键仍可正常触发单组合）。序列条目按「激活层优先、基层兜底」收集（`collect_sequence_items`），与 `match_shortcut` 层语义一致。
- **与单组合互相独立**：序列字符串本就不被 `Shortcut::parse` 接受，天然被 `match_shortcut` 跳过；`detect_conflicts` 把「序列 leader 遮蔽同层单组合」（如 `"F9 J K"` 吞掉组合 `"F9"`）列为硬冲突。

## 4. 跨平台策略

- 键模型平台无关（`Meta` 承载 macOS ⌘），平台层负责把 OS 键映射成 `Key`（Windows VK 码 / Linux evdev 键码，均 US 布局语义、左右修饰键归一）。
- 钩子引擎按平台模块化（`win`/`linux`），对外统一 `start(handler) -> HookHandle` + `Action` 三态 + `simulate` 接口。
- 非 Windows/Linux 平台（macOS）用占位类型保证壳可编译（`hooks_supported() = false`），托盘与配置界面可用，快捷键/改键/录制暂不可用（M5 待实现）。

## 5. 已知天花板（升级路径）

- 低层钩子拦不住 UAC 提权进程 / 部分游戏 → 驱动级拦截（Interception）。
- Linux 热插拔键盘不在监听列表 → 监听 `/dev/input` 热插拔事件动态增删设备。
- 剪贴板粘贴被目标程序吞 → `KEYEVENTF_UNICODE` 直发兜底。
