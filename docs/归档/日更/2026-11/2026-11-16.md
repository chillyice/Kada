**决策**：

1. **放进现有「操作系统」动作（`Action::System`）而不是新动作类型**：代理开关动的是操作系统自身状态，与虚拟桌面 / 回收站同一类；界面入口只在子操作下拉里多一项，配置里仍是 `{"type":"system","operation":{"op":"switch_proxy",…}}`。
2. **`server` 留空 = 沿用系统现有地址**：多数用户只需要一个「开 / 关」热键，地址已经在代理软件里配好；填了才覆盖。开启时系统里既没地址、动作里也没填 → **明确报错**（不把「开着但没地址」这种看似成功的状态写进去）。
3. **`Toggle` 是缺省状态**：手工只写 `{"op":"switch_proxy"}` 就是「切一下」，符合用户点名的「切换代理」；要固定方向就选「开启 / 关闭」。
4. **换协议要清掉另一类**：Windows 只写 `http=…;https=…` 或 `socks=…`，macOS 打开一类时关掉另一类，GNOME 清空另一类的 host——否则两套代理会同时生效，排查起来像「代理时好时坏」。
5. **macOS 不弹提权框**：`networksetup` 需要管理员权限，注入路径上弹 UAC / 授权框会卡住整条动作链；改为执行失败 + 提示「把 Kada 以管理员身份运行」，不假装成功。Linux 同理只认 GNOME（KDE / XFCE 没有统一接口）。

**遗留**：

1. **真机没实际开关过系统代理**（避免动开发机的网络）：Windows 注册表写入 + WinINET 刷新、macOS `networksetup`、Linux `gsettings` 三条路都只做到「编译 + 纯函数 / 文本解析单测」，需要按「开 → 浏览器生效 → 关」各跑一次。
2. macOS 的「需要管理员权限」提示按 `networksetup` 输出里的 `admin` 关键字命中；若系统换了文案，提示会退化成原文报错（仍不静默）。
