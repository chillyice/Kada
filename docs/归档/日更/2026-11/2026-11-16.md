**决策**：

1. **放进现有「操作系统」动作（`Action::System`）而不是新动作类型**：代理开关动的是操作系统自身状态，与虚拟桌面 / 回收站同一类；界面入口只在子操作下拉里多一项，配置里仍是 `{"type":"system","operation":{"op":"switch_proxy",…}}`。
2. **`server` 留空 = 沿用系统现有地址**：多数用户只需要一个「开 / 关」热键，地址已经在代理软件里配好；填了才覆盖。开启时系统里既没地址、动作里也没填 → **明确报错**（不把「开着但没地址」这种看似成功的状态写进去）。
3. **`Toggle` 是缺省状态**：手工只写 `{"op":"switch_proxy"}` 就是「切一下」，符合用户点名的「切换代理」；要固定方向就选「开启 / 关闭」。
4. **换协议要清掉另一类**：Windows 只写 `http=…;https=…` 或 `socks=…`，macOS 打开一类时关掉另一类，GNOME 清空另一类的 host——否则两套代理会同时生效，排查起来像「代理时好时坏」。
5. **macOS 不弹提权框**：`networksetup` 需要管理员权限，注入路径上弹 UAC / 授权框会卡住整条动作链；改为执行失败 + 提示「把 Kada 以管理员身份运行」，不假装成功。Linux 同理只认 GNOME（KDE / XFCE 没有统一接口）。

**决策**：

1. **宽松解析放 core，Kotlin 不解析触发键**。手机上敲 `ctrl+alt+k` / `f4` 是常态，而 `sanitize_config` 对触发键**大小写敏感**——不补正的直接后果是「有名字没触发键」（条目留下了、触发键被当坏值丢掉），比界面缺失更值得先修。只补正大小写、**不猜别名**（`pgup` 仍是错），别名表继续只有 `parse::key` 一份。
2. **撞车判定用 core 的口径**：重复触发键是 `detect_conflicts` 里的**硬冲突**，编辑器据此**拦保存**而不是只警告。比较的是 `format_trigger` 规范化后的写法，不是用户敲的原文。
3. **落盘只有一条路**：界面按钮与 adb 广播都走 `ShortcutStore.save()`（先校验再 `RustBridge.save`），不做「先写文件再等重启」。`save()` 里做校验是**故意**的——绕开界面直接调它也不会写进坏触发键。
4. **动作链只编五类，其余保持原样**：手机屏上做不了桌面的全量编辑器（目录 / 层 / `when` / 多步链），但**改触发键绝不能把动作改没**——不认识的类型一律 `ACTION_KEEP`，原 JSON 一个字节不动。
5. **录入必须在无障碍回调里截**：否则录 `F8` 会先把 `F8` 原来的快捷键执行一遍（可能拉起浏览器抢前台，把录入过程打断）。录到后连抬起一起吞，避免目标 app 收到「只有 keyup」；安全阀用「新的非修饰键按下即放弃」，因为无障碍偶发丢事件，宁可漏半个抬起也不能把键盘永久吞住。
6. **列表只在用户动作后重建**，不跟主界面 500ms 重绘跑——那是 S0 延迟 P95 顶到 491 ms 的同一个坑（主线程共享预算）。

## 安卓 S1-e：`text` 动作改「光标处插入」（不动剪贴板）

| 文件 | 改动 |
|---|---|
| `android/.../SemanticActions.kt` | 新增 `insertText(text)`：读聚焦节点的文本与选区 → `ACTION_SET_TEXT` 写「前段 + 文本 + 后段」并落光标；节点不接受才 `insertViaClipboard`（写剪贴板 → 粘贴 → 120ms 后**尽量恢复原剪贴板**，读不到就如实写「已被覆盖」） |
| `android/.../ActionRunner.kt` | `text` 与 `clipboard/tempstr` 都改走 `insertText`；`set_clipboard` 保持原样 |
| `crates/kada-android/src/action_support.rs` | 支持口径注释同步（`text` = SET_TEXT 插入 + 剪贴板退路） |
| `android/tools/verify.ps1` | 新增 S1-5 三断言：编辑器写入 `text` 动作、原 `abc` + F2 → `abcinsertme`、F1 写 `clipmark` → F2 插文本 → F12 粘贴仍得 `clipmark` |
| `android/README.md` · `docs/{安卓版规划,人工验证清单,代码地图}.md` | S1 段文本动作说明 + 44/44 验收表三行 + 限制改写；规划 §11 本轮日志；新增 §91 人工项（7 步）；代码地图 1 条路由 |

**决策**：

1. **首选 `ACTION_SET_TEXT`，不是「剪贴板 + 粘贴」**：粘贴要占用用户剪贴板、依赖输入法连接（软键盘没起来时 `ACTION_PASTE` 常被拒），而 `SET_TEXT` 是节点级写入，一次 binder 调用就完事。安卓上「输入文本」最常见的用法是插一段模板到光标处，覆盖整段反而是错的。
2. **只在聚焦节点上写**：`nodeAction` 的「沿父链重试 8 层」在插入这里不成立——父容器即便返回 `true`，它的 `text` 也不是同一段内容，拿父节点的文本拼会把输入框写坏。插入失败直接走退路。
3. **不假装恢复剪贴板**：Android 10+ 后台应用读不到剪贴板，`primaryClip` 可能是 `null`。读不到就写明「已被覆盖为插入内容」，让用户自己决定要不要重新复制——这类「以为没丢其实丢了」的静默状态最坑。
4. **临时文本走同一条路**：桌面 `tempstr` 是「写 → 粘 → 恢复」，安卓这边先试不碰剪贴板的那条，语义更干净（真·不留痕）。

**验证**：

- `verify.ps1 -SkipBuild -SkipSlowChecks` → **44/44 PASS**（emulator-5554 / Android 14）：S1-5 三条全过——`actionType=text`、`field=[abcinsertme]`（`lastOk=true`）、F12 粘贴后 `field=[abcinsertmeclipmark]`（剪贴板没被动过）
- `gradlew --offline assembleDebug` ✅（Kotlin 改动）；Rust 侧只改注释，`cargo fmt` / `clippy` 无新告警

**遗留**：带格式文本只能退化成纯文本；不接受 `SET_TEXT` 的 App 走粘贴，原剪贴板可能恢复不了（已上报）。真机逐条（中文 / 表情 / 多行 / 第三方输入框）归 `docs/人工验证清单.md` §91。

| `android/tools/verify.ps1` | S1-6 五断言（用 `file://` 清单把网络摘掉） |
| `android/README.md` · `docs/{安卓版规划,人工验证清单,代码地图}.md` | 目录树 / S1 段自更新小节 / adb op / 49/49 验收表五行 / 限制；规划 §11 日志；新增 §92 人工项（8 步）；代码地图 2 条路由 |

**决策**：

1. **版本比较只认 `versionCode`**：`versionName` 是给人看的（`0.2.0-s5` 这种后缀迟早会有人手滑），整数单调递增才靠得住；缺 `versionCode` 的清单**直接报错**——否则它永远判「已是最新」，用户以为自动更新坏了也查不出原因。
2. **安装走 `PackageInstaller` 会话，不拼 `file://` Intent**：后者在 Android 7+ 直接 `FileUriExposedException`，得引 FileProvider 绕；会话是系统给的正路，还能拿到「被取消 / 失败原因」的回执。
3. **写会话放后台线程**：8 MB 的包拷进会话就要好几秒，按钮回调 / 广播回调都在主线程，在这一层同步拷必然 ANR。`install()` 返回成功只代表「已开始」，真实阶段看 `phase`。
4. **没授权就回报 `need_permission`**：`canRequestPackageInstalls()` 为假时不做任何「也许系统会弹」的猜测，界面直接引导去设置页——静默失败是这类功能最难支持的故障。
5. **不做签名校验，只比 sha256**：清单与 APK 同走 https，APK 本身有系统安装器的签名校验；sha256 挡的是下载截断 / 中间缓存串味。真正的信任根在发布链路（`latest.json` 与 APK 必须同批更新），这条写进限制里而不是假装做了。

**验证**：

- `verify.ps1 -SkipBuild -SkipSlowChecks` → **49/49 PASS**（emulator-5554 / Android 14）：S1-6 五条全过——`phase=available current=0.2.0-s5/6 manifest=0.2.0-s99`、`bytes=8221943/8221943`「已下载 8029 KB（sha256 已校验）」、`need_permission canInstall=False`、`phase=installing` 且前台是 `…PackageInstallerActivity`、坏 sha256 → `phase=failed bytes=0`「已删掉下载的文件」
- `gradlew --offline assembleDebug` ✅（会话 `commit` 要 `intentSender`，`PendingIntent` 直接传类型不匹配——编译期就拦住）
- 模拟器中途崩过一次（`device offline` + `adb install` 卡住）：`adb kill-server` → 重开 AVD 后复跑全量通过

**遗留**：

1. 清单地址是代码常量（`Update.MANIFEST_URL`），换域名要重编；真发布前要把 `latest.json` 与 APK 一起传到 `/files/kada/android/`。
2. 只比 sha256，**没有 APK 签名校验**；发布侧要保证清单与包同批。
3. 真机点「安装」覆盖安装（配置是否保留）、取消安装、断网 / 404、国产 ROM 安装器差异归 `docs/人工验证清单.md` §92。
4. 本轮不出包、不发 ihomy（等 S1 全部收尾再发 s5 安装包 + 清单）。

## 「切换系统代理」补排除项（bypass，三平台）

「切换代理」只有一个开 / 关键不够用：很多代理软件要「公司内网 / 本地地址直连」，否则开了代理连不上局域网。这一轮把排除项做成动作里可填的一项，三个平台各写各的系统字段。

| 文件 | 改动 |
|---|---|
| `crates/kada-core/src/action.rs` | 新增 `parse_proxy_bypass(raw) -> Vec<String>`（中英文分号 / 逗号 / 换行都算分隔符，去两端空白、完全重复的项去重，空串 = 空列表 = 不设置）；`SystemOperation::SwitchProxy` 加 `bypass: String`（`serde(default)` + 空值不落盘，老配置自动补空）；`proxy_action_tests` 扩两条：缺省值 / 落盘回读带 `bypass`、拆分去重规则 |
| `crates/kada-actions/src/proxy.rs` | `switch()` 加 `bypass: &[String]`；**Windows** 开启且填了才写注册表 `ProxyOverride`（分号串，`override_value()`），**macOS** 走 `networksetup -setproxybypassdomains <服务> <域名…>`（`bypass_args()`），**Linux** 写 GNOME `ignore-hosts`（GVariant 数组串，`ignore_hosts_gvariant()` 转义单引号 / 反斜杠）；三处都是**空列表 = 一个字节都不碰**系统里已有的排除项。`enabled_message` 带上排除项数（`…，3 项排除`）。新增 4 条单测 |
| `crates/kada-actions/src/lib.rs` | `proxy_body()` 摘要加排除项数（`开启系统代理（127.0.0.1:7890，排除 2 项）`）；`run_system` 调 `parse_proxy_bypass` 后传下去；两条代理单测跟着改并补排除项断言 |
| `ui/src/types.ts` · `options.ts` · `form.ts` | `switch_proxy` 加可选 `bypass?: string`（老配置没有这个字段，按空处理）；`proxyBypassList()` 与 core 同口径拆分（摘要只报项数）；编辑页在「代理地址」下面加「排除项」输入框 + 问号说明，选「关闭」时一起隐藏 |
| `ui/src/i18n.en.json` | 新增 5 条英文（排除项标签 / 占位符 / 说明 / 两种摘要模板），并把「切换」那条长说明改写成「地址 / 排除项」口径 |
| `docs/代码地图.md` | 新增一条路由：切换系统代理不生效 / 排除项没写进去 |
| `docs/归档/日更/2026-11/2026-11-16.md` | 本文件 |

**决策**：

1. **`bypass` 留空 = 不动系统里已有的排除项**（与 `server` 留空沿用现有地址同一口径）：多数人只需要一个开 / 关热键，排除项早就在系统或代理软件里配好了；一个热键顺手清掉用户手工例外是最坑的静默破坏。
2. **只有「开启」那条路写排除项**，「关闭」只关开关：关代理时改地址或例外都没有意义，反而让下次开启前多一步手工恢复。
3. **排除项是一个字符串字段而不是数组**：配置跟着同步 / 走卡带，字符串在界面上就是一行输入框，用户从代理软件里复制 `localhost;127.*;*.local` 粘进来即可；拆分口径统一在 core 的 `parse_proxy_bypass`，UI 只做同样规则的拆分用于显示项数，**写系统时以 core 的解析结果为准**。
4. **三平台各用自己的写法，不做归一化**：Windows `ProxyOverride` 是分号串（`<local>` 有特殊含义）、macOS 是多参数列表、GNOME 是 GVariant 字符串数组——硬凑成一种写法会在某个平台变成「写进去了但不生效」，宁可各自拼各自的。
5. **摘要只报项数不列整串**：排除项可以很长，塞进列表页会把摘要撑爆；要看细节点开编辑页。

**验证**：

- `cargo fmt --all -- --check` ✅ / `cargo clippy --workspace --all-targets -- -D warnings` ✅（零告警）
- `cargo test --workspace` ✅ 517 条（kada-core 250 / kada-actions 82 / kada 117 / kada-android 18 / kada-hook 42+2 ignored / cassette 7 / 冒烟 1）——新增的 proxy 单测 6 条全过
- `cargo check -p kada` ✅ / `cargo check -p kada --no-default-features` ✅
- `cargo check -p kada-hook -p kada-actions --target x86_64-unknown-linux-gnu --all-targets` ✅（`ignore-hosts` 那条能真编过）
- `cargo check -p kada-hook -p kada-actions --target aarch64-apple-darwin --all-targets` ✅（`-setproxybypassdomains` 那条能真编过）
- `npm --prefix ui run build` ✅ / `npm --prefix ui run lint` ✅
- `node scripts/check-i18n.mjs` ✅（1096 条全覆盖）/ `node scripts/check-docs.mjs` ✅

**遗留**：

1. **真机没实际开过代理**（避免动开发机的网络）：Windows `ProxyOverride` 写入 + WinINET 刷新、macOS `networksetup -setproxybypassdomains`、Linux `gsettings ignore-hosts` 三条路都只到「编译 + 纯函数单测」。要按「填排除项 → 开 → 访问一个被排除的内网地址应直连 → 关」各跑一次。
2. 老配置兼容只看过 serde 的 `default`（`bypass` 缺失 → 空串），没在真实老 `config.json` 上跑过保存 / 导入。

## exe 图标排查：不是丢了，是图标缓存（无代码改动）

反馈「打出来的 exe 在资源管理器里看不到软件 logo」。查到的是**图标资源完整**，问题落在系统缓存那一层：

- `target/release/kada.exe`（21 MB，2026-11-16 16:07）里 `RT_GROUP_ICON` 六帧齐全：16 / 24 / 32 / 48 / 64 / 256，中心像素是橙色 K（`#FFCA58`），与 `src-tauri/icons/32x32.png` 一致。
- `System.Drawing.Icon::ExtractAssociatedIcon` 与 `SHGetFileInfo(SHGFI_ICON)` 都能取到 32x32 / 16x16 图标；把 exe 复制到临时目录再取，同样取得到——说明不是「资源没嵌进去」，也不是「换了路径就没了」。
- 该 exe 的属性是 `Archive | NotContentIndexed | Pinned`，不是 OneDrive 的云端占位文件。
- 处置：跑 `ie4uinit.exe -show` 刷一遍资源管理器图标缓存后让用户再确认（`kada-package.ps1` 每次都会重新嵌入图标，重新构建同样会刷新）。
- 备注：`icon.ico` 的六帧**全是 PNG 帧**。Windows Vista+ 认，但 `.NET`/GDI+ 只解得出小尺寸那几帧（`new Icon(path, 256, 256)` 只回落到 64×64）。如果用户机器上仍是空白，下一步把 16~64 那几帧转成 DIB（**只留 256 帧为 PNG**），那是兼容性更稳的写法——本轮没这么做，因为现有 exe 实测能取到图标，换帧属于「未复现问题前的改动」。
