**决策**：

1. **无 root 档做不了「键 → 键」，只能「键 → 动作」**。`Config.remaps` 整块失效（输出是键、落地必须注入），`Config.shortcuts` 保留（输出是动作）。这是产品边界，要写进 UI，不是实现细节。
2. **手机档不做输入法**。文本扩展三个方案里选「面板点一下 → 粘贴」；无障碍读输入框 + `setText` 只做默认关闭的开关（读屏权限是 Play 审核风险最高的一类用途）。
3. **root 档 = Linux 后端同构**（`/dev/input` grab + uinput），所以要先做一次重构：把 `crates/kada-hook/src/linux.rs` 的 evdev 部分抽成 `evdev_common`，避免 1.8k 行复制两份。
4. **`PlatformCaps` 从编译期常量改运行时探测**（档位 + 授权 + 有无物理键盘），能力判定下沉到 `Action::capability()`，卡带按条标灰。
5. 手机档唯一可用的物理触发是**音量键**（无障碍可收可吞），其余靠悬浮球 / 磁贴 / 常驻通知。

**验证**：`node scripts/check-docs.mjs` → `OK: 文档无问题`（AGENTS.md 19,340 B，上限 20,480，余 1,140 B）。本轮**未写代码**，未跑 cargo / npm。

**遗留**：S0 spike 未开始（先验 S0-2：无障碍 `onKeyEvent` 的 down/up/repeat 时序能否喂动 `Engine` 的 tap-hold 与和弦判定）；本机 Android SDK（platform 36 / build-tools 35、36）+ AVD `ihomy34` + JDK 21 就绪，**NDK 未装**（S0 纯 Kotlin 不需要，S1 起需要）；`软著申请/` 与 `scripts/copyright/` 仍未跟踪。
