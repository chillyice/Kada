**决策 / 结论**：

1. **没有「先吞下、凑不齐再回放」的窗口**——`onKeyEvent` 必须同步回答吞不吞，桌面 `Engine` 的吞键语义在安卓上不成立。
2. **只能吞不能注入**：吞错的键补不回来，和弦必须选「成员键被吞也无所谓」的组合。
3. **软键盘打字不产生 `KeyEvent`**：手机档「打字触发」只能走面板 / 粘贴（规划 §4 定案未变）。
4. **自动化必须用 `sendevent`**：`adb shell input keyevent` 的注入事件不进无障碍过滤，用它测吞键是假阴性。
5. **音量键可收可吞**（系统音量不跟着变），但系统侧流水线约 160 ms。

**验证**：模拟器 `emulator-5554` / `ihomy34`（Android 14）S0 段全过（收键 / 吞键 / tap-hold / 和弦 / 音量键 / 前台服务 / `GLOBAL_ACTION_*`）；探针自身判据 32 项见下一节汇总。`sendevent` 需要 `adb root`（重启后丢，脚本开跑先补）。

**决策**：

1. **吞键策略定成非破坏式**：`shortcuts` 只吞「凑齐的那一下」，和弦成员 / 序列前缀一律放行；`remaps` 与层**永不吞**（无 root 注入不了，吞了就是白吞），只在报告里标 `unsupported`。这是对规划 §5.2「先吞后回放」的**有意偏离**——安卓没有回放通道，只能少吞。
2. **判定在 Rust，Kotlin 只搬运**：决策顺序、等待窗、前台过滤全在 `crates/kada-android/src/engine.rs`；Kotlin 只做 keycode → core 键名映射 + 动作执行，避免两套规则漂移。
3. **动作支持表只有一份**：`action_support.rs` 的 `SUPPORTED`（`open_url` / `text` / `clipboard` / `pause_ms` / `group` / `disabled`）；Kotlin 不许再维护第二张表，报告里的 `unsupported_actions` 也由它产出。
4. **共享层搬 core 而不是复制**：`decide` / `config_io` 搬进 `kada-core`，桌面壳改成重导出——桌面行为零变化，安卓直接用。
5. **`text` 动作先按「写剪贴板 + `ACTION_PASTE`」落地**（规划 §4 方案 ③ 的底座），已知会覆盖用户剪贴板，方案本身仍待决策。

**决策**：

1. **S1 段以 `resetConfig` 起跑**：上一轮的合并导入会把 `F6` 留在设备上，「示例 5 条」「合并后 6 条」这类断言就随残留漂移。删配置 + 重新 `init` 比「导出→替换导入」干净（不依赖上一轮导出的文件）。
2. **前台切换是「丢键」的头号原因**：`open_url` 拉起 Chrome、通知栏 / 快捷设置抢焦点，都会让无障碍重建输入连接，窗口里的按键直接丢。所以每段按键前统一 `Restore-App`，而不是逐条补 `am start`。
3. **时序必须一次发完**：每次 `adb shell` 在 Windows 上有 50~200ms 抖动，偶发卡 1~2 秒；分开发会把和弦成员间隔拖过 `chord_timeout_ms`（1000ms）。`Send-Sequence` 把 `睡 60ms` 这类间隔也交给**设备侧** `sleep`，脚本自身延迟不再影响按键时序。
4. **重试一次不掩盖回归**：`Test-KeyFlow` 失败会重发并重判，两次都失败才判 FAIL；重试成功时打 `[warn]` 留痕，方便区分「脚本抖了」和「功能坏了」。
5. **主线程是共享预算**：`onKeyEvent` 与节点动作 / 报告序列化同在主线程，连续 binder 调用会吃掉输入过滤的 500ms 预算（超时即 fail-open 放行）。所以音量键检查前移到节点动作之前。

| `ui/src/style.css` | 新增 `--run`（深色 `#4aa3f0` / 浅色 `#1a6ab8` / 像素浅色 `#2d5fa8`，像素深色沿用深色档）；`st-running` 的五处从 `var(--accent)` 换成 `var(--run)`：消息页签圆点、执行记录徽标文字、时间线块旗标、流水线块旗标、块边框（`.st-running`） |

**决策**：

1. 根因是 `--accent` 橙 `#e06040` 与失败红 `#e0574f` 亮度 / 色相都太近，「执行中」和「有失败」在徽标、块边框、页签圆点上几乎分不清。换成一档独立的蓝，与成功绿 `#4cc38a`、失败红 `#f0736b`、中止黄 `#e0bb5c` 都不撞。
2. `--run` 是**唯一分主题的结论色**（其余 st-ok / st-error / st-abort 写死）：亮蓝当 11~12px 小字在浅底只有 ~2:1，浅色档必须压深到 `#1a6ab8`（白面板 5.3:1、淡底 4.7:1）。
3. 只换颜色、不动结构：脉动动画（`pulse`）、停止按钮悬停红都保持原样。

**验证**：`npm --prefix ui run build`、`npm --prefix ui run lint` 通过。

**遗留**：观感（四套主题下蓝与橙是否各就各位）需真机看一眼；`docs/需求设计说明书.md` 无字段级变化，不用改。
