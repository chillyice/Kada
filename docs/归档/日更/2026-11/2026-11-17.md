## 安卓 S2b：画符号（单笔画手势当触发源）

手机上没有物理键盘，S2 的触发源是「打开面板点一下 / 磁贴 / 通知 / 音量键」——都要求先找到那个入口。
这一轮补的是**不打开面板就能点一下**：长按悬浮球画一笔，抬手执行绑定的那条快捷键。

### 决策

- **S3 root 档不排期**：本机没有 root 设备、手机 root 比例逐年下降，root 只换来「改键 + 鼠标手势」两样，而这两样在手机上的需求量远低于「点一下」与「画一笔」。有 root 真机 + 明确需求再动（`docs/安卓版规划.md` §6 表下）。
- **符号 + 方向两关判定**：只做形状识别不够——四向三角在 $1 眼里是同一个形状。方案是 90° 扇区量化 + ±35° 容差，落在 45° 附近**直接拒绝**：猜错方向比不识别更糟。
- **绑定不进 `Config`**：进配置要动 core 的模型、卡带格式与同步口径，收益要等「录自定义画法」（P2）才显现；这一轮先用本机 `SharedPreferences`，执行链完全复用现有快捷键。
- **自检跑在设备上**（`op drawSelfTest` → 报告 `phone.draw.selfTest`）：断言的正是「旋转方向 / 扇区阈值」这类只有真跑才作数的东西，而离线 Gradle 拉不到测试依赖，索性不引。
- **画板打开走 service intent**：`startForegroundService` 是异步的，直接拿 `instance` 会静默失败；`ACTION_SHOW_BOARD` 让 `onCreate` 先跑完。

### 遗留 / 教训

- **教训：挑 F 键要按当下占用看**。S2b 首轮 **65/68**，三条失败全因测试条目用了 `F5`——S1-3 合并进来的「S1 语义动作」一直留到最后、占着 F5，`editorAdd` 按硬冲突拒了（logcat 只有一行 `编辑失败：触发键与 #5 S1 语义动作 重复`），条目没建出来、绑定与执行连锁失败。改用 F6 后全绿。
- 只做**单笔画 + 17 个预设**：还不会「录自定义画法」（P2），多笔画（如「圆 + 竖」）没做（P3），绑定换机 / 导入卡带带不走。
- 圈选截图那种「画圈再点一下」的复合手势不在这套里（那是桌面右键手势的家庭），安卓侧要做得另设计一层。
- APK 仍是 debug 签名；`latest.json` 手工维护。
