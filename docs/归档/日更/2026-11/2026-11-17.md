## 安卓 S2b：画符号（单笔画手势当触发源）

手机上没有物理键盘，S2 的触发源是「打开面板点一下 / 磁贴 / 通知 / 音量键」——都要求先找到那个入口。
这一轮补的是**不打开面板就能点一下**：长按悬浮球画一笔，抬手执行绑定的那条快捷键。

### 决策

- **S3 root 档不排期**：本机没有 root 设备、手机 root 比例逐年下降，root 只换来「改键 + 鼠标手势」两样，而这两样在手机上的需求量远低于「点一下」与「画一笔」。有 root 真机 + 明确需求再动（`docs/安卓版规划.md` §6 表下）。
- **符号 + 方向两关判定**：只做形状识别不够——四向三角在 $1 眼里是同一个形状。方案是 90° 扇区量化 + ±35° 容差，落在 45° 附近**直接拒绝**：猜错方向比不识别更糟。
- **绑定不进 `Config`**：进配置要动 core 的模型、卡带格式与同步口径，收益要等「录自定义画法」（P2）才显现；这一轮先用本机 `SharedPreferences`，执行链完全复用现有快捷键。
- **自检跑在设备上**（`op drawSelfTest` → 报告 `phone.draw.selfTest`）：断言的正是「旋转方向 / 扇区阈值」这类只有真跑才作数的东西，而离线 Gradle 拉不到测试依赖，索性不引。
- **画板打开走 service intent**：`startForegroundService` 是异步的，直接拿 `instance` 会静默失败；`ACTION_SHOW_BOARD` 让 `onCreate` 先跑完。

### 决策

- **存原始笔画，不存归一化后的 32 点**：归一化口径（点数 / 缩放 / 重采样）以后还会调，存原始点意味着老符号能跟着新算法重新归一化；代价只有一条几百点的 JSON。
- **自定义符号不判方向**（`directional=false`）：随手画的形状 θ 不稳，也没必要判；匹配只比形状。
- **与已有符号 ≥ 0.90 直接拒收**：两份几乎重合的模板都留着，每次识别都在边界上抖——比不认更糟。
- **仍不进 `Config`**：绑定与自定义都在 `SharedPreferences("kada-draw")`（`bindings` / `custom`），删除符号时连绑定一起删（否则留下取不出来的键）。进配置要动 core 模型 + 卡带格式 + 桌面兼容，留到 P2b。
- **adb 入口只做「代替手指」**：`drawLearn` 与「录自定义」按钮调同一个 `learn()`，坐标串与真笔画在设备上走同一条归一化 / 模板化路径。

### 决策

- **点坐标量化成 `[i16;2]`（0~1000）而不是浮点**：`Config` 一路 `PartialEq + Eq`，换浮点要把整个模型链降级；1/1000 对「重采样到 32 点」的识别器完全够用，还省得两份实现舍入口径不一致。
- **绑定键有两种，清洗只校验 `u:` 前缀**：预设符号写死在安卓侧、不进 `draw.symbols`。「符号必须存在」一刀切会把 `triangle → 某条目` 悄悄洗掉——第一轮全量跑就是这么红的（`draw save ignored=1`、画三角立刻变「还没绑定」）。
- **绑到不存在 / 已停用的条目不清绑定**：那是「已失效」，面板要看得见；只在 `detect_conflicts` 报 `Warn`。合并时反而更严（目标条目没进合并结果就不导绑定），免得导入一份配置就凭空多出一串告警。
- **迁移按「补空缺」而不是「有 `draw` 段就整体跳过」**：升级后用户很可能先绑了个预设符号（`draw.bindings` 已存在）才第一次打开画板；按「有段就跳过」，P2a 录的符号会被静默丢掉、prefs 还被清空（S2b-10 第一版就是这条红的）。
- **安卓画符号写盘仍只有一条路**：`RustBridge.save`（core 的 `sanitize_config` + `config_io` 原子写 + `.bak`），不新开 JSON 手写路径。
- **符号表缓存不能只靠 `learn` / `forget` 里的 `invalidate()`**：配置会被**不经过 `DrawStore`** 的路径整份换掉（导入、恢复出厂、桌面同步），那时一次 `learn` / `forget` 都没跑过。改成以**配置 `draw` 段原文**为缓存键（并让模板缓存跟着列表实例走）——收尾那次「导入 → 替换」就跑出了这个 bug：配置里已经没有 `draw` 段，报告仍 `custom=1`、面板还列着旧符号。
