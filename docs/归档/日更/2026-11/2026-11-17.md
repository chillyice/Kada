## 安卓 S2b：画符号（单笔画手势当触发源）

手机上没有物理键盘，S2 的触发源是「打开面板点一下 / 磁贴 / 通知 / 音量键」——都要求先找到那个入口。
这一轮补的是**不打开面板就能点一下**：长按悬浮球画一笔，抬手执行绑定的那条快捷键。

### 决策

- **S3 root 档不排期**：本机没有 root 设备、手机 root 比例逐年下降，root 只换来「改键 + 鼠标手势」两样，而这两样在手机上的需求量远低于「点一下」与「画一笔」。有 root 真机 + 明确需求再动（`docs/安卓版规划.md` §6 表下）。
- **符号 + 方向两关判定**：只做形状识别不够——四向三角在 $1 眼里是同一个形状。方案是 90° 扇区量化 + ±35° 容差，落在 45° 附近**直接拒绝**：猜错方向比不识别更糟。
- **绑定不进 `Config`**：进配置要动 core 的模型、卡带格式与同步口径，收益要等「录自定义画法」（P2）才显现；这一轮先用本机 `SharedPreferences`，执行链完全复用现有快捷键。
- **自检跑在设备上**（`op drawSelfTest` → 报告 `phone.draw.selfTest`）：断言的正是「旋转方向 / 扇区阈值」这类只有真跑才作数的东西，而离线 Gradle 拉不到测试依赖，索性不引。
- **画板打开走 service intent**：`startForegroundService` 是异步的，直接拿 `instance` 会静默失败；`ACTION_SHOW_BOARD` 让 `onCreate` 先跑完。

### 决策

- **存原始笔画，不存归一化后的 32 点**：归一化口径（点数 / 缩放 / 重采样）以后还会调，存原始点意味着老符号能跟着新算法重新归一化；代价只有一条几百点的 JSON。
- **自定义符号不判方向**（`directional=false`）：随手画的形状 θ 不稳，也没必要判；匹配只比形状。
- **与已有符号 ≥ 0.90 直接拒收**：两份几乎重合的模板都留着，每次识别都在边界上抖——比不认更糟。
- **仍不进 `Config`**：绑定与自定义都在 `SharedPreferences("kada-draw")`（`bindings` / `custom`），删除符号时连绑定一起删（否则留下取不出来的键）。进配置要动 core 模型 + 卡带格式 + 桌面兼容，留到 P2b。
- **adb 入口只做「代替手指」**：`drawLearn` 与「录自定义」按钮调同一个 `learn()`，坐标串与真笔画在设备上走同一条归一化 / 模板化路径。

### 决策

- **点坐标量化成 `[i16;2]`（0~1000）而不是浮点**：`Config` 一路 `PartialEq + Eq`，换浮点要把整个模型链降级；1/1000 对「重采样到 32 点」的识别器完全够用，还省得两份实现舍入口径不一致。
- **绑定键有两种，清洗只校验 `u:` 前缀**：预设符号写死在安卓侧、不进 `draw.symbols`。「符号必须存在」一刀切会把 `triangle → 某条目` 悄悄洗掉——第一轮全量跑就是这么红的（`draw save ignored=1`、画三角立刻变「还没绑定」）。
- **绑到不存在 / 已停用的条目不清绑定**：那是「已失效」，面板要看得见；只在 `detect_conflicts` 报 `Warn`。合并时反而更严（目标条目没进合并结果就不导绑定），免得导入一份配置就凭空多出一串告警。
- **迁移按「补空缺」而不是「有 `draw` 段就整体跳过」**：升级后用户很可能先绑了个预设符号（`draw.bindings` 已存在）才第一次打开画板；按「有段就跳过」，P2a 录的符号会被静默丢掉、prefs 还被清空（S2b-10 第一版就是这条红的）。
- **安卓画符号写盘仍只有一条路**：`RustBridge.save`（core 的 `sanitize_config` + `config_io` 原子写 + `.bak`），不新开 JSON 手写路径。
- **符号表缓存不能只靠 `learn` / `forget` 里的 `invalidate()`**：配置会被**不经过 `DrawStore`** 的路径整份换掉（导入、恢复出厂、桌面同步），那时一次 `learn` / `forget` 都没跑过。改成以**配置 `draw` 段原文**为缓存键（并让模板缓存跟着列表实例走）——收尾那次「导入 → 替换」就跑出了这个 bug：配置里已经没有 `draw` 段，报告仍 `custom=1`、面板还列着旧符号。

### 决策

- **顺序与笔数才是身份，位置不是**：每笔各自归一化、只比形状与顺序；「圆 + 竖」与「竖 + 圆」是两个符号。随手画时人对相对位置的控制最差，拿位置当特征只会让同一符号每次都抖。
- **多笔画要单笔下限**：总分取各笔平均，只卡总分的话「一笔完美 + 一笔乱涂」会靠平均混过去，所以另加 `STROKE_FLOOR = 0.72`。
- **单笔画符号只接受「只画了一笔」**：多笔画手势不拿第一笔去猜圆 / 三角——宁可没反应，也别在用户还没画完时就执行。
- **画板按「还可能接得更长」决定等不等**：`mayContinue`（存在更长符号且前几笔 ≥ 0.80）才等 700ms；没有多笔画符号时恒为立即提交，单笔画体验零回归。
- **`closed` 不落盘**：由点自己算（起收笔距 ≤ 总长 15%），少一个可能与点矛盾的字段。
- **老格式照读**：P2b 的符号级 `points` 用手写 `Deserialize` 并成一条笔画；否则清洗会把符号连同绑定一起丢掉，用户视角是「升级后符号没了」。

- 本地：`assembleDebug` 成功；`Get-FileHash` / 字节数与远端 `sha256sum` / `stat` 一致。
- 远端：APK 直链 200 + 长度一致；`latest.json` 线上回读与本地逐字一致；chunk 与 `sw.js` 回读见上表。
- 设备（模拟器）：覆盖安装后 `versionCode=9` / `versionName=0.2.0-s8`；自检 34/34；更新检查 `latest`；升级前（v8 包）检查为 `available`。
- `node scripts/check-docs.mjs` / `check-i18n.mjs` 通过。

### 遗留

- APK 仍是 debug 签名（侧载渠道；Play 上架不在计划内）。
- `latest.json` 仍手工维护；`sw.js` 的 `revision` 仍要人工跟着 chunk 更新（本轮第二次踩「`revision:null` + immutable」这个坑）。

## 发布后修：点安卓下载却跳到 ihomy 首页

现象：在 `https://ihomy.top/kada` 点「APK · 调试签名」不是下载，而是打开 `https://ihomy.top/home?page=kada&file=…`（ihomy 首页）。

| 项 | 结论 |
|---|---|
| 复现 | 直接导航到 `/api/public/product/download?page=kada&file=…`：**装了 PWA（有 Service Worker）**时落在 `/home` 并带回原 query；同一台浏览器**先注销 SW** 再导航则正常触发下载 → 不是后端 / nginx 的问题（`curl` 带 `Accept: text/html` + `Sec-Fetch-Mode: navigate` 也是 302 → APK 200 / 8,525,625 B） |
| 根因 | `sw.js` 里 Workbox 的 `NavigationRoute(createHandlerBoundToURL("index.html"), { denylist: [/^\/mini-games\//] })` 只放行了静态小游戏：**`/api/`、`/files/` 的导航请求被离线兜底顶成 `index.html`**，SPA 路由找不到该路径就跳 `/home`（query 原样带走）。下载接口 `/api/public/product/download` 正好是「302 → /files/…」的导航式链接，于是「点下载」变成「打开首页」 |
| 修复（源码） | `ihomy/frontend/vite.config.js`：`navigateFallbackDenylist` 加 `/^\/api\//`、`/^\/files\//`；`runtimeCaching` 的 `/api/` NetworkFirst 排除 `/api/public/product/download`（8 MB 级二进制不进 `api-cache`） |
| 修复（线上） | 不整包重发 dist：直接对线上 `sw.js` 定点改两处（`denylist` 加两条、api 缓存排除下载接口），`node --check sw.js` 通过、属主复原；SW 靠 `autoUpdate` + `skipWaiting`/`clientsClaim` 在下次加载时换新 |
| 验证 | 注销旧 SW → 重新打开页面 → `controller=true` 后再点 APK：开始下载 `kada-android-0.2.0-s8-debug.apk`（8,525,625 B），页面停在 `/kada`；直接导航到下载接口也不再落到 `/home` |

### 教训

- **PWA 的导航兜底要留白名单**：`/api/` 与 `/files/` 这类「非 SPA 路径」必须排除，否则「能下载」会被离线缓存吃掉——而且只在**装了 PWA 的浏览器**上复现，用 `curl` 或刚开始调试时看不出来。
- 现象容易被误判成「链接写错了」：`a[href]` 与 `download` 属性全对，错在被 SW 换成了一张 `index.html`。先看 `navigator.serviceWorker.controller`、再注销 SW 对照一次，比读模板快。
- 同类风险还在别处：`AppDownload.vue` / `BitPouch.vue` 的安装包链接走同一个接口，这次一起修好了（denylist 是全局的）。
