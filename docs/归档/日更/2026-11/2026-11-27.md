# 2026-11-27

## 动作类型新增「轮巡」（Action::Cycle）

需求原话：「这一组里有三个动作，按下按键先触发第一个，第二次按触发第二个，第三次按触发第三个，第四次回到第一个，如此反复」。做法是把轮巡做成**容器动作**（与 `Group` / `Parallel` / `If` 同级），每次触发只挑一个成员上场。

| 文件 | 改动 |
|---|---|
| `crates/kada-core/src/action.rs` | 新增变体 `Cycle { actions, description }`（`serde(tag = "type")` → JSON 里是 `"type":"cycle"`，`actions` / `description` 都带 `serde(default)`）；`validate()` 递归校验成员 |

**决策**：

1. **计数放 `kada-actions` 的进程内静态表，不落盘、不进配置**：`run_actions` 每次触发都是无状态的、`fire` 有多个调用点，把「轮到第几个」塞进壳层得改一大串签名。按「触发身份 + 动作 JSON 指纹」做 key —— 不同快捷键互不干扰，**改了轮巡内容就按新动作从头计数**（指纹变了等于另一个轮巡）。代价是重启归零（用户视角：重新开应用后从第一个开始），符合「这只是个便利计数器」的定位。
2. **禁用成员直接踢出轮换，而不是「轮到它时跳过」**：铁律 1.8「关掉开关 = 它不存在」。所以 `N`（总数）与「第 n/N 个」都按**可执行成员**算，`action_body` / UI 摘要同口径数，避免标题与摘要对不上（真出现过：摘要说 3 个、标题说 1/2）。
3. **空组 / 全禁用不留白**：照 Group 的做法报一条 `ok` 步骤，`stdout` 写明「没有可执行的成员」，省得用户以为按键坏了。
4. **`action_description` 不放进 automation 门控**：第一版顺手塞进了 `#[cfg(feature = "automation")]` 分组，基础版（`--no-default-features`）直接 E0004 —— 轮巡与分组一样属基础版能力，必须留在非门控组。
5. **成员按一条子链跑**（`run_chain(from_ref(member))`）而不是直接 `run_action`：这样成员里放分组 / 条件判断 / 并行 / 嵌套轮巡都不用另写一套；中止语义与 Group 一致（子链已收尾记过结果，外层不再记）。
