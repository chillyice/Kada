##### 更新失败提示分类 + 动作类型标签「文件/目录」（V1.00）

更新检查 / 下载失败不再把插件的英文错误原样抛给用户，也不再让后台检查静默失败：网络不通、超时、清单缺失 / 格式坏、缺平台条目、签名不符 / 版本不一致各自给出中文原因与下一步；后台失败记入消息中心（去重）。同时把动作类型下拉的「文件/目录操作」正式改名为「文件/目录」（收掉 V0.85 留下的小尾巴）。

| 文件 | 改动 |
| --- | --- |
| `src-tauri/src/update.rs` | 新增 `CHECK_TIMEOUT_SECS`（20 秒，**只限清单请求**）并接进 `build_updater`；`endpoint` 改为直接接收 `UpdateSource`；新增 `source_label` / `check_error_text` / `download_error_text`（按 `UpdateError` 分类：`Reqwest` 超时与连接失败、`ReleaseNotFound`、`TargetNotFound` / `TargetsNotFound`、`Serialization` / `Semver`、`Minisign` / `MissingSignedVersion` / `SignedVersionMismatch` 等）；`fail` 手动模式弹窗、自动模式改记消息中心；新增 `record_auto_failure`（`kind: "error"`、`label: "更新"`、`trigger: "后台更新"`，按错误文本去重）与 `UpdateState::last_auto_error`（成功阶段清空）；手动检查「已是最新」与「无需下载」提示带更新源；安装前核对发现清单已翻页 / 已是最新时按手动与自动分别提示 |
| `ui/src/main.ts` | `ACTION_TYPES` 的 os 标签「文件/目录操作」→「文件/目录」；两处注释同步 |
| `ui/index.html` | 变量指南示例文案「文件/目录操作 → 复制」→「文件/目录 → 复制」 |
| `crates/kada-core/src/lib.rs` | `OsOperation` 文档注释里的界面标签同步改名 |
| `docs/需求设计说明书.md` | §2 Os/System 分类注释同步；§5.5 新增「失败提示按原因分类、说清下一步」条 |
| `docs/变量提取与引用指南.md` | 示例文案同步 |
| `docs/人工验证清单.md` | §29 的类型下拉文案同步 |

**规则 / 决策**：

- **错误必须分类翻译，不能直接 `format!("{e}")`**：插件把 HTTP 非 2xx 压成 `ReleaseNotFound`、免安装版缺条目只报英文 `TargetNotFound`，原样展示等于没提示。每类错误都要回答「哪个源、什么原因、怎么办」。
- **清单请求单独限时 20 秒**：不设时限时连不上更新源会一直停在「正在检查更新…」。插件 `check()` 构造的 `Update` 句柄 `timeout` 为 `None`，所以这个时限不会掐断下载（镜像带宽低时大包需要更久）。
- **后台失败不弹窗但必须留痕**：自动检查 / 下载 / 安装没有用户在场，只写设置页状态等于永远没人知道；记进消息中心（未读红点）即可发现。按错误文本去重，防止自动安装每 10 分钟重试刷满消息页；成功一次后清空去重记忆。
- **动作类型标签正式定为「文件/目录」**：V0.86 拆分「操作系统」时曾判断标签已字面贴合、无需改名，但用户仍觉得「操作」二字多余；本次统一为「文件/目录」，与 `Os` 的文档叫法一致。

**验证**：

- `cargo test --workspace` 全绿（壳 **121**（+2）/ kada-actions 27 / core 148 / hook 29 + 2 ignored / smoke 1，共 **326 passed**）；`cargo check -p kada` 与 `--no-default-features` 通过；`npm --prefix ui run build`（tsc + vite）通过。
- 新增单测 `check_errors_are_translated_with_source_and_next_step`、`download_errors_explain_signature_and_version_mismatch`，钉住「哪个源 / 什么原因 / 已拒绝安装」等关键字。
- **未验证**：真机断网 / 更新源 404 / 便携包缺条目时的实际弹窗与消息中心观感（分类逻辑由构造 `UpdateError` 的单测覆盖，端到端需发布环境配合）。

**AGENTS.md 体积**：未动（19,925 B，无新「铁律」，且已接近 20KB 上限）。

##### 设置页同步 / 片段两组项目合并（V1.01）

设置页「配置与数据」卡片里两对相邻项各自合成一行：**同步存档**把目录选择、清除、立即同步、从存档恢复四个按钮收进同一项；**片段市场**把索引地址文本框与「打开…」按钮收进同一项。手动同步两个动作的解释从常驻说明文字改为按钮悬停提示（`title`）。

| 文件 | 改动 |
| --- | --- |
| `ui/index.html` | 「片段市场」与「片段索引地址」合并为一行（索引地址输入框 +「打开…」）；「同步存档」与「手动同步」合并为一行（选择目录 / 清除 / 立即同步 / 从存档恢复）；删除「手动同步」行，两个手动动作的说明改挂 `title`（「选择目录…」也补了说明）；索引地址框补 `placeholder` 与 `title`。两条合并行加 `set-row-merged`，控件包进 `.set-controls` |
| `ui/src/style.css` | 新增 `.set-row-merged`（`flex-wrap: wrap`，说明与控件各占 `flex: 1 0 100%`）与 `.set-controls`（右对齐、8px 间距、可换行）；原 `.set-row > input[type="text"]` 改为 `.set-controls > input[type="text"]`（`flex: 0 1 340px` + `min-width: 170px`，去掉 `margin-left: auto`） |
| `docs/需求设计说明书.md` | §6.6 设置页描述改为合并后的行结构，并说明手动同步解释走按钮悬停提示 |

**规则 / 决策**：

- **合并项采用「说明占第一行、控件放第二行」**：宽窗口下设置卡片是两列（每列约 520px），同步存档的四个按钮加左侧说明硬挤一行会把说明压成 3 行以上（实测片段市场说明会到 6 行）；控件整体换行后说明恢复单行，控件仍贴右缘对齐，与原设置行视觉一致。
- **手动同步的解释改用原生 `title`**：这两个动作是低频操作，常驻说明占一整行不划算；悬停提示能就地回答「这个按钮会做什么」，且不改按钮文案与行为（保留系统原生提示，不另造浮层）。

**验证**：

- `npm --prefix ui run build`（tsc + vite）通过。
- **浏览器演示模式实测**：设置页两条合并行 `overflowX = 0`；说明区宽 512px、小字高 19px（单行）；控件位于第二行、右缘与卡片对齐（片段市场输入框 340px +「打开…」；同步存档四按钮 91 / 52 / 78 / 104px）。DOM 中不再有「手动同步」「片段索引地址」两个独立项；「立即同步」「从存档恢复…」「选择目录…」的 `title` 均已生效。
- **未验证**：壳内 Tauri 真实窗口的悬停提示观感（原生 `title` 由系统渲染，浏览器与壳内一致）。

**AGENTS.md 体积**：未动（纯界面布局调整，无新铁律）。

##### 像素 CRT 主题（新增第三主题，原主题不动）（V1.04）

用户要把软件风格换成**像素游戏 + 复古显像管终端**（绿色荧光字、扫描线、像素字体与图标），但明确要求**原样式不变、只是增加一个主题、可切换**。实现是设置页主题下拉新增「像素 CRT」一档；全部视觉规则作用域限定 `[data-theme="crt"]`，深色 / 浅色两套样式一行未动。

| 文件 | 改动 |
| --- | --- |
| `ui/index.html` | 「界面主题」下拉新增 `<option value="crt">像素 CRT</option>`；左栏品牌字拆成 `.brand-glyph`（原单字 K）与 `.brand-word`（四色 Kada 字标，`aria-hidden`），默认只显示前者 |
| `ui/src/style.css` | 末尾新增「像素 CRT 主题」整块：`@font-face`（Kada Pixel）+ CRT 变量组（荧光绿调色板 / 字号阶梯 12·12·12·14·16·24px / `--font-pixel`）+ 字体覆盖、荧光 `text-shadow`、全站方角、硬边投影、SVG `crispEdges` / 2.4px 线宽 / 辉光、主界面扫描线 + 暗角 + 淡亮带（`body:has(.layout)::before/::after`，`pointer-events:none`）、三个浮窗的面板内扫描线、主按钮深色字、类型色（K 青 / a 黄 / a 绿）、四色字标 + 星芒、`prefers-reduced-motion` 降级 |
| `ui/src/assets/fonts/kada-pixel-sc.woff2` | 内嵌「缝合像素（Fusion Pixel）12px 等宽简中」，31,345 字形，约 595 KiB（构建报告 609 kB） |
| `ui/src/assets/fonts/LICENSE-OFL.txt` | 字体 SIL OFL 1.1 许可证 |
| `docs/需求设计说明书.md` | §6 开头改为三主题；§6.2 改写为四档下拉，并新增 CRT 的叠加层 / 视觉构成 / 扫描线 / 像素字体 / 品牌字规则；§6.6 设置页主题项同步 |
| `docs/人工验证清单.md` | 新增 §33「像素 CRT 主题（真机观感）」+ 状态表一行 |

**规则 / 决策**：

- **CRT 是叠加层，不是第四套基准**：选择器一律带 `[data-theme="crt"]`，深色 / 浅色的变量与规则不碰；切回即完全恢复原样。设置项只加一个 `<option>`，`localStorage["kada.theme"]` / `resolveTheme()` / 首帧应用这套机制原样复用。
- **字体内嵌但按需加载**：`@font-face` 写在全局，只有 CRT 字栈引用它；浏览器不会在深色 / 浅色下下载这 600KB。选 Fusion Pixel 12px 等宽简中是因为它有 31k 字形、覆盖简体中文，且为 SIL OFL 1.1（许可证与字体一起入库）。CRT 下字号阶梯改用 12 的整数档，避免像素字体被非整数缩放糊掉。
- **扫描线不能画在 body 上给浮窗用**：`#toast` / `#hud` / `#hints` 是透明窗口，body 必须保持透明；画在 body 上会把整圈透明留白糊成实心矩形。浮窗扫描线画在 `.toast-bubble::after` / `.hud-row::after` / `.hints-panel::after`，硬投影也只给无模糊的 `4px 4px 0`，保证落进窗口透明边（气泡 12px / HUD 7px / 提示框 10px）内。
- **图标不另做一套资源**：用 CSS 在现有 SVG 上做 `shape-rendering: crispEdges` + 方端头 + 2.4px 线宽 + `drop-shadow` 辉光，一份 DOM 两种观感；品牌字用 `.brand-glyph` / `.brand-word` 两段在不同主题间切换，深色 / 浅色仍是原来的单字 K。
- **主按钮在 CRT 下反转为深色字**：亮绿实底上的白字对比度不足，改用 `#04120a`；`--accent-dim` 上的字仍守「一律 `--text`」那条既有规则。
- **动态效果可降级**：扫描亮带、闪烁与星芒在 `prefers-reduced-motion: reduce` 下全部停掉，只留静止扫描线。

##### 像素 CRT 改为发光扫描线 + 恢复动态、字体去加粗（V1.08）

用户看过 V1.07 后提出三点：① 闪烁与自上而下的亮带要留着；② 满屏横线改成**亮的**，像屏幕在发光；③ 字体太粗、容易看不清。于是把扫描线从「压暗的黑线」改成「提亮的白线」，恢复 V1.07 删掉的两段动画，并去掉让像素字加粗一圈的 1px 贴边实影。

| 文件 | 改动 |
| --- | --- |

**规则 / 决策**：

- **「发光」用加法、不用减法**：老实现是黑色横线压暗画面，观感是「脏」；改成白色亮线后在深色底上直接提升亮度，才像荧光粉发光。用「主线 + 1px 次级余晖」制造柔和过渡，避免硬边白线像栅栏。

- **浅色档的亮线要更高浓度**：同样的白线在白 / 浅灰底上对比弱，故主线从深色档的 5% 提到 50%，靠「比底色更白」体现透光感。

##### Linux 热插拔（7.2-㉜ 落地 → 7.1-㉜）（V1.21）

§7.2-㉜：Linux 侧设备拔出会正确复位状态，但之后**只能重启应用**才恢复监听。落地：钩子线程每 2 秒只看一次 `/dev/input` 的 `eventN` 目录条目（不打开设备），条目变了才重新枚举，把新接入、尚未抓取的键盘 / 鼠标接进来；拔出的设备沿用原有的 fetch 错误路径移除并复位。**轮询而非 inotify**：零新依赖、不新增线程，2 秒延迟对热插拔足够。两个坑：必须**跳过自建虚拟设备** `kada-virtual-input`（否则注入事件被自己抓回来）；设备丢失时清空目录快照**强制重扫**（内核会把刚释放的 `eventN` 号复用给重新插入的设备，只比快照会漏）。

| 文件 | 改动 |
|------|------|
| `crates/kada-hook/src/linux.rs` | 新增 `VDEV_NAME` / `RESCAN_INTERVAL` / `Grabbed { path, dev }`；`start` 保留每个设备的 `eventN` 路径并跳过虚拟设备；`poll_loop` 每 2s 比对目录、变了调 `rescan_devices`；新增 `event_nodes`（只认 `eventN`）与 `rescan_devices`（跳过已抓 / 虚拟 / 非键鼠，抓取失败只留一行日志）；设备丢失时 `nodes.clear()` 强制下一轮重扫；新增单测 `event_nodes_only_lists_event_digits` |
| `docs/需求设计说明书.md` | §4.2 设备丢失条改为「复位 + 热插拔」（机制与 2s 轮询）；§4.5 删掉「Linux 热插拔不在监听列表」；§7.1 新增 `P3-㉜`、§7.2 删掉 ㉜ |
| `docs/人工验证清单.md` | **新增 §36**（Linux 真机：插拔 USB 键盘 / 鼠标、快速插拔、按住修饰键时拔出、虚拟设备不被抓走）；状态表与复跑索引同步 |

**规则 / 决策**：

- **只比对目录条目，不每拍枚举**：`evdev::enumerate()` 会打开每个设备，2 秒一次地反复打开既浪费也可能在 `EBUSY` 时刷日志；`read_dir` 只看文件名，条目不变就零开销。

- **丢失即清快照**：解决「拔出与插回发生在同一次 2s 检查内、`eventN` 号相同 → 快照看不出变化」的竞态；代价是极端情况下陈旧节点可能被重试（真机拔插时节点会消失）。

**规则 / 决策**：

- **入口放在「快捷键」页的「鼠标操作」分类**（不另起设置页卡片）：手势是**鼠标相关功能**，与快捷键 / 改键 / 文本扩展并列成合并列表的第四类——行首图标区分类型，模式菜单里叫「鼠标操作」，编辑页填方向串 + 动作。设置页只留一张「实验功能」卡片放**新功能总闸**（将来滚轮快捷键等新功能也归它管）。**别影响其他功能**：三类原有条目的路径一行未改（`FOLDER_ENTRY_KINDS` 仍只含目录型条目，鼠标操作无目录归属，排在根级）。
- **手动打 exe 必须带 `--features custom-protocol`**：这个 feature 才是「用内嵌前端资源而不是 dev server」的开关（Tauri CLI 打包时自动带上）。直连 `cargo build --release -p kada` 出来的 exe **只嵌壳不嵌前端**，运行时去连 `http://localhost:1420` → 用户看到「嗯… 无法访问此页面 / localhost 拒绝连接」。判据很快：exe 里搜不到字体文件名（`kada-pixel-sc`）就是没嵌进去。已写进 `AGENTS.md` 的构建命令区。
- **一个总闸管所有新功能**（`Settings.experimental`）：这类功能「全局抢右键」这类副作用必须留一个一键回退的闸门。**关掉 = 入口隐藏 + 行为不生效，配置保留**（不删用户的配置）——删配置等于替用户做决定，且重新打开就白配了。**默认关**（缺字段即关）：新功能多半带全局副作用，替用户打开不合适，要用的人自己开。
- **正式开发完成前不对外发布 release**：本功能只落了第一期（余项见 §7.2-MG），且真手势尚未真人验收——在余项清空 + §40 验收通过之前**不打 tag、不发 release**（含更新源 / 镜像）。
- **手势不进 `Key` 模型**：右键不是键，进了会污染快捷键 / 改键 / 冲突检测 / 录入四条链路。手势走独立触发通道，**动作链 / 执行记录 / 气泡全部复用现有引擎**。
- **手势不进 `Engine::step`**：它不是键序列，绕进状态机会把 tap-hold / 和弦 / 序列那套等待态搅乱。
- **识别是纯函数、在壳层做**：钩子回调超时会**被系统静默摘掉**（整个输入层随之失灵），所以回调里只记点；方向量化与匹配放 `kada-core::gesture`（可单测），执行放壳层线程。
- **未命中必须回放右键**（吞键铁律）：手势吞掉的右键如果不给补回来，用户的右键就废了——这正是 外部实现「什么都不做」与 Kada 的分水岭。**匹配到但没配动作**也按「没命中」处理（半条配置不能把右键吞掉）。
- **按需挂钩子要分两个口径**：`config_uses_mouse` 兼着「输入层环境诊断要不要跑」，手势只用右键，混进去会让用户白收「厂商软件接管了鼠标键」的提示；故新增 `config_needs_mouse_hook` 专管「钩子挂不挂」。
- **手势开着时右键归手势**：右键单击会晚十几毫秒、鼠标操作录制录不到右键——这是全局拦截的固有代价，靠「总闸 + 设置页一键关」兜底。
- **手势的动作链复用现成的动作编排器**（不是「每条手势只配一个动作」）：「鼠标操作」这一类与快捷键共用 `#work-shortcut` 那套流程图编辑器。为此把动作宿主从「快捷键草稿」抽成 `currentActionsHost()`（快捷键 / 鼠标操作两个草稿），加动作 / 加分组 / 录制都走它。

##### 鼠标手势采集出口修复 + 两处可见反馈（V1.29）

用户反馈「Kada' 的功能未能从 kada 里成功使用，甚至鼠标右键根本无法出现手势效果」。查下来是**三件事叠在一起**，其中一处是硬缺陷：

1. **采集的轨迹出口被取走了（缺陷）**：`on_right_up` 里 `SINK.lock().unwrap().take()` 把出口**取走**再回调——于是**第一次右键抬起之后出口就没了**：之后所有手势都不再上报；更要命的是这时右键**仍被吞**（`on_right_up` 照旧返回「吞」），却没人回放 → **右键菜单从此再也不弹**。而第一次右键往往只是一次普通点击，用户看到的就是「手势完全没反应 + 右键也坏了」。
2. **总闸是关的**（配置实况）：`Settings.experimental = false` → 采集闸门关着、手势不生效；而总闸关着时「鼠标操作」这一类在界面上是**整类隐藏**的，用户在列表里根本看不到自己配的那条手势 → 只会得出「配了没反应」。
3. **没匹配上时毫无反馈**：只有一行 `eprintln!`，GUI 里什么都不显示。

| 文件 | 改动 |
|------|------|
| `crates/kada-hook/src/gesture.rs` | `StrokeSink` 由 `Box<dyn Fn(Stroke) + Send>` 改为 **`Arc<dyn Fn(Stroke) + Send + Sync>`**；`on_right_up` 改为**克隆借用**（`SINK.lock().unwrap().clone()`）而不是 `take()`——出口是**长期资源**，每次右键抬起都要用它。两条单测合并成一条（`right_button_gestures`）：采集状态是**全局静态**、多个 `#[test]` 会并行跑并互相踩 `set_enabled`，拆开测没有意义；合并后连画 5 次手势，断言出口**每次都收到**（钉住「取走一次 = 之后再没有下一次」） |
| `src-tauri/src/lib.rs` | 注册出口改 `Arc::new`；`handle_gesture` 的两个「没命中」分支（方向串没配 / 配了但没动作）各加一条**气泡**（`show_toast_note`）：报出方向串（如「手势未匹配：RU」）+ 教用户把方向串填进「快捷键 → 鼠标操作」，同时照旧回放右键；气泡**不进消息中心**（每次误拖都留一条会成噪音） |
| `ui/src/main.ts` | `renderConflictBubble` 增一条气泡：**总闸关着但已配了手势** → 列表栏顶部「已配置 N 条鼠标手势，但「实验功能」未开启 → 不会触发」，**点一下就打开总闸并落盘**（新增 `enableExperimentalFeatures`） |
| `docs/需求设计说明书.md` | §5.9 增「两处看得见的反馈」段（总闸关着的气泡 / 没匹配上的气泡） |
| `docs/人工验证清单.md` | §40 增第 11~13 步（总闸气泡、未匹配气泡、**连续多次手势**回归项）与三条判失败；标题与状态表注明「2026-10-21 首次真机尝试暴露此缺陷，已修待复跑」 |
| `docs/鼠标手势与功能扩展规划.md` | 状态行补「首次真机尝试暴露并已修一处采集缺陷」与两处反馈 |
| `AGENTS.md` | 钩子引擎「鼠标手势」条补「**轨迹出口只借用不取走**」与「总闸关着但已配手势 → 列表栏出气泡，点一下就开」；**为腾体积压掉两处细节**（罗技解锁的 CID 细节、Linux 交叉检查的括注，均在 `需求设计说明书` 里） |

**规则 / 决策**：

- **钩子层的回调出口是长期资源，只能借用不能取走**：`Box<dyn Fn>` 天然「一次性」，但出口的语义是「每次事件都找它」——取走一次，链路上剩下的事件就没人接了，而**吞掉的动作没人回放**（吞键铁律的另一半）。这类出口一律用 `Arc` 装，取用时克隆。
- **「配了没反应」必须看得见**：总闸关着是**设计**（新功能默认关，见 V1.28），但**「藏起来」不能是唯一的告知方式**——这一类整类不显示时，用户唯一的线索就是「配了没反应」。所以配了却关着 → 列表栏出气泡（点一下就开）；画了没匹配 → 报出方向串的气泡。两处都是**就地可行动**的提示，不是日志。
- **气泡不进消息中心**：消息中心是**结果**的归档（执行记录 / 命令结果），「没匹配上」是过程中的常态提示（每次误拖都留一条会把它淹掉）。气泡 3 秒自动消失，位置固定，不抢前台。
- **单测里的全局静态状态只能串在一个测试里**：`TRACKER` / `SINK` / `ENABLED` 都是进程级静态，多个 `#[test]` 并行跑会互相踩（`set_enabled(false)` 把另一个测试的采集掐掉）——这类测试要么合并成一条，要么自己加串行锁。合并后还顺带钉住了「连续多次手势都要有反应」这条回归。

**验证**：

- `cargo test --workspace` 全绿（壳 121 / kada-actions 27 / core 159 / hook **31**（采集单测 2 → 1，合并后覆盖更全）/ smoke 1）；`cargo check -p kada` 与 `--no-default-features` 通过；`cargo check -p kada-hook -p kada-actions --target x86_64-unknown-linux-gnu --all-targets` 与 `--target aarch64-apple-darwin --all-targets` 均通过；`npm --prefix ui run build`（tsc + vite）通过。
- **release exe 重编并启动**：`cargo build --release -p kada --features custom-protocol` 通过（14,929,920 B），程序已重启（旧的 17:25 版本正在运行、锁着 exe，编译前先停掉）。
- **未验证**：**真手势端到端仍未跑**（合成事件带 `LLMHF_INJECTED`、被钩子放行，主工程没有自测开关）——需按 `人工验证清单.md` §40（含本次新增的第 11~13 步）真人复跑；macOS / Linux 上手势**不生效**（采集没接线，属已知边界）。

##### 「停止执行」改挂到「执行中」徽标右侧的图标按钮（V1.30）

用户诉求：停止按钮移到「执行中」状态右侧、以图标按钮呈现，**只有执行中的才需要停止**，右上角那颗删掉。

**规则 / 决策**：

- **入口跟着状态走**：停止按钮只在**真的有东西在跑**时存在。常驻按钮的代价是「永远可点、多数时候无意义」，而运行状态本来就是记录自带的字段（`RunRecord.status`），渲染时判一次即可；跑完（`ok` / `error` / `abort`）按钮自动消失，不需要额外的禁用态。

- **跑着的那条记录就在眼前**：新记录到达时列表自动选中它（`run-update` 里 `msgSelId` / `msgIndex` 归零，既有行为），所以触发后打开「消息」页看到的正是那条执行中的记录，按钮随即可见。

- **key = 中文原文，不是语义 key**：`tr("保存")` 比 `tr("common.save")` 少一层命名与维护，漏翻时源码里仍是通顺的中文；代价是改中文文案等于改 key（要同步词典），这对「中文是产品原文」的现状是对的——`check-i18n` 会把漏掉的立刻报出来。
- **语言是「这台机器怎么看」，不是配置**：只记 `localStorage["kada.locale"]`，**不进配置、不随同步存档走**——同一份配置给不同母语的人用各看各的。切换整页 reload，比逐块重画可靠（静态文案与已渲染 DOM 一起换）。
- **静态 DOM 只翻「整块纯文本」**：`innerHTML` 整块替换能保留 `<code>` / `<strong>` 这类行内标签，但**含表单控件 / svg / 图标的块必须跳过**，否则会抹掉控件；`i18n-html.mjs` 用同一口径提取 key，保证「提取到的」与「运行时翻到的」是同一批。
- **壳层文案仍中文，属已知缺口**：冲突消息 / 执行摘要 / 托盘菜单 / 原生确认框由 Rust 产生；要翻得改成「key + 参数」交前端翻译，或在壳层挂第二套字典（两套字典必然漂移），口径没定之前不动——并明确写进 7.2-㊲，避免被误当成漏翻。
- **手势 `when` 复用快捷键那套指纹**：`WhenKey` 已经是「判重是否同一条」的口径，手势直接沿用；因此**同方向串 + 不同 `when` 是两条独立条目**（按条件分流），冲突检测只对「方向串 + `when` 都相同」给 Warn，合并 / 清洗同一口径。
- **`when` 不成立 = 这条不存在**：与快捷键 / 改键一致——落到下一条同方向串，都落空就回放右键。不能因为「条件不成立」就把右键吞掉（违反吞键铁律）。
- **排除程序在识别之前判**：命中就整条不接管、连方向串都不算（省一次前台查询后的匹配，也让「游戏 / CAD 里右键拖拽是正常操作」真正回到原生）。语义复用 `when` 的「前台应用」（`match_name`），并把 `match_name` / `wildcard_match` 撤掉 `automation` 门控——基础版也有手势排除。
- **全屏自动暂停而不加开关**：判据「窗口矩形 ⊇ 所在显示器」+ `!IsZoomed`——最大化（浏览器 / 资源管理器）的窗口矩形含不可见边框、会越过显示器边缘，只用矩形判定会把最常见的「全屏感」误判成真全屏，手势在日常使用里静默失效。无边框全屏（游戏 / F11 / 视频）才是目标场景，且没有「全屏里还要用鼠标手势」的合理需求，故不设开关（少一个配置项、少一类「我明明开了却没用」的排查）。

##### 滚轮快捷键（Windows）（V1.33）

7.2-MG 余项①的前半：**滚轮当离散键**（`WheelUp`/`WheelDown`），可作快捷键 / 序列触发或改键来源与目标。后半（macOS / Linux 接线）留在 §7.2-MG。

滚轮与普通键的差别不在「按下/抬起」，而在**事件形态**：标准滚轮一次 `WM_MOUSEWHEEL` 带 ±120 的 `delta`，高精度滚轮 / 触控板可能只带 15 / 30，而且没有抬起事件。所以口径定成「**一格 = 一次按下 + 一次抬起**」：按 120 累积，够一格才合成一对 `KeyEvent`，不足一格原样放行（否则触控板每一丝滚动都会触发一次）；`Down` 的判定决定吞不吞，`Up` 由钩子补（状态机的按住集合 / 序列才看得到完整一对）。

**规则 / 决策**：

- **一格 = 按下 + 抬起**：滚轮没有物理按键状态，但状态机（序列 / tap-hold / 按住集合）都按「按下-抬起对」维护；合成一对才能复用整条决策链，不必给滚轮开特殊路径。和弦要「同时按住」，滚轮天然不满足，录入侧直接不收。
- **120 累积、换向清零**：`WHEEL_DELTA` 就是 120；按「每来一个事件就触发」会让触控板每一丝滚动都触发一次，按「只看事件不比 delta」又会在高精度设备上丢格。换向清零避免「上 90 + 下 90」被凑成一格（用户手感是两次微小反向移动，不是一次滚动）。
- **只有绑了才逐事件处理**：`config_uses_wheel` 单独判定（`config_uses_mouse` 包含滚轮是因为它同时管钩子安装与环境诊断），壳层推 `set_wheel_enabled`；没绑时钩子层直接返回「放行」，不构造事件、不碰 `HANDLER` 锁——不做这层，所有用户的每一次滚动都要多走一遍判定。
- **不足一格的事件原样放行**：吞掉半格会让高精度滚动的手感变「顿」；累积值留着下次接着用，命中那一格才吞。
- **注入只滚按下**：`WheelUp` 作为改键目标 / `Keys` 动作时，`tap`（Down+Up）不能变成两格；`Up` 分支显式不产生事件，代价是「按住滚轮」这种语义不存在（本来也不存在）。
- **macOS / Linux 显式留缺口**：`Key` 是三平台共享的，但采集与注入只接 Windows；两个后端的键码映射显式 `return None`，不让滚轮键在那里落成「看起来支持、实际静默失效」。余项写回 §7.2-MG ①。

##### 鼠标 / 按键动作补全（EXT-16 第一阶段）（V1.43）

EXT-16 六项盘点后按「不重复造已有能力」落地第一阶段。**X1/X2 点击**（`MouseButton::Back/Forward`、`Key::MouseBack/Forward`）与 **`App::Activate`** 已存在、不改；**「不激活发送」**（后台发给非前台窗口）语义与现有注入模型冲突，登记为二阶段，本版不做。

- `MouseOp::MoveTo { x, y }`：绝对屏幕坐标，统一以**主显示器左上角 = (0,0)**、多屏可为负。Windows 用物理像素，`SendInput` 前按虚拟屏幕 `SM_*VIRTUALSCREEN` 归一化到 0..=65535 并带 `MOUSEEVENTF_VIRTUALDESK`（越界夹边缘）；macOS 用全局点坐标 `CGEvent`；Linux 拿不到可靠的全局屏幕范围（尤其 Wayland），执行明确报错并标平台软冲突。
- `MouseOp::MoveToOrigin`：取本次手势的**右键按下点**。`TriggerCtx` 增 `origin: Option<(i32, i32)>`，`handle_gesture` 把 `stroke.points[0]` 传进 `fire`；快捷键 / 录制 / 手动执行路径为 `None`，执行到该动作报错而非静默。origin 在动作层解析成 `MoveTo` 后再注入，提权通道协议只新增 `mouse moveto`。
- `Action::Keys` 增 `mode`（`KeysMode`）：`tap` 默认且不落盘（旧配置形状不变）、`press` 只按下并登记、`release` 逆序抬起。按住状态按「作用域」登记在全局表：链尾 / 串行并行组结束由守卫收回，动作失败当步收回，输入复位由壳层在 `Engine::reset` 同一处调 `release_held_keys()` 收回——修饰键不会粘住。
- **并行顺序保证**：`Parallel` 递归检测到任一成员（含嵌套）有 press / release 时整组按声明顺序串行执行，避免注入锁只保证单步不交错而出现「先松后按」；全 tap / 普通动作的并行组仍真并发。

##### V1.45 复制快捷菜单（EXT-13）

选中文字后**双击 Ctrl+C** 在光标处弹出用户配置的动作菜单。触发**只旁路观察、不吞键**：两次 Ctrl+C 照常交给前台程序完成复制，Kada 只在第二次按下时弹菜单。

- **触发**：键盘钩子回调里判定「按下、非 repeat、主键 C、修饰键恰为 Ctrl」，两次间隔 ≤ `ClipboardMenu.double_copy_ms`（默认 500ms，150~2000），命中后清零。判定放在暂停 / 全局排除 / 全屏暂停三闸之后——这三种情形不弹；命中后由后台线程读剪贴板，空则不弹（读剪贴板不在钩子回调里做）。
- **模型**：`Settings.clipboard_menu` = `enabled` + `double_copy_ms` + `items`；条目为 `Action { label, enabled, action }` / `Submenu { label, enabled, items }` / `Separator`，数组顺序即顺序、`enabled` 缺省 true 不落盘、子菜单最多 3 层。条目内部是现有 `Action`（可用 `Group` / `Parallel` 串多步），执行完全复用动作引擎。
- **浮窗**：`index.html#clipboard-menu` 透明窗，`focusable(false)` + `focused(false)` + `shadow(false)` + `zoom_hotkeys_enabled(false)`，**不设鼠标穿透**（条目要能点，与 hints 同属「可交互但不可激活」）。锚点 = 触发时光标物理坐标，偏移 12 逻辑像素，放不下翻向左 / 上并钳进当前显示器工作区。
- **收回**：点条目 / Esc / 光标离开 300ms / 前台窗口变化 / 再次触发。菜单不可激活 → 收不到失焦事件，Esc 由钩子回调置旗标、60ms 轮询线程真正 `hide()`（回调里不碰窗口 / IPC）。
- **执行**：点击回 `clipboard_menu_exec(path)`，壳层按当前配置重解析（路径上任一层禁用则不执行），收回后走 `fire()`：等物理修饰键释放、链内注入锁、`ActionStep`、超时 / 中止全部继承。

##### V1.46 后台发送（EXT-16 二阶段）

把按键 / 文本发给一个**非前台窗口**：全程不激活、不抢焦点。作为**独立动作** `Action::SendTo` 落地，不给现有 `Keys` / `Text` 加字段——后者是前台注入语义（等修饰键、持 `SendInput` 那条链），前后台两套语义混在一个变体里会让 `injects_keys` / 修饰键等待 / 失败口径全部要分叉。

- **目标选择**：动作字段 `target` 由用户填，同时匹配**进程名或窗口标题**（复用 `app_excluded` 的忽略大小写 / `*` `?` 通配 / 否则子串）。`EnumWindows` 的顺序就是 Z 序，取第一个可见、非工具、非本进程的命中；命中顶层窗后再用 `GetGUIThreadInfo` 下钻到该线程的焦点子窗（编辑控件必须发给它，发顶层框没用），取不到才回顶层。**执行时**解析，不按触发那一刻的快照。
- **注入**：只用 `PostMessage`。按键走 `WM_KEYDOWN` / `WM_KEYUP`，`lParam` 带扫描码（`MapVirtualKeyW`）、扩展位与抬起位；文本逐 UTF-16 码元发 `WM_CHAR`（`\r\n` 只发一次回车、`\n` 归一成 `\r`）。组合键按声明顺序按下、逆序抬起，但**不模拟修饰键状态**——依赖 `GetKeyState` / `GetKeyboardState` 的程序仍会忽略组合键。
- **边界**：前台目标直接报错（前台只走既有 `simulate`，不开第二套注入路径）；目标进程提权时先查 `TokenElevation` 报错，**不复用提权伴随进程**（通道只放行 SendInput 类 op，加 hwnd + post 等于扩大提权进程能力面，而目标程序多半照样忽略 posted 消息）；无匹配 / 窗口已关闭 / 提权 / POST 被拒全部进该步 `error`，不静默。**已知不生效**：Chromium / Electron / WebView2、UWP / WinUI、Windows Terminal、游戏（Raw Input / 反作弊）、提权窗口、依赖真实修饰键状态的组合键；`PostMessage` 无回执，成功只代表消息进了队列。
- **与现有链的关系**：复用 `run_actions` / `ActionStep` / `RunRecord` / 链级超时与中止；持链内注入锁（保证链内输入步骤不交错），但**不算 `injects_keys`**——`PostMessage` 不受物理修饰键影响，算进去会白等 300ms、超时还会把整条链跳过。只支持 tap 类按键与纯文本；鼠标键 / 滚轮、转大小写、按住 / 抬起都在执行前报错。
- **平台口径**：只有 Windows 实现。macOS / Linux 的 `send_to_window` 返回明确错误；新增 `PlatformCaps.background_input`（Windows true，其余 false），`detect_conflicts` 对用到 `SendTo` 的快捷键与手势都标 `Warn`「后台发送仅 Windows 可用」，不拦保存。

##### V1.48 Explorer 补全（EXT-17）

四个 Windows Shell 动作，全部挂在既有 `Os` / `System` 下，不新建动作类型（它们是「对文件 / 操作系统本身做动作」，与现有分类口径一致）。

- **定位文件**（`OsOperation::Reveal`）：先查路径存在，再起 `explorer`，`/select,` 与路径分成两个参数（带空格路径由 Command 补引号，正好是 Explorer 认识的 `explorer /select, "C:\..."`）。只选中，不打开文件、不移动。
- **清空回收站**（`SystemOperation::EmptyRecycleBin`）：`CoInitializeEx` + `SHEmptyRecycleBinW`，带 `SHERB_NOCONFIRMATION | SHERB_NOPROGRESSUI | SHERB_NOSOUND`——动作本身就是用户明确配置的，执行时不再弹系统确认（与「删除文件」同一口径，**不可逆**）。
- **关闭显示器**（`MonitorOff`）：`SendMessageTimeoutW(HWND_BROADCAST, WM_SYSCOMMAND, SC_MONITORPOWER, 2)`，带 `SMTO_ABORTIFHUNG`，不阻塞等某个挂死的窗口；任何输入都会亮回。
- **切换桌面图标**（`ToggleDesktopIcons`）：先找 `Progman` 下的 `SHELLDLL_DefView`，找不到再遍历 `WorkerW`（Win10 / Win11 桌面宿主不同），对 `SysListView32` 发 `WM_COMMAND` / `0x7402`。
- **平台口径**：`PlatformCaps.shell_actions`（Windows true，其余 false）+ `uses_shell_actions` 递归动作树；快捷键与手势两条路径都标 `Warn`「当前平台用不了（只有 Windows 实现）」，不拦保存。执行侧 macOS / Linux 返回明确错误。
- **不碰输入层**：四项都不注入按键、不持注入锁；`Reveal` 用独立进程，其余用 Win32 API（actions crate 新增 `cfg(windows)` 的 `windows` 依赖 + `win_shell` 模块，基础版 `--no-default-features` 整个模块不编译）。

##### V1.49 CRT 品牌字标动效（霓虹微闪 / 按下回弹 / 星屑迸射）

把左栏品牌字标从「常驻星芒的静态四色字」改成**可按压的霓虹四字**：松开时那一下星屑就是「咔哒」那声轻响的视觉化。

- **静止霓虹微闪**：四字共用一套 9s 关键帧，`steps(1, end)` 让熄灭是**硬切**（不是呼吸式淡入淡出）；每轮两次「两连熄」+ 一次单熄，每次 50~90ms。熄灭次序固定 **K → d → 左 a → 右 a**：四字各挂 `--flick-delay`，按 0 / 90 / 180 / 270ms 递增（DOM 顺序是 K / 左 a / d / 右 a，所以变量挂在 `.bw-cyan` 0ms、`.bw-red` 90ms、`.bw-yellow` 180ms、`.bw-indigo` 270ms）。
- **按下**：四字**同时** `translateY(1px) scale(0.9)`，`text-shadow: none` 摘掉荧光，颜色往背景混（深色档混 `--panel`、浅色档混 `--text`）只剩暗淡本色；过渡 80ms。按下状态由 `.rail-brand.is-pressed` 驱动。
- **松开回弹**：190ms `cubic-bezier(0.2, 1.7, 0.45, 1)` 带轻微过冲弹回并恢复荧光，同时在右上角播放一次星屑（`.is-burst`）。星屑 = 3 颗星（7 / 5 / 4px，四角 / 五角 / 四角，`clip-path` 画）+ 3 根 1px 短射线（`-18° / -42° / -66°`，7~9px）；星向 `--dx/--dy`（右上 5~13px）飞出并旋转缩小淡出，射线快速亮起→停一瞬→淡出，各元素时长 280~530ms、延迟 0~105ms 错峰，落点与时机都不规则。
- **星屑层是字标的兄弟节点**（`.brand-burst`，不放在 `.brand-word` 里）：字标整体有 `skewX(-6deg)`，星形与射线跟着斜切会让角度失真；锚点放在 38px 盒的 `top: 9px / right: 0`（末字右上方），飞出最远约 x=63.9px，仍在 64px 宽的 rail 内。
- **不注册全局按键、不吞键**：只在 `.rail-brand` 上按下 / 松开（`pointerdown` 上 `.is-pressed`、`pointerup` 摘类并放 `.is-burst`），`setPointerCapture` + `pointercancel` / `pointerleave` 兜底；字标加 `user-select: none`，不会拖出一片选中文字。
- **重播**：`.is-burst` 由 `bindBrandLogo()` 在 760ms（最长动画 530ms + 延迟 105ms + 余量）后摘掉；下次松开先摘类、`void offsetWidth` 强制一次样式计算再挂回，连点每次都从头播。

**规则 / 决策**：

- **熄灭必须硬切**：用 `steps(1, end)` 而不是 `ease`——缓慢淡出读作「呼吸」，像素 CRT 的灯管坏了就是「啪」地断一下。
- **按下深度只给 10%**：18px 像素字再缩就糊了；10% + 1px 下移 + 去辉光已经足够读作「按进屏幕」。
- **浅色档的「暗淡」往暗混，不往白混**：浅底上把字混向 `--panel`（白）会淡到看不见；改混 `--text`，并按更具体的选择器显式 `text-shadow: none`——否则后出现的浅色辉光规则会把按下的摘除覆盖回去（无头浏览器实测发现的）。
- **不用 `lostpointercapture` 当收尾**：它可能在「没有 pointerup」的情况下被释放（合成事件 / 某些 WebView 时序），实测会把按下态提前取消、星屑不播；收尾只认 `pointerup` / `pointercancel`，没捕获时用 `pointerleave` 兜底。
- **星屑不参与布局**：绝对定位 + `pointer-events: none` + 父级 `overflow: visible`，飞出盒外也不推挤 rail；不放在斜切节点内，星形与角度不受 `skewX` 影响。

##### V1.50 字标动效改为自动循环 + 射线不交叉 / 星线分离 + 整体提亮

V1.49 把动效挂在了鼠标按下 / 松开上；这一版改成**固定节奏自动播放**（字标是装饰，不响应点击），并解决星屑构图的两个问题：射线交叉、星与线叠在一起。

- **自动循环**：`startBrandLogoLoop()` 在进主窗口 1.5s 后按下第一下，之后每 **6s** 一拍——`.is-pressed` 保持 240ms → 摘类并播放 `.is-burst`（760ms 后摘掉）→ 余下时间静止。不再注册 `pointerdown/up`；窗口回到前台时清掉 `is-pressed` / `is-burst`，避免最小化期间定时器节流把字标卡在暗色。
- **射线不再交叉**：三根射线原来各有 0~2px 的 `left/top` 偏移，视觉上会互相穿插；改成 `left/top: 0` + `transform-origin: 0 50%` 的**同一个原点**，只靠 `-20° / -50° / -80°` 扇开，除原点外不可能相交；长度收到 6~7px。
- **星与线、星与星分离**：射线最长 7px × `scaleX(1.2)` = 8.4px；三颗星的起点放在半径 10.5~16px 的**三个扇区中间**（-35° / -65° / -2°），一开始就在射线扇面之外，整段动画不会压线。三颗星尺寸 4.5 / 5 / 3.5px、最右缘 63.5px、最高点 y≈37px，仍在 64px 宽的 rail 内。

- **降级**：`prefers-reduced-motion: reduce` 时 `startBrandLogoLoop()` 直接用 `matchMedia` 判定后不启动，字标完全静止（CSS 的微闪 / 星屑 / 位移也停）。

**规则 / 决策**：

- **字标是装饰，不挂交互**：自动节奏比「用户碰巧点到 logo」更可靠，也不会让一个展示元素看起来像按钮；`user-select: none` 保留，拖窗口时不会选到字。

##### V1.53 触发角（EXT-10：四角触发 / 命名 / 动作链，Windows）

- **模型**：`Settings.hot_corners` = 总开关 + 四角（`top_left` / `top_right` / `bottom_left` / `bottom_right`），每角 `enabled` / `name` / `actions`（复用 `Action`）。缺字段全关，老配置照常读；`experimental` 仍是总闸。四角各自可启用、命名、配动作链。
- **判定在钩子层、执行在壳层**：`kada-hook::hotcorner` 是平台无关的纯坐标状态机——触发区 `SIZE = 3px`，进入只上报一次、停留不重复、离开角点超过 `REARM_DISTANCE = 24px` 才重新武装；钩子回调里不建窗、不 IO、不执行动作。出口回调只开线程，壳层 `handle_hot_corner` 走 `fire` → `run_actions`（`ActionStep` / `RunRecord` / 链内注入锁 / 超时中止全部继承）；`fire` 在调用线程抓前台窗口给 `Action::Window` 用，`origin = None`。
- **多屏口径**：同一份四角配置应用到每台显示器的对应角；判定用屏幕物理坐标（显示器完整矩形，不按工作区裁掉任务栏）。壳层在定时器线程每 ~3 秒重取一次显示器几何并只在变化时推给钩子层，热插拔 / 改分辨率能跟上。
- **让路与不吞键**：全屏（复用 `foreground_fullscreen`）与 `gesture_exclude` / `exclude_apps` 命中的程序里整条不执行，与鼠标手势同口径；**不吞任何鼠标事件**（没有右键那样的回放）。
- **按需装钩子**：`config_needs_mouse_hook` 纳入「触发角启用」，但**不混进 `config_uses_mouse`**——后者兼着输入层环境诊断，混进去会让只用触发角的用户白收「鼠标键被接管」提示。
- **平台**：只有 Windows 接了 `WH_MOUSE_LL` 鼠标钩子；macOS / Linux `PlatformCaps.hot_corners = false`，配了触发角给一条平台 `Warn`（不拦保存），执行侧不静默。

##### V1.59 边缘滚动（EXT-11：四边触发 / 去重 / 多屏 / 与滚轮快捷键分流，Windows）

光标贴在屏幕四边时滚动滚轮，执行该边绑定的动作链。**不新建执行器**：命中后走 `fire` → `run_actions`，`ActionStep` / `RunRecord` / 链内注入锁 / 超时中止全部继承；触发时 `fire` 在前台抓窗口给 `Action::Window`，`origin = None`。仍归新功能总闸 `Settings.experimental` 管。

- **配置模型**：`Settings.wheel_edges` = `{ enabled, top/bottom/left/right: WheelEdge }`，`WheelEdge` = `{ enabled, name, actions }`；**缺字段 = 全关**，老配置照常读。总开关 + 至少一条边启用才生效；四边名字空则用方位名（上 / 下 / 左 / 右边缘）。`sanitize_config` 逐边校验动作、去名字空白；`merge` / 导入 / 同步存档随整份 `Settings` 走。
- **判定与去重**（`kada-hook::wheel_edge`，平台无关）：钩子回调里只做纯坐标状态判断，不建窗 / 不 IO / 不执行。贴边 `SIZE` = 3px；**一次停留只上报一次**（继续滚不重复）；离开超过 `REARM_DISTANCE` = 24px 才重新武装。移动事件只负责重新武装，触发靠滚轮事件；角上同时命中两条边时优先级 上 → 下 → 左 → 右。
- **与滚轮快捷键分流**：`swallow_mouse` 先走既有 `swallow_wheel`——这一格已被快捷键 / 改键接走并吞掉时，边缘滚动不再处理；没绑、条件不成立、未累积到一格才轮到边缘滚动。边缘滚动**不吞滚轮**（页面照常滚）：真正执行与否要看全屏 / 排除程序，钩子层拿不到这些信息，吞了会把该让路的滚动也吃掉。
- **多显示器与让路**：同一份四边配置应用到每台显示器的对应边，判定用**屏幕物理坐标**（完整显示器矩形，不裁任务栏）；显示器几何与触发角共用一份，壳层每 ~3 秒重取。全屏（`foreground_fullscreen`）/ `gesture_exclude` / `exclude_apps` 与手势同口径让路。鼠标钩子按需安装（`config_needs_mouse_hook` 含边缘滚动），但**不混进 `config_uses_mouse`**。
- **平台**：只有 Windows 接了鼠标钩子；macOS / Linux `PlatformCaps.wheel_edges = false`，配了给一条平台 `Warn`（不拦保存、执行侧不静默），配置保留但不触发。

**规则 / 决策**：

- **不吞滚轮是刻意的**：全屏与排除程序只能在壳层判，钩子层若先吞，退出全屏 / 排除程序里的滚动也会一起丢；边缘滚动只旁听，动作执行与否由壳层决定。代价是贴边滚动时页面也会滚——比「该让路却吞掉」可接受。
- **滚轮快捷键优先**：一格滚轮只该有一个主人。既有 `swallow_wheel` 命中即返回，边缘滚动只在它放行时才有机会。
- **停留去重放在 `ACTIVE` 单值里**：与触发角同一套状态机口径（进区上报一次 / 离开 `REARM_DISTANCE` 才清），不引入定时器或时间窗。
- **共用显示器几何**：触发角与边缘滚动都要每台显示器的物理矩形，合并在同一个推送块里，避免两条线程各自枚举显示器。
- **平台能力走软冲突**：macOS / Linux 没接鼠标钩子，`PlatformCaps.wheel_edges = false` 给平台 Warn，配置保留、执行侧不静默。
