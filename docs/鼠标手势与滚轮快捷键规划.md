# 鼠标手势与滚轮快捷键规划

> **定位**：把 MouseInc 那一类「鼠标手势 / 滚轮快捷键」能力并入 Kada 的**可行性 + 分期方案**。
> **不是**需求规格（规格与规划编号以 `docs/需求设计说明书.md` §7 为准，本文档对应 **7.2-MG**，第一期已落地为 **7.1-MG**），也**不是**实现历史（那在 `docs/变更归档.md`）。
> **关联**：本体试验台 `kada-prime/`（独立 crate，自带 `[workspace]`，不进 Kada workspace）→ 详见 §4 与 `kada-prime/README.md`。

> **状态（2026-10-22）**：**V1 已并入 Kada**（7.1-MG）——手势采集（**仅 Windows**）+ 方向串识别 + 未命中回放右键；入口在「**快捷键**」页的「**鼠标操作**」分类（与快捷键 / 改键 / 文本扩展并列，第四类），设置页「**实验功能**」卡片放**新功能总闸**（`Settings.experimental`，**默认关**；关掉 → 这一类不出现、行为不生效、配置保留）。**首次真机尝试暴露并已修一处采集缺陷**（轨迹出口被取走 → 第一次右键之后手势再不触发、且右键被吞不回放，见 `变更归档.md` V1.29），并补了两处可见反馈（总闸关着但已配手势 → 列表栏气泡；没匹配上 → 报出方向串的气泡）。**V1 余项已落地四项**：手势 `when` 条件门控（前台应用 / 窗口标题 / 设备；条件不成立落到下一条）、**排除程序** `Settings.gesture_exclude`（设置页「实验功能」一行一个，命中就整条不接管）、**全屏程序自动暂停**（前台窗口占满显示器且非最大化时不接管）、**手势进卡带**（`PickKind::Gesture`，市场预览也认）。**未做**：滚轮快捷键、macOS / Linux 接线、任意形状模板、轨迹浮层（余项清单见 `需求设计说明书.md` §7.2-MG）。**真手势尚未真人复跑**——见 `人工验证清单.md` §40 / §41。**正式开发完成（余项清空 + 真机验收通过）之前不对外发布 release**：不打 tag、不发版、不推更新源。

## 1. 结论摘要

| 问题 | 结论 |
|---|---|
| 能不能做 | **能**。Windows 侧事件现成（`WH_MOUSE_LL` 本来就在装），macOS 缺两个事件掩码，Linux 已有 `BTN_RIGHT` + `REL_X/Y` |
| 代价多大 | **体积几乎为零**（实测：exe +60~120 KB、安装包 +30~80 KB，<1%）；**真正的代价是行为风险**（全局抢右键） |
| 与 MouseInc 能否互通 | **不能**。配置格式、手势表示、动作集、失败行为四层都对不上（§10） |
| 建议 | 先在 `kada-prime/` 试验台把手感调对（已做，§4），再按 V1（§5）并入；V1 只做「方向串手势 + 滚轮键」，**不做任意形状模板** |
| 最大的未决项 | ① 失败时回放右键会不会干扰日常右键（默认 10 ms 延迟）② 没有「排除程序」时是否敢默认开启（§11） |

## 2. 竞品对照：MouseInc 有什么 / Kada 有什么 / 缺什么

### 2.1 MouseInc（闭源，仅 Windows）

配置在 `MouseInc.Settings`（Vue3 + 本地 WebSocket 整份 JSON），核心逻辑在闭源 `MouseInc.exe`，**算法不可抄，只能按行为重建**。

四类鼠标触发源：

| 触发源 | 机制 | 配置形态 |
|---|---|---|
| 右键拖拽手势 | 起点画轨迹，形状匹配原始点模板 | `Gestures[{Sign, Data:[x,y,…], Actions, StartDistance, Timeout, Sensitive, AddMode, RestoreEvent}]` |
| 右键按住 + 滚轮 | 虚拟手势 `WheelSwitchUp` / `WheelSwitchDown` | `MatchGlobal` / `MatchCustom` 的虚拟手势项 |
| 屏幕边缘 + 滚轮 | 每条边三组（上滚 / 下滚 / 按下） | `WheelEdge` |
| 屏幕四角 | 四角触发 | `HotCorner` |

动作是元组串：`["SendKeys","Ctrl+C"]` / `["Window","Minimize"]` / `["SendClick","middle"]` / `["MouseMove","start_x","start_y"]` / `["Execute",…]`；一条触发后多个动作按 100 ms 间隔顺序执行。另有 `MatchCustom`（按 exe 覆盖）、`Excludes`、`IgnoreFullScreen`。

### 2.2 Kada 现状

| 能力 | 状态 | 位置 |
|---|---|---|
| 鼠标侧键 / 中键作触发键 | **有**（`Key::MouseMiddle/MouseBack/MouseForward`） | `crates/kada-core/src/lib.rs`（`Key` 枚举） |
| 鼠标动作（移动 / 点击 / 滚轮） | **有**，但**全是相对值** | `Action::Mouse { MouseOp::{Move(dx,dy), Click, Scroll} }` |
| 鼠标操作录制 | **有**（`MouseRecorder`） | `crates/kada-hook/src/lib.rs`（`MouseRecord`） |
| 动作引擎（层 / 序列 / 和弦 / tap-hold / `when` / 并行 / 分组） | **远强于 MouseInc** | `src-tauri/src/engine.rs`、`crates/kada-actions/` |
| 透明浮窗基建（toast / hud / hints） | **有**（含「不可激活」铁律） | `src-tauri/src/lib.rs` |
| **右键 / 左键进键模型** | **无**（有意为之） | — |
| **滚轮作触发键** | **无** | — |
| **手势识别 / 轨迹浮层** | **无** | — |
| **边缘滚动 / 触发角** | **无** | — |
| **绝对坐标移动 / 全屏检测 / 排除列表** | **无** | — |

> Kada 现有规划里唯一的「鼠标手势」是 **7.2-㊻ 触摸板手势**（多指手势，与本文档的「鼠标拖拽手势」不是一回事，两条独立线）。

### 2.3 三平台事件可得性

| 平台 | 现状 | 要补什么 |
|---|---|---|
| Windows | `WH_MOUSE_LL` 本来就装（`config_uses_mouse` 为真时），**所有鼠标事件都看得到** | 只差状态机 |
| macOS | tap 掩码只订阅了 `RightMouseDown`（给录制用） | 补 `RightMouseDragged` / `RightMouseUp`（`crates/kada-hook/src/macos.rs` 的 `events_of_interest()`） |
| Linux | evdev 已抓真鼠标，`BTN_RIGHT` + `REL_X/REL_Y` 都有；触摸板**有意不抓** | 吞右键 = 不往 uinput 转发 `BTN_RIGHT`；抬起回放走 `simulate` |

## 3. 设计原则（并入 Kada 时必须遵守的既有铁律）

1. **吞键铁律**：被吞掉的键补不回来。「吞掉」只允许发生在「还在等下一个输入来凑齐」的窗口内；**没组成快捷键的按键必须按用户输入顺序原样回放**。手势 = 右键按下先吞，抬起后判定「命中 → 执行」或「未命中 → 回放一次完整右键（按下-抬起配对）」。
2. **注入防回环**：注入事件带 `INJECTED` / `LLMHF_INJECTED` 一律放行；回放与动作注入都不得再被自己的钩子吃掉。
3. **回调里不许做耗时操作**：钩子回调只留「收集点 / 判阈值 / 返回是否吞」；**识别与动作执行一律在壳层线程**（`std::thread::spawn`）。
4. **按需挂钩子**：`config_uses_mouse()`（`crates/kada-core/src/lib.rs:2687`）决定鼠标钩子装不装（`src-tauri/src/lib.rs:926` / `:4668`）。新增鼠标用途**必须同步这个判定**，否则静默失效。
   > 注意区分两种口径：`config_uses_mouse` 还被「输入层环境诊断」（§4.6）用来判断是否要提示厂商接管；手势只用右键，**不该**混进那个口径，否则会误报罗技 / G HUB 接管。**做法**：新增 `config_needs_mouse_hook = config_uses_mouse(cfg) || 有启用手势`，钩子装不装看它，诊断仍看 `config_uses_mouse`。
5. **浮窗不可激活**：轨迹层 / 结果层必须 `focusable(false)`（`WS_EX_NOACTIVATE`），否则会被判成前台切换而误触发 `ResetWatch` 复位。
6. **配置落盘铁律**：新增配置段走 `sanitize_config` / `merge_configs` / 外部监听 / 同步存档全链路（§9）。

## 4. 本体试验台 `kada-prime/`（已落地，用来定手感）

`kada-prime/` 是**独立 crate**（自带 `[workspace]`，不进 Kada workspace，不读写 Kada 配置），Windows 单平台 Rust + Win32，无 UI 框架、零新依赖（复用 `windows` 0.61 + `serde_json`）。

| 文件 | 行数 | 职责 |
|---|---|---|
| `src/main.rs` | 1102 | 运行时状态机接线、鼠标钩子、托盘菜单、轨迹浮层、配置读写、启动/退出 |
| `src/config.rs` | 224 | 配置模型 + 默认手势 + 原子写 + 缺失字段回落 |
| `src/gesture.rs` | 231 | 方向量化 / 归一化 / 匹配 + 状态机（纯逻辑，单测覆盖） |
| `src/actions.rs` | 230 | 迷你动作执行器（按键 / 启动 / 音量 / 通知 / 点击 / 滚轮 / 移动 / 输入文本 / 停顿） |

**已验证**

- `cargo test` **9 个单测全绿**（方向量化：直线 / 斜向 / 四段 DRUL / 抖动去噪 / 归一化接受 `UP`·箭头·`UPRIGHT`；状态机起手距离；组合键解析；配置缺失字段回落）。
- release 打包 + 启动成功：托盘图标、配置落盘（`dist/config.json`）、日志（`dist/kada-prime.log`）、钩子安装成功（启动日志在装钩子之后写出）。
- 体积实测：本体 exe **455,168 B**；同依赖空壳程序 **116,224 B** → **本体全部代码净成本 ≈ 339 KB**（独立软件口径，含托盘 / 浮层 / 动作执行等 Kada 已有基建）。

**未验证（必须真人补）**

- **端到端手势未跑通自动验证**：开发时输入桌面处于 `Screen-saver`，`GetCursorPos` 返回「拒绝访问」，脚本合成的手势进不来；因此「按住右键 → 画轨迹 → 命中 → 执行动作 → 未命中回放」这条链**只做过代码级验证（单测 + 钩子安装成功），没做过真手势验证**。
- 试验台为此留了自测开关：`KADA_PRIME_SELFTEST=1` 允许外部合成事件进入识别路径（我们自己注入的鼠标事件带 `dwExtraInfo` 标记，仍然被忽略，不会回环）。
- 托盘菜单、配置热加载、轨迹浮层绘制同样只做过「启动即成功」级别的验证。

**试验台能试的东西**：右键 8 方向手势（默认 8 条：U/D 音量、L/R 前进后退、DL 复制、DR 粘贴、UD 显示桌面、DRUL 记事本）、右键+滚轮切标签、屏幕边缘滚轮、触发角（默认关）、轨迹层、命中/未命中的结果提示、托盘开关（手势 / 滚轮 / 边缘 / 触发角 / 轨迹）。

## 5. 目标分级（建议并入 Kada 的口径）

### V1（建议本轮做，做完就是「MouseInc 的核心」）

| 能力 | 验收标准 |
|---|---|
| 右键拖拽手势（**方向串**表示，8 方向） | 画 `↓→` 触发复制；画 `DRUL` 触发「打开记事本」；方向串在轨迹层上实时可见 |
| 未命中回放右键 | 右键随便拖一下不匹配 → 右键菜单照常弹出（延迟 ≤ 30 ms） |
| 右手势不影响左键 / 其它键 | 左键、右键单击、滚轮、键盘全部照旧 |
| 命中后动作复用 Kada 现有引擎 | 动作链、层、`when`（含前台程序）、并行、记录与消息上报全部复用，不另造一套 |
| 配置全链路 | 保存 / 外部改动监听 / 导入导出 / 合并 / 同步存档 / 冲突提示 都不丢手势段 |
| 三平台可编译 + Windows 真人验收 | `cargo check -p kada`（两版）+ `cargo check -p kada-hook --target aarch64-apple-darwin --all-targets` + `cargo check -p kada-hook -p kada-actions --target x86_64-unknown-linux-gnu --all-targets`；Windows 真机按 `docs/人工验证清单.md` 新增节逐条跑 |

### V1.1（手感补丁，V1 稳定后）

- 模板匹配（任意形状：S / P / 圆圈）——**注意**：这才是 MouseInc 的真正形态，方向串只是退化近似。
- 轨迹浮层（原生 GDI 折线，或 Tauri 窗口 + canvas）。
- 灵敏度 / 起手距离 / 超时可在 UI 调。
- 手势「按程序」限定（复用 `when` 的前台应用条件）。

### V2（长尾）

- 右键+滚轮（`WheelSwitch`）、屏幕边缘滚轮、触发角。
- 排除列表 / 全屏程序自动暂停。
- 绝对坐标移动 `MouseMoveTo(x,y)`、手势起点变量、执行前激活手势起点窗口。
- 手势进卡带 / 分享（`PickKind::Gesture`）。

### 明确不做

- MouseInc 配置导入 / 转换器（格式四层都不一样，见 §10）。
- 截图 / OCR / 贴图 / 按键回显 / AltDrag / 剪贴板增强（MouseInc 独有，与本能力无关）。
- 键模型里加入右键 / 左键（会污染快捷键、改键、冲突检测、录入四条链路）。

## 6. 数据模型提案（`kada-core`）

```rust
// crates/kada-core/src/lib.rs —— Config 新增一段（serde(default)，旧配置照常加载）
pub struct Config {
    pub folders: Vec<Folder>,
    pub layers: Vec<Layer>,
    pub shortcuts: Vec<ShortcutItem>,
    pub remaps: Vec<Remap>,
    pub expansions: Vec<TextExpansion>,
    pub gestures: Vec<Gesture>,   // 新增
    pub settings: Settings,
}

pub struct Gesture {
    pub id: String,          // 稳定 id（合并 / 卡带去重靠它）
    pub name: String,
    pub pattern: String,     // 方向串："U" / "D" / "L" / "R" / "UR" / "DR" / "DL" / "UL" / "DRUL"
    pub enabled: bool,
    pub actions: Vec<Action>,// 复用现有 Action（文本 / 按键 / 鼠标 / 命令 / 脚本 / …）
    pub when: Option<When>,  // 复用现有触发侧条件（前台程序等）
}
```

`Settings` 新增：`gesture_start_distance`（默认 22 px）、`gesture_timeout_ms`（默认 1500）、`gesture_min_segment`（默认 16 px）、`gesture_trace`（画轨迹）。

**序列化约定**：`#[serde(default)]` + 缺失字段回落默认值 → 旧版 Kada 存过的配置在新版里能加载；反之**旧版 Kada 读到带 `gestures` 的配置会把它丢掉**（前向不兼容，属已知代价，文档写明）。

**方向串约定**（与试验台一致，便于把调好的手感直接搬过来）：

| 记法 | 含义 |
|---|---|
| `U` / `D` / `L` / `R` | 上 / 下 / 左 / 右 |
| `UR` / `DR` / `DL` / `UL` | 四个斜向 |
| `↑` `↓` `←` `→` `↗` `↘` `↙` `↖` | 箭头别名（加载时归一化） |
| `UP` / `DOWN` / `LEFT` / `RIGHT` / `UPRIGHT` … | MouseInc 风格单词（归一化后等价） |

## 7. 识别算法（纯函数，放 `kada-core`，可单测）

```
输入：轨迹点序列 (x, y)[]、起手距离、方向段长
输出：方向串 "DRUL"
```

1. **起手判定**：累计位移 > `start_distance` 才进入「正在画」；之前只吞不画。
2. **方向量化**：从锚点累积到 ≥ `min_segment` 的位移，取与屏幕坐标（y 向下）夹角 → 8 方向桶；相邻同向合并（`DDD` → `D`）。
3. **归一化**：见 §6；匹配时对配置串与识别串都归一化后比较。
4. **匹配**：**精确匹配**（不做前缀匹配，避免 `D` 与 `DR` 互相吃）。同 pattern 多条 → 冲突检测给 Warn，按配置顺序取第一条。
5. **抖动**：靠「段长阈值 + 同向合并」吸收，无需额外滤波。
6. **超时**：绘制途中静止超过 `timeout_ms` → 取消本次手势，抬起时按「未命中」处理（回放右键）。

> 试验台已把这套逻辑写成单测（6 条），可直接搬。

## 8. 三平台接线（`kada-hook`）

**统一形状**：`kada-hook` 暴露一个平台无关的「手势采集器」：

```
set_gesture_enabled(bool)   // 壳层按配置推送（独立于 config_uses_mouse）
set_stroke_sink(fn(Stroke)) // 松手时把轨迹交出去（识别在壳层做）
```

| 平台 | 接线 |
|---|---|
| Windows | `mouse_proc` 里处理 `WM_RBUTTONDOWN` / `WM_MOUSEMOVE` / `WM_RBUTTONUP`；`swallow_mouse` 的既有「按下-抬起配对吞键」语义可直接复用 |
| macOS | `events_of_interest()` 补 `RightMouseDragged` / `RightMouseUp`；CGEventTap 回调同样不许做耗时操作 |
| Linux | `BTN_RIGHT` + `REL_X/REL_Y`；吞右键 = 不转发给 uinput 虚拟设备；回放走 `simulate` |

**壳层（`src-tauri`）**：

- 定时器线程（`spawn_engine_ticker` 已有）比对配置 → 推 `set_gesture_enabled`。
- 收到 `Stroke` → 后台线程做识别（§7）→ 命中则走现有动作执行路径（复用 `fire` / 记录 / 消息上报）；未命中则走注入路径回放右键（`deliver`，提权窗口走伴随进程，§4.7）。
- **手势不进 `Engine::step`**：它不是键序列，绕进去会污染 tap-hold / 和弦 / 序列的状态机。

## 9. 配置全链路（并入时必须一起做的清单）

| 环节 | 位置 | 要做什么 |
|---|---|---|
| 清洗 | `sanitize_config`（`crates/kada-core/src/lib.rs:3100`） | 丢空 pattern、归一化、去重 id、校验 actions |
| 迁移 | `Config::migrate`（同文件 `:3013`） | 旧配置无需迁移（新增段有默认值） |
| 冲突检测 | `detect_conflicts`（同文件 `:2093`） | 同 pattern 且 `when` 相同 → Warn（`when` 参与指纹，与既有规则一致） |
| 合并（导入 merge） | `crates/kada-core/src/merge.rs` | 按 `id` 去重纳入，`MergeReport` 加手势计数；不造新冲突、设置保留本机 |
| 卡带 / 分享 | `crates/kada-core/src/snippet.rs` | V1 先**不进卡带**（须在文档写明）；V2 加 `PickKind::Gesture` |
| 示例配置 | `crates/kada-core/src/sample.rs` | 放**默认禁用**的示例手势（启用的示例会在用户机器上抢右键） |
| 外部改动监听 | `src-tauri/src/config_watch.rs` | 整份 JSON 指纹，自动覆盖；界面有未保存草稿仍要问用户 |
| 同步存档 | `settings.sync_dir` | 走既有 `push_sync`，新增写盘路径别漏 |
| 按需挂钩子 | `config_uses_mouse`（`:2687`） | 新增 `config_needs_mouse_hook`（§3.4） |

## 10. 与 MouseInc 的不兼容点（四层全不一样）

| 层 | MouseInc | Kada 计划 | 后果 |
|---|---|---|---|
| 配置格式 | PascalCase + 元组动作（`["SendKeys","Ctrl+C"]`），整份 JSON 走本地 WebSocket | camelCase + 类型化 `Action` 对象，Tauri IPC + 草稿 / 保存守卫 | **无法直接导入**，需要另写转换器（明确不做） |
| 手势表示 | 原始点模板（能画字母 / 圆圈） | V1 方向串；V1.1 才上模板 | V1 认不出 S / P，老用户「画了没反应」 |
| 失败行为 | 默认 `RestoreEvent:false` → 未识别**什么都不做** | 按吞键铁律：未识别**回放右键** | 同样画错一笔，MouseInc 无事发生，Kada 会弹菜单 |
| 触发范围 | 全局右键手势 + exe 覆盖 + `Excludes` | 复用 `when`（更强），但 V1 **没有排除列表** | 被排除的程序里右键拖拽照样被劫持 |
| 动作集 | 窗口 / 截图 / OCR / 贴图 / PostMessage / RegSet / 算法 / Explorer… | Kada 的 `Action` 子集 | 大部分 MouseInc 动作**没有一一对应**，迁移只能手工重配 |
| 鼠标移动 | 绝对坐标 + `start_x/start_y` 特殊值 | 只有相对 `Move(dx,dy)` | 录制的宏换分辨率会偏；V1 不补绝对坐标 |
| 执行窗口 | `SendKeys` 前会激活手势起点窗口 | 注入到当前前台窗口 | 正常场景一致；焦点在手势中途被抢时行为不同 |
| 滚轮语义 | `WheelSwitch` / 边缘滚动 / Alt+滚轮 是内建行为 | 走「滚轮当离散键」模型 | 不是同一种抽象，MouseInc 的「右键+滚轮切标签」V1 没有 |
| 平台 | Windows only | 三平台 | 窗口 / 注册表 / 截图类动作无跨平台等价物，只能按 `PlatformCaps` 标「本平台用不了」 |

**最痛的三个**：① 配置不能平移；② V1 的方向串表达不了字母形状；③ 失败回放策略与 MouseInc 相反（Kada 更符合「不吞用户输入」，但手感不同）。

## 11. 风险与已知天花板

| 风险 | 级别 | 说明 | 缓解 |
|---|---|---|---|
| **全局抢右键** | 高 | 右键拖拽在游戏 / CAD / 远程桌面 / 资源管理器（拖文件）里是正常操作；被吞后即使回放也只是「点击」，拖拽语义已丢 | 默认**不做排除列表**时建议默认关闭；V2 补排除列表 + 全屏自动暂停；托盘一键暂停 |
| **回放延迟** | 中 | 未命中时右键菜单晚 ~10~30 ms 出现 | 试验台已用 10 ms；可调；命中路径无延迟 |
| **右键单击也走吞→回放** | 中 | 每个右键都要走一遍判定 | 起手距离 + 只在「启用手势」时吞；`RestoreEvent` 式回放可配置 |
| **方向串手感** | 中 | 8 方向 + 段长阈值 ≠ 任意形状；抖动 / 弧线识别不到 | V1 接受；V1.1 上模板 |
| **macOS 事件掩码** | 中 | 需补 `RightMouseDragged` / `RightMouseUp`；tap 回调对耗时更敏感 | 识别在壳层线程（§3.3） |
| **Linux 只有相对位移** | 低 | 方向串只依赖位移 → 可用；绝对坐标 / 边缘 / 触发角在 Wayland 下做不了 | V2 的边缘 / 触发角在 Linux 明确受限 |
| **浮层抢前台** | 中 | 轨迹层若可激活会被判成前台切换 → 误触发 `ResetWatch` | `WS_EX_NOACTIVATE` + `WS_EX_TRANSPARENT`（§3.5） |
| **多显示器 / DPI** | 中 | 轨迹层跨虚拟屏坐标 + 缩放 | 进程声明 per-monitor DPI aware；坐标用物理像素 |
| **钩子被静默摘** | 低 | 与 Kada 现有看门狗同源 | 复用 `reinstall_count()` / 心跳（§4.1） |
| **与厂商软件并存** | 低 | Logi Options+ 等 divert 的是侧键，不影响右键 | 无需处理；诊断口径别混（§3.4） |

## 14. 验收标准（并入后要进 `docs/人工验证清单.md`）

1. 按住右键画 `↓→` → 复制动作触发，轨迹层显示方向串。
2. 按住右键画一个**未配置**的方向 → 右键菜单照常弹出（不得消失、不得变成别的动作）。
3. 右键单击（不动）→ 菜单正常弹出，延迟 ≤ 30 ms。
4. 左手拖拽文件（Explorer）→ 不被劫持（前提：未配置与之匹配的方向；否则记为「已知限制」）。
5. 手势执行中右键**不残留**（不出现「一直按着右键」的状态）。
6. 关闭「启用手势」→ 右键完全回到系统行为；删除全部手势 → 鼠标钩子按需卸下（若无其它鼠标用途）。
7. 钩子重装 / 切前台 / 锁屏唤醒后 → 手势状态复位，不残留半截轨迹。
8. 注入事件（`Action::Click` / 回放右键）不触发手势。
9. 配置改动（外部 / 导入 / 合并）后手势不丢、id 不冲突。
10. macOS / Linux：至少编译通过 + 登记为「待真机」。

## 15. 待决策（拍板后再开工）

1. **V1 是否接受「方向串」而不是任意形状模板？** 建议接受（工期差 3~5 天，且手感可调）。**但**老 MouseInc 用户的肌肉记忆是字母形状 → 若目标用户是 MouseInc 迁移者，模板匹配要提到 V1。
2. **未命中是否回放右键？** 建议回放（符合吞键铁律、不吞用户输入）；代价是「画错一笔会弹菜单」，与 MouseInc 默认相反。也可以做成配置项（`gesture_restore_event`）。
3. **是否默认开启？** 无排除列表时建议**默认关闭 + UI 里显式提示风险**；或默认开启但把起手距离调大（如 40 px）。
4. **右键单击也走「吞→回放」？** 影响每个右键的延迟；备选是「按下先不吞，位移超阈值才吞」（代价：菜单已经弹了就没法撤回，**不可行**）→ 只能先吞后回放。
5. **手势是否参与层 / 卡带 / 同步？** V1 建议「不参与层（手势是全局触发源），卡带 V1 不含，同步走整份 JSON 自然包含」。
