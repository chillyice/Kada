## 2. 铁律（拆分的操作规范，违反就是返工）

1. **只搬不改**：一次提交里只允许「文件移动 + `mod` / `use` / `pub` 调整」。看到顺手能改的代码 → 记一笔，拆完单独提交。
2. **一次只拆一个巨型文件**，拆完跑完 §7 全部绿灯、提交、再动下一个。
3. **拆前先统一格式**（Q-01）。否则「格式化 diff」和「搬移 diff」混在同一次提交里，评审时根本看不出有没有改逻辑。
4. **对下游透明优先**：`kada-core` 走 `pub use` 重导出，`kada-hook` / `kada-actions` / `src-tauri` **一行都不用改**；一旦发现要改下游，说明模块边界切错了，停下来重切。
5. **每搬完一个文件，同批更新两处文档**：`docs/代码地图.md` 的「文件」列（令牌列不用改，但要确认令牌跟着文件走了）、`docs/README.md` 的目录树。`check-docs` 会拿代码地图的文件列去 grep 令牌，不同步必红。
6. **测试先整体搬、不边拆边分**：`kada-core` 那 4,464 行测试先原样搬进 crates/kada-core/src/tests.rs，不要同时重写测试——那会让「搬移」和「改测试」两件事纠缠在一起。
7. **不做的事**：不引入路径别名（`tsconfig` paths + vite alias 双端都要配，收益不值）、不趁机抽「万能 helpers」、不动 i18n key、不改 `docs/需求设计说明书.md` 的字段定义。
8. **本文件里新路径写在代码块里、不加反引号**：`check-docs` 会校验反引号里的 `docs/` / `ui/` / `crates/` 路径必须真实存在；文件真建出来之后再加反引号。

### Q-01 细节（有争议，先读再动）

**为什么要先做**：现在 `core.autocrlf=true` + 没有 `.gitattributes`，工作区是 CRLF、索引是 LF、CI（Linux）是 LF。后果是 `cargo fmt --check` 在本地永远红、在 CI 永远绿，等于没闸门；同时任何格式化都会把整文件标成改动。

**三步走**：

1. 加 `.gitattributes`：`* text=auto eol=lf`，然后 `git add --renormalize .`（此时应该**没有**内容差异，因为索引本来就是 LF）。
2. `cargo fmt --all` 一次提交，**只格式化不改逻辑**。commit message 建议 `style: cargo fmt 全仓一次性格式化（不改逻辑）`。
3. 加 `.git-blame-ignore-revs`（写上第 2 步的 sha），并在 `git config blame.ignoreRevsFile .git-blame-ignore-revs` 说明里讲清怎么用。

**代价（要认）**：约 13,800 行差异、一次大提交、`git blame` 在这一行 sha 上会「断代」（靠 ignore-revs 缓解）。

**如果不想付这个代价**：跳过 Q-01，**不做全仓 fmt**，CI 也就不加 fmt 闸门；Q-02 的 clippy 照做（clippy 不要求代码已格式化）。此时 `.gitattributes` 仍然建议加（它解决的是行尾不一致，与格式化无关）。

**已落地（2026-11-06，V2.17）**：`* text=auto eol=lf` + 二进制 / 锁文件规则已加；工作区用 `git rm --cached -r . && git reset --hard` 重刷成 LF；格式化提交 `bfa9207`（32 文件、6,418+ / 1,850-）已写进 `.git-blame-ignore-revs`；`ci.yml` 加 `Rust formatting` 步骤。注意：**rustfmt 会改 token**（给闭包补块、补尾逗号），验证靠编译 + 测试，别用「去空白后文本相等」当无损证明。

**下一步**：Q-02（clippy 清零 + CI 闸门）。

### Q-06 细节（先定性，再动手）

`src-tauri/src/lib.rs` 里 6 处 `#[allow(dead_code)]` 不是同一类东西：

| 位置 | 是什么 | 结论 |
|---|---|---|
| `double_copy_hit` | 双击 Ctrl+C 判定，5 处引用**全在测试里** | 真测试专用 → 搬进 `#[cfg(test)]` |
| `MenuNodeView` + `menu_node_views` | 复制快捷菜单的展示树（EXT-13 已下线） | 挂在死链上 |
| `spawn_clipboard_menu` → `menu_clipboard_has_text` / `ensure_clipboard_menu` | 触发与建窗 | 挂在死链上 |

死链那几条的源码里有 `// ponytail: 复制快捷菜单已下线（EXT-13），这些建窗 / 判定函数留着给旧配置回看，先不删。`——**这是刻意保留，不是技术债**。所以 Q-06 有两个正当出口，二选一，不要两边都占：

- **留**：保持现状，把 `#[allow(dead_code)]` 换成注释里写清「等旧配置彻底不可能回来再删」。**别为了消警告把它们挪进 `cfg(test)`**——那会同时废掉「给旧配置回看」的原始意图。
- **删**：确认 `spawn_clipboard_menu` 全仓无调用者（当前只有定义）、`Settings.clipboard_menu` 也不再被任何界面读到，然后整链删除（约 120 行），连同 `MenuEntry` 相关分支一起判。

**顺带一条规矩**：仓库里带 `ponytail:` 前缀的 `#[allow(dead_code)]` 都是刻意留的尾巴（当前 2 处），review 时别当警告清掉。

### 坑（这些人踩过才知道）

- **ESM 循环依赖**：模块顶层互相 import 对方的 `const` 会 TDZ 崩（`Cannot access X before initialization`）。规矩：可变状态一律进 `state.ts` 的一个对象里；模块之间只通过函数调用交互，**不要**在模块顶层读别的模块的 `const`。
- 段名有**两个**「拖拽排序/移动」（一处是列表、一处是编辑器画布），合并前先读上下文，别合并错。
- 每个视图模块对外只导出 `renderXxx()` / `bindXxx()` 这类入口，**不要**为了「方便」把内部函数导出成公共 API——导出的越多，下一刀越难砍。
- `style.css` 里的类名是全局的，拆分不影响样式；但**别顺手改类名**。
- 拆完必须重跑 `node scripts/check-i18n.mjs`：`check-i18n` 扫的是 `ui/src` 下所有文件，新增文件里的中文一样要被 `tr()` 包住。

### 坑

- **可见性**：类型保持 `pub`（`pub use` 要重导出它）；只在 crate 内用、或只被测试用的函数降成 `pub(crate)`。`pub use` 一个 `pub(crate)` 项会直接编译报错（E0365），编译器会告诉你哪个漏了。
- **`tests.rs` 的可见性**：`#[cfg(test)] mod tests;` 是 crate root 的子模块，只能看见各模块的 `pub` / `pub(crate)` 项。测试里凡是直接调私有 helper 的，把那个 helper 提成 `pub(crate)`——这是刻意的（crate 内可见、不对外导出）。
- **常量与 default 函数**跟着第一个使用它的类型走，别单独建 `consts.rs`。
- **`#[cfg(feature = "automation")]`** 门控要跟着被门控的类型一起搬（`Action::If` / `Parallel` / `Condition` / `Script` / `Vars` 相关），漏一个就是 `--no-default-features` 编译失败——CI 的 clippy / test 都按默认 feature 跑，**基础版只能靠 §7 那条 `cargo check -p kada --no-default-features` 拦**。
- 测试里有 `#[cfg(feature = "automation")]` 的辅助函数（`linux_caps()` 之类），搬家后要保持门控，否则基础版编译失败。

## 6. 阶段 3：拆 `src-tauri/src/lib.rs`（8,303 行，生产 4,780）

**最后做**：它同时碰 Tauri 宏、多线程、建窗，最容易和别的会话冲突；而且前两阶段做完之后，它已经是「最难读但最少改」的那个。

### 目标骨架

```
src-tauri/src/lib.rs           run() / setup / generate_handler![...] / 单实例 / 全局状态
src-tauri/src/commands/mod.rs 60 个 #[tauri::command] 按域再分：
                                config.rs   get_config / set_config / get_conflicts / 导入导出 / 卡带
                                record.rs   start_record / stop_*_record / start_mouse_record …
                                results.rs  run_entry / abort_actions / get_run_records / get_command_results …
                                devices.rs  input_devices / input_env_report / running_tools / hidpp_* / elevated_*
                                windows.rs  *_ready / get_*_payload / hints_* / tray_menu_exec / clipboard_menu_exec
src-tauri/src/windows.rs      五个透明浮窗的建窗与定位（toast / hud / hints / clipboard-menu / tray-menu）
src-tauri/src/tray.rs         托盘图标与菜单
src-tauri/src/engine_host.rs  钩子安装/卸载、看门狗、定时器线程、事件泵、Engine 接线
src-tauri/src/results.rs      RunRecord / ActionStep / 消息中心 / 推送
src-tauri/src/net.rs          http_client / http_get_text / fetch_snippet*
src-tauri/src/tests.rs        cfg(test) 整块（第 4,780 行起到文件尾）
```

### 切法

| ID | 步骤 | 搬什么 | 状态 |
|----|------|------|------|
| T-01 | 测试整块搬家 | `mod tests`（第 4,780 行到文件尾，3,523 行）→ `src/tests.rs` | ⬜ |
| T-02 | 抽无状态叶子 | `net.rs`（`http_client` / `http_get_text`）、`results.rs`（执行记录与消息中心那套纯数据结构与 upsert） | ⬜ |
| T-03 | 抽浮窗与托盘 | `windows.rs`（`ensure_toast` / `ensure_hud` / `ensure_hints` / `ensure_prompt` / 两个菜单窗 + 定位计算）、`tray.rs` | ⬜ |
| T-04 | 抽命令层 | 60 个 `#[tauri::command]` 按上表分进 `commands/`；每搬一个，`generate_handler!` 里的路径改成 `commands::xxx`（**漏一个就是运行时「命令未注册」**） | ⬜ |
| T-05 | 收尾 | `engine_host.rs` 接线；`lib.rs` 只剩 `run()` 与注册表 | ⬜ |

### 坑

- **`generate_handler!` 是唯一真相**：搬命令时宏列表要同步改，编译能过但**运行时才炸**（`invoke` 报 `command not found`）。搬完必须真机启动应用、把主界面每个页签点一遍（至少跑完 §7 再加上「命令全注册」这条人工确认）。
- `#[tauri::command]` 函数必须是 `pub(crate)`（宏生成的 `__cmd__*` 要在模块内可见）。
- 建窗代码里有大量 `#[cfg(desktop)]` / 平台分支，**整段搬，别顺手改 `#[cfg]`**。
- 钩子回调里**不许有带等待的 IPC**（架构设计 §3.6 的铁律），搬 `engine_host.rs` 时最容易「顺手加个 `emit` 前先等锁」——不许。
- `docs/代码地图.md` 里指向 `src-tauri/src/lib.rs` 的行特别多（命令、浮窗、执行记录、托盘…），T-04 是**一次大改文档**，别拆成多次小改把自己绕晕。

## 8. 阶段 4：体积与规则优化（能砍的不多，逐条给结论）

| ID | 事项 | 结论 | 理由 |
|----|------|------|------|
| O-01 | 删 `Win32_System_LibraryLoader` | ✅ 做（并入 Q-05） | 零引用 |
| O-02 | 6 处 `#[allow(dead_code)]` | ➖ 转 Q-06 定性 | 不是同一类问题：1 处是测试专用，其余挂在「已下线的复制快捷菜单」死链上且有 `ponytail:` 注释说明是刻意保留——**别为了消警告一刀切挪进 `cfg(test)`** |
| O-03 | `noUncheckedIndexedAccess` | ⬜ 可选 | 实测 **95 处**；这项能真挡住「数组越界拿到 undefined」，但 95 处得逐条判断。建议 U-01~U-04 拆完、文件变小之后再开，按文件逐个加注 |
| O-04 | `exactOptionalPropertyTypes` | ✅ 便宜，做 | 实测仅 **3 处** |
| O-05 | CRT 像素字体 595 KB | ➖ **保留** | 中英任意文本都要覆盖，**subset 砍不动**；且 `@font-face` 只在 `data-theme="crt"` 真正用到时才下载，非 CRT 用户运行时不付这个成本——它的代价只是安装包大 595 KB |
| O-06 | `mock.ts` 改懒加载 | ➖ **不做** | ①演示模式是写进 `docs/需求设计说明书.md` 的验收手段（§6.8），删了/延迟了会毁掉「纯浏览器预览」这条路；②`file://` 下动态 `import()` 会被浏览器拦，`ui/dist/index.html` 双击打不开；③它只占 30 KB 源码（约 9 KB gzip），省下来不值这个风险 |
| O-07 | 清「未使用」CSS 类 | ➖ 不做 | 粗测 42 个「未命中」几乎全是 `kind-${x}` / `st-${x}` / `type-${x}` 动态拼接的假阳性，真死规则很少 |
| O-08 | 重复依赖（base64 0.22/0.23 等） | ➖ 不做 | 全来自 tauri 自己的依赖树，动不了 |
| O-09 | `panic = "abort"` | ➖ **不采纳** | 省 1~2 MB，但任一线程 panic 会直接杀进程（现在是只死那个线程）。对「钩子线程 + 自愈看门狗」这套可靠性设计是倒退 |
| O-10 | 换 HTTPS 栈（reqwest + rustls + ring → 更小的替代） | ➖ 不采纳 | 省 2~3 MB，但要重做整个更新链路（含签名校验），风险收益不划算 |
| O-11 | 删测试换体积 | ➖ 不做 | 测试不进发布物，删了省 0 字节，却拆掉改键引擎唯一的护栏 |

## 9. 风险与回滚

| 风险 | 触发信号 | 对策 |
|---|---|---|
| 拆错边界导致下游要改 | C-02/C-03 时 `kada-hook` 报错 | 停下来重切，**不要**为了迁就模块边界去改下游 |
| 循环依赖 | U-03 之后启动报 `Cannot access ... before initialization` | 状态进 `state.ts`，模块间只用函数调用 |
| 命令没注册 | T-04 之后某个按钮点了没反应、控制台 `command not found` | `generate_handler!` 与 `commands/` 逐个人工核对 |
| 文档令牌失效 | `check-docs` 报 `[map-token]` | 这一条就是设计出来拦这个的，照着报错改代码地图 |
| 一次提交太大没法评审 | diff 超过 ~1,500 行 | 说明混了多步；拆小重来 |
| 与其他会话冲突 | `git status` 出现非自己改的文件 | 让对方先归档；拆分类提交尤其不能并行 |

**回滚**：拆分全程是「只搬不改」，任何一个步骤挂了直接 `git reset --hard <上一步绿灯的 sha>`，损失只有搬运时间。**这也是为什么每步必须单独提交。**
