# 安卓版规划（Android 平台）

> **本文是跨会话进度账本**：开工前读 §6「当前阶段」与 §11「进度日志」，收尾回来追加一条。
> 结论先行：**这不是把桌面版移植到 Android**，而是「一个 APK、三档能力、按设备与授权运行时切换」。
> 三档能做什么、为什么 `remaps` 在无 root 档整块失效，见 §2 / §3；先证伪什么见 §7。

## 0. 结论摘要

- **三条支柱在 Android 上一条都不存在原样**：全局收键、全局注入、常驻浮窗（§1）。
- **无 root 档做不了「键 → 键」，只能做「键 → 动作」**：`Config.remaps` 整块不成立，`Config.shortcuts` 保留（§3）。
- 补偿手段是**语义动作映射表**（复制 / 粘贴 / 最近任务 / 返回 / 截图……），能覆盖桌面常用组合键的六成（§3.2）。
- **能整块复用的**：`kada-core`（配置模型 / 键模型 / 判重 / 冲突 / 卡带）、`Engine` 状态机、前端 15.7k 行编辑逻辑、卡带格式（§5）。
- **手机档不做输入法**：文本扩展先用「面板点一下 → 粘贴」，读屏方案只做默认关的开关（§4）。
- 单人 **约 4 个月**到三档齐全；S1（平板 MVP）结束即可发布（§6）。

## 1. 为什么不能移植：三处断裂

| Kada 的能力 | 桌面三平台靠什么 | Android 上是什么 |
|---|---|---|
| 全局收键 | `WH_KEYBOARD_LL` / `CGEventTap` / evdev grab | 没有。只有无障碍服务的 key-event 过滤（**仅硬件键**） |
| 吞键 | 回调返回非 0 / 不转发 | 无障碍可吞硬件键；**软键盘输入根本不产生 KeyEvent** |
| 注入 | `SendInput` / `CGEventPost` / uinput | 没有全局注入（`INJECT_EVENTS` 是系统签名权限） |
| 前台应用 / 窗口 | 各平台 API | `UsageStats`（特殊权限）或无障碍事件；**窗口句柄 / 标题不存在** |
| 托盘 | `tray-icon` | 前台通知 / 快捷设置磁贴 |
| 浮窗 | 六个独立窗口 + 透明 + `focusable(false)` | `TYPE_APPLICATION_OVERLAY` + 悬浮窗特殊权限；**Tauri mobile 不支持多窗口** |
| 常驻 | 开机自启 + 托盘 | 前台服务 + 常驻通知 + 厂商杀后台 |
| 命令 / 脚本 | `Command` | 没有 cmd / PowerShell；`sh` 可用但 W^X 限制 |
| 鼠标 / 滚轮 / 手势 | 鼠标钩子 | **拿不到全局 motion / 滚轮事件**（无障碍不给，浮层拦了就把 app 断了） |

**断裂分三层，逐层变难：**

1. **没有低层钩子等价物。** 桌面版「任意 app 里按键都归我管」这件事，Android 没有对等 API。
2. **硬件键先投递给焦点 app。** 第三方只能旁观或过滤，不能改写后转交——这是「改键」需要注入的根本原因。
3. **软键盘打字走 `InputConnection`，不产生 KeyEvent。** 任何「钩子」都看不到触屏输入，只有输入法能看到。

第 3 层决定了本文最硬的一条产品边界：**无 root 档的手机上没有「改键」，只有「点一下执行」**。

## 2. 三档能力矩阵

一个 APK，运行时探测决定档位（`/dev/uinput` 可写 + `su` 可用 → root 档；有物理键盘 → 平板档；否则手机档）。

| | 档 1 · 手机（无 root） | 档 2 · 平板 / 外接键盘（无 root） | 档 3 · root |
|---|---|---|---|
| 输入后端 | 无障碍（音量键）+ 悬浮球 / 磁贴 / 通知 | 无障碍硬件键全量 | `/dev/input` grab（复用 Linux 后端） |
| 触发形式 | 点按、音量键 | 快捷键、序列、和弦、层、tap-hold | 同左 + 鼠标键、滚轮、手势、角动作 |
| `remaps`（键→键） | ✗ | ✗ | ✓ 全形态 |
| `shortcuts`（触发→动作） | ✓ | ✓ | ✓ |
| 注入 | 节点语义动作 / 粘贴 / 手势 | 同左 | uinput 全保真（`Keys` / `Mouse` / `Text`） |
| 文本落地 | 输入框内 `setText` / 粘贴 | 同左 | 逐字注入 |
| 命令 / 脚本 | `sh -c` + Rhai（可留） | 同左 | 同左 |
| 鼠标 / 滚轮 / 手势 | ✗ | ✗（外接鼠标的 MotionEvent 只到 app） | ✓ |
| 常驻 | 前台服务 + 常驻通知 | 同左 | 同左 |

**手机档的物理触发源只有音量键**（无障碍能收到并吞掉，也可用「音量上 + 音量下」组合）。其余靠悬浮球、磁贴、常驻通知——这也是各类宏 app 的实际做法。

## 3. 核心边界：`remaps` 死，`shortcuts` 活

### 3.1 为什么

- `Config.remaps`（`crates/kada-core/src/config.rs`）的语义是「把 `from` 换成 `to` 这个**键**」，落地必须注入。无 root 档没有注入 → **整块不成立**，不是降级，是失去意义。
- `Config.shortcuts`（触发 → `Action`）落地是**动作**（打开应用 / 插文本 / 发请求 / 跑脚本），不依赖注入 → 保留。
- 这条边界要写进 UI：配置页在无 root 档直接标注「本机不支持改键，只能用快捷键与动作」，别让用户配完才发现不生效。

### 3.2 语义动作映射表（无 root 档的「改键」替身）

桌面上靠注入实现的常用组合键，在无障碍里有语义等价 API。把它们做成内置动作，就是无 root 档的改键：

| 桌面组合键 | Android 等价 | API |
|---|---|---|
| Ctrl+C / V / X / A | 复制 / 粘贴 / 剪切 / 全选 | `ACTION_COPY` / `ACTION_PASTE` / `ACTION_CUT` / `ACTION_SELECT_ALL` |
| Enter | 提交 | `ACTION_IME_ENTER`（API 30+） |
| PgUp / PgDn | 上 / 下翻页 | `ACTION_SCROLL_BACKWARD` / `FORWARD` |
| Alt+Tab | 最近任务 | `GLOBAL_ACTION_RECENTS` |
| Win | 主屏 | `GLOBAL_ACTION_HOME` |
| Esc / 返回 | 返回 | `GLOBAL_ACTION_BACK` |
| Win+N | 通知栏 | `GLOBAL_ACTION_NOTIFICATIONS` |
| Win+A | 控制中心 | `GLOBAL_ACTION_QUICK_SETTINGS` |
| — | 锁屏 | `GLOBAL_ACTION_LOCK_SCREEN`（API 28+） |
| — | 截图 | `GLOBAL_ACTION_TAKE_SCREENSHOT`（API 30+） |

> 这些 API 的可用性**必须真机逐条验**（尤其厂商 ROM 对 `GLOBAL_ACTION_*` 的裁剪），验收项见 §7 的 S0-5。

### 3.3 对配置与卡带的影响

- 桌面卡带导进安卓会带 `Command` / `Keys` / `Mouse`：逐条标灰 + 执行时跳过（复用 `Action::Disabled` 那条「跳过、不占执行记录」的路径），比整份 Warn 好用。
- 建议卡带加一个**可选 `platforms` 提示字段**（只做展示与导入提示，不参与解析）——否则安卓用户第一次逛市场就是一片灰。

## 4. 手机档的文本扩展：三个选项

| 方案 | 能做到 | 代价 |
|---|---|---|
| ① 自建输入法 | 管所有打字 | 用户要换掉搜狗 / Gboard，还得自带拼音引擎——**缩水版不该背** |
| ② 无障碍读输入框 + `setText` 替换 | 不用换输入法也有热串 | 读屏权限用于自动化，**Play 审核风险最高**；组字中会误判；只有暴露文本的输入框有效 |
| ③ 面板点条目 → 粘贴到当前输入框 | 模板 / 片段 / 地址，覆盖 90% 场景 | 需手动点，不是「打字触发」 |

**定案：③ 先做，② 做成默认关闭的开关**并在界面写明风险。手机档零审核雷区。

## 5. 架构落点（文件级）

### 5.1 `crates/kada-core`

- **`PlatformCaps` 从编译期常量变运行时探测**（`crates/kada-core/src/conflicts.rs`）：能力不再是「平台是什么」，而是「当前档位 + 授权状态 + 有没有物理键盘」。这是 core 唯一的结构性改动。
- 给 `Action` 加 `capability()` 映射，而不是继续往 `PlatformCaps` 里堆键集合——卡带逐条标灰需要**动作级**判定。
- `Key` 加一张 Android `KEYCODE_*` 映射表（`crates/kada-core/src/keys.rs`），`Key::ALL` 不动。
- 配置 / 合并 / 卡带 / 判重**零改动**——这是安卓版最大的现成资产。

### 5.2 `crates/kada-hook`

- **先做一次重构**：把 `crates/kada-hook/src/linux.rs` 的 evdev 部分抽成 `evdev_common`（设备枚举 / grab / uinput 建虚拟设备 / 键码表），Linux 与 Android-root 共用。不抽则 1.8k 行要复制，之后两边各自修 bug。
- 新增 `android.rs`（无障碍后端）：事件从 Kotlin `AccessibilityService` 经 JNI / mpsc 进来，`F: FnMut(KeyEvent) -> Action` 的契约与三平台一致。
- `arboard` 无 Android 后端：剪贴板改走 Tauri clipboard 插件（或 Kotlin 侧）。
- `gesture.rs` / `hotcorner.rs` / `trackpad.rs` 的平台无关状态机可复用，但 Android 上**没有采集源**（除 root 档）。

### 5.3 `crates/kada-actions`

- 按 `capability()` 大面积失效：`Command` / `Os` / `System` / `Mouse` / `SendTo` 在 Android 语境下要么删、要么换语义（Intent / 通知 / 无障碍手势）。
- 保留：`Text`（限输入框）、`PauseMs`、`OpenUrl`、`App::Launch`（Intent）、`Clipboard`（仅前台）、`If` / `Vars` / `Parallel` / `InlineScript`（Rhai 沙箱原样可用）。

### 5.4 `src-tauri`（壳）

- 目前 workspace 里 `cfg(desktop)` / `cfg(mobile)` 门控数量是 **0**（`src-tauri/src/lib.rs` 只有一个 `cfg_attr(mobile, tauri::mobile_entry_point)`），第一次编 `aarch64-linux-android` 会成片红。
- `tray.rs` / `overlays.rs` / `update.rs` / `autostart` / `single-instance` 全 `cfg(desktop)`。
- **引擎宿主从 `AppHandle` 解耦**（`src-tauri/src/engine_host.rs`）：引擎跑在前台服务里，不依赖主 Activity 存活。
- 浮层改原生 Kotlin `WindowManager`（Tauri 移动端多窗口不支持），`toast` / `hud` / `hints` / 剪贴板菜单逐个重做，`hints` 那套悬停让位在触屏上没有对应物。

### 5.5 `ui`

- 拖拽区 / 八条 resize zone / 多窗口交互全废；设置项按能力表隐藏（这套已有）。
- 键位编辑器要重做触屏交互（长按出候选、拖动换位），**不是缩放就行**。

### 5.6 构建链

- `cargo-ndk` + NDK + `aarch64-linux-android` 目标（emu 另需 `x86_64-linux-android`）+ `tauri android init` 生成的 Gradle 工程。
- 本机现状：Android SDK 有（platform 36 / build-tools 35、36）、AVD `ihomy34`（android-34）、JDK 21；**NDK 未装**（Rust 阶段才需要，S0 纯 Kotlin 不需要）。

## 7. S0 spike 验收项（真机 / 模拟器）

环境：模拟器 `ihomy34`（android-34）够用——AVD 会把宿主键盘转成真实按键事件；无障碍服务可用 adb 开启（`settings put secure enabled_accessibility_services` + `accessibility_enabled 1`）。

| 项 | 步骤 | 通过标准 | 判失败的含义 |
|---|---|---|---|
| **S0-1 收键 + 吞键** | 最小 `AccessibilityService`，声明 `canRequestFilterKeyEvents` + `FLAG_REQUEST_FILTER_KEY_EVENTS`，`onKeyEvent` 返回 `true` | 在 3 个不同 app（含一个游戏 / WebView）里按键均被吞掉，logcat 有记录 | 档 2 不成立 |
| **S0-2 时序** | 记录同一次按键的 down / up / 系统 repeat，喂给 `Engine` 的 `taphold_step` / `chord_step` | tap-hold 短按长按判定正确；两键和弦（含修饰键）顺序不丢 | 状态机要按 Android 事件模型改写（不是移植） |
| **S0-3 延迟** | 连续按 500 次，统计从「系统收到」到「动作开始执行」 | P50 < 15 ms、P95 < 40 ms（浏览器 / 列表滚动不卡顿） | 需要评估是否只在特定 app 启用 |
| **S0-4 存活** | 前台服务 + 常驻通知，模拟器熄屏 8 小时 + 手动「强行停止」其他 app | 服务不被回收；Doze 下按键仍响应 | 常驻策略要改（WorkManager 联动 / 引导白名单） |
| **S0-5 语义动作** | §3.2 表逐条触发 | 表中 API 在目标 ROM 上可用；不可用的记入能力表 | 只影响可映射的组合键数量，不阻塞 |

> S0-2 是**最该先证伪**的一条：桌面版 `Engine` 的判定依赖完整的 down/up 配对与「所有 keyup 都回调」的约定（架构设计 §3.1）；无障碍的 `onKeyEvent` 是否对重复键、修饰键、被 app 消费的键都给齐，决定 `Engine` 能搬多少。

## 8. 合规与分发

- **无障碍用途声明**：Play 要求填用途并接受审核；「自动化他人 app」是高风险类别，文案要写清「本机按键映射与个人快捷动作」。
- **Android 13+ 受限设置**：侧载安装后无障碍 / 输入法开关默认被锁，引导里要教用户解除。
- **国内商店**：软著（`软著申请/` 材料可按安卓包名重出）+ App 备案。
- **自更新**：`tauri-plugin-updater` 不支持 Android；Play 走商店，侧载走 APK 安装 Intent + `REQUEST_INSTALL_PACKAGES`。
- **root 档**：只出现在侧载 / 高级选项，不进商店主流程。

## 9. 待决策

1. **一个 APK 还是两个 flavor？** 建议一个 APK，root 功能靠运行检测自动出现；Play 版可用 flavor 去掉 root 引导文案。
2. **卡带要不要加 `platforms` 提示字段？** 建议加（只做展示与导入提示）。
3. **手机档是否做读屏式文本扩展？** 建议做，但默认关 + 风险说明。
4. **`sh -c` 命令动作要不要保留？** 保留可以留住「跑脚本」类用户，但 Play 审核对「执行任意命令」敏感。

## 10. 明确不做

- **自建输入法（IME）**：能吃下触屏打字的全部场景，但要自带中文输入法与词库，是另一个产品，另立项。
- **无 root 的鼠标手势 / 滚轮触发**：没有采集源。
- **Tauri 多窗口浮层**：mobile 不支持，必须原生。
- **桌面语义对齐**（窗口标题条件、当前窗口动作、后台发送）：没有对应 API。
