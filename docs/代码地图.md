# Kada 代码地图（症状 → 代码位置）

> **给 AI / 新人的路由表**：先在这里找到「该改哪个文件的哪个符号」，再去读那一节的规则。
> 表里每个 grep 令牌都由 `scripts/check-docs.mjs` 守着——符号被改名 = 检查红，不用等文档腐烂才发现。
> 目录树（哪个文件装什么）见 `docs/README.md`；规则原文见 `docs/需求设计说明书.md` 与 `docs/架构设计.md`。

## 怎么用

1. 在「路由表」里找与症状最接近的一行
2. 按 **文件** 列打开，按 **grep 令牌** 列搜（令牌是源码里逐字存在的字符串，直接搜得到）
3. 按 **规则出处** 列读那一节，**读完再动手**——铁律几乎都在那儿
4. 动手完按 `AGENTS.md` 的「归档流程」写文档
5. 要拆巨型文件、加质量检查（fmt / clippy / ESLint / tsc strict）或评估能不能再瘦身 → 先读 `docs/代码拆分与质量加固计划.md`（跨会话进度账本，Q/U/C/T/O 编号）

## 改一个功能，通常要动的文件

按「加什么」查。先改 core（数据模型），再改判定（engine），再改执行（actions），最后改 UI 与文档。

- **加一个动作类型**（`Action` 变体）
  `crates/kada-core/src/action.rs`（`pub enum Action` + `impl Action` 的 `validate`）→ `crates/kada-actions/src/lib.rs`（执行分支 + `action_label` / `action_summary`）→ `ui/src/main.ts`（`ACTION_TYPES` / `ACTION_ICONS` / `actionTypeLabel`）→ 说明书 §3 + §5.7
- **加一种改键形态**
  `crates/kada-core/src/config.rs`（`pub struct Remap`）→ `src-tauri/src/engine.rs`（`fn taphold_step` / `fn find_taphold_rule`）→ `ui/src/main.ts` → 说明书 §3
- **加一个设置项**
  `crates/kada-core/src/config.rs`（`pub struct Settings`）→ `src-tauri/src/lib.rs`（`fn save_settings_patch`）→ `ui/src/settings.ts`（设置页）→ 说明书 §5
- **加一个钩子能力 / 平台特性**
  `crates/kada-hook/src/win.rs` / `macos.rs` / `linux.rs` → `crates/kada-core/src/conflicts.rs`（`pub struct PlatformCaps` + `fn detect_conflicts`）→ 说明书 §4
- **加一个 Tauri 命令**
  `src-tauri/src/lib.rs`（`#[tauri::command]` + 注册进 `invoke_handler`）→ `ui/src/api.ts`（薄封装，启动 / 保存这类「进来就拉」的）或 `ui/src/main.ts`（页面内的一次性 `invoke`）→ 说明书 §5.3
- **加一个键**
  `crates/kada-core/src/keys.rs`（`pub enum Key` + `Key::ALL`）→ `ui/src/options.ts`（`KEY_OPTIONS`）→ **两端必须同时改**，壳测试 `frontend_key_table_matches_core` 守着
