> **本文档为 Kada 功能需求的唯一活文档**（键模型 + 配置模型 + 钩子引擎 + 桌面壳 + UI + 未实现规划），随功能迭代持续更新。
> 配套文档：实现历史与文件级变更见 `docs/变更归档.md`；开发强制规范见根目录 `AGENTS.md`；架构与关键机制见 `docs/架构设计.md`。
> 代码事实以 `crates/kada-core/src/lib.rs` + `crates/kada-hook/src/*.rs` + `src-tauri/src/lib.rs` 为准，如需检索先 `grep` 再动手。

## 1. 产品概述

咔哒 Kada 是轻快跨平台快捷键工具：全局键盘快捷键、改键、宏，桌面托盘常驻（关窗不退出），配置以 JSON 落盘、可跨平台同步。

- 目标平台：Windows、Linux（已实现）；macOS（M5 规划）。
- 无后端服务、无数据库，纯本地运行。
- 运行时配置落盘在 Tauri `app_data_dir()/config.json`；落盘是**原子写**（临时文件 → `fsync` → `rename` 覆盖，另留 `config.json.bak` 上次良好副本），读取遇到损坏**不静默清空**（原名留档 + 尝试从 `.bak` 自愈 + 消息中心告警）。见 §5.6。

## 2. 键模型（kada-core）

### 2.1 类型

| 类型 | 说明 |
|------|------|
| `Modifier` | `Ctrl / Alt / Shift / Meta`（跨平台中性名；macOS 的 ⌘ 即 Meta） |
| `Key` | 字母 A-Z、数字 0-9、F1-F24、标点（`,` `.` `/` `\` `;` `"` `` ` `` `-` `=` `[` `]`）、功能键（`Enter/Escape/Tab/Space/Backspace/Delete/Insert/CapsLock`）、修饰键本体（`Shift/Control/Alt/Meta`）、方向/编辑键（`Home/End/PageUp/PageDown/Up/Down/Left/Right`）、媒体键（`MediaPlayPause/MediaPrev/MediaNext/VolumeMute/VolumeDown/VolumeUp`）、NumPad 区（`Numpad0..9/NumpadAdd/NumpadSubtract/NumpadMultiply/NumpadDivide/NumpadDecimal/NumpadEnter`）+ `NumLock`、鼠标键（`MouseMiddle/MouseBack/MouseForward`，即中键/侧键 MB4/MB5） |
| `RawEvent` | `{ key, mods: BTreeSet<Modifier>, pressed }`，钩子层产出 |
| `Shortcut` | `{ mods: BTreeSet<Modifier>, key }`，一个快捷键组合 |
| `Trigger` | `Combo(Shortcut)` 单组合 \| `Sequence(Vec<Shortcut>)` 按键序列（首步即 leader 键）\| `Chord(Vec<Shortcut>)` 和弦（同时按住多键，成员限非修饰裸键）；`is_sequence`/`is_chord`/`steps`/`first` |
| `SequenceTracker` | 键序列匹配时序状态机（纯逻辑）：`advance` → `NoMatch \| Advance \| Complete(usize)`，支持共享前缀 |
| `ChordTracker` | 和弦匹配状态机（纯逻辑）：`press` → `NoMatch \| Await \| Complete(usize)` + `release` → 是否原本按住，无序「按住集合」凑齐判定 |

### 2.2 解析与匹配

- 解析 `"Ctrl+Alt+K"`：`+` 分隔；`Ctrl/Control/Cmd/Win`→Ctrl、`Alt/Option`→Alt、`Shift`→Shift、`Meta/Super`→Meta。单个部分（如 `"Shift"`）按按键处理（改键场景）。
- 渲染：`format_shortcut` / `key_name` 把 `Shortcut`/`Key` 渲染回 `"Ctrl+Alt+K"` 形式（UI 展示与配置落盘共用）。
- 匹配（`matches`）：主键一致 **且** 事件修饰键 ⊇ 快捷键修饰键——按下 `Ctrl+Shift+K` 也命中 `Ctrl+K`（宽松规则）。
- 键名别名：媒体/NumPad/鼠标键支持别名（`MB4`/`XButton1`→`MouseBack`、`VolUp`→`VolumeUp`、`NumpadPlus`→`NumpadAdd` 等），渲染统一回规范名。鼠标键不参与修饰键，`"MouseBack"` 即无修饰组合、`"Ctrl+VolumeUp"` 为带修饰组合，均可作快捷键主键或改键 from/to。
- 触发键解析（`Trigger::parse`）：按空白切分——1 个 token 是 `Combo`（`"Ctrl+K"`），≥2 个 token 是 `Sequence`（`"F9 J K"` 依次按下 F9→J→K），单 token 含 `&` 是 `Chord`（`"F&J"` 同时按住 F 和 J）；约定组合键用 `+` 且不含空格、序列步之间用空格、和弦成员之间用 `&`，`"Space"`（空格键）单 token 仍是组合、`"F9 Space"` 是序列；每步用 `Shortcut::parse`（组合键可作序列步，如 `"F9 Ctrl+K"`），任一步坏则整条丢弃；和弦成员必须是非修饰的裸键（`"F&Ctrl"`/`"Ctrl+K&J"`/`"F&"` 均拒绝）。
- 序列匹配时序（`SequenceTracker`，纯逻辑、可单测）：空候选时命中任一序列首步即建立候选（leader 吞掉）；有候选时推进命中下一步的候选、任一条走完返回 `Complete`、全断链则重置返回 `NoMatch`；共享同一 leader 的多条序列（`"F9 J K"`/`"F9 J L"`）一并建候选，天然共存。超时由壳层 `sequence_step` 判定（核心只提供 `DEFAULT_SEQUENCE_TIMEOUT_MS = 1000`）；**断链/超时的按键由壳层原样回放**，见 §4「吞键铁律」。
- 和弦匹配时序（`ChordTracker`，纯逻辑、可单测）：成员无序——按下任一成员键即计入「按住集合」，凑齐某和弦的所有成员返回 `Complete`、未凑齐返回 `Await`、该键不是任何成员则返回 `NoMatch`（集合不变）；`release` 在成员抬起时移出集合，保证「同时按住」判定准确。成员键的 keyup 被钩子层吞掉，但回调仍以观察者身份进入状态机；**没凑齐时由壳层原样回放**，见 §4「吞键铁律」。

## 3. 配置模型（kada-core）

配置是跨平台同步介质，直接以 JSON 落盘/交换；快捷键以 `"Ctrl+Alt+K"` 文本存放（人类可读、可编辑），加载时解析校验。

```rust
Config { folders: Vec<Folder>, layers: Vec<Layer>, shortcuts: Vec<ShortcutItem>,
         remaps: Vec<Remap>, expansions: Vec<TextExpansion>, settings: Settings }

Folder { id: String, name: String, parent: Option<String> }  // 目录树分组（可嵌套，仅影响展示/排序）
Layer  { id: String, name: String }                          // 键位层：快捷键/改键可归属某层，仅该层激活时生效

ShortcutItem { name: Option<String>, description: Option<String>, folder: Option<String>,
               layer: Option<String>, triggers: Vec<String>, actions: Vec<Action>, enabled: bool }
// triggers 任一组命中即触发（每项为单组合 "Ctrl+K" 或按键序列 "F9 J K"）；actions 按顺序执行；folder=目录分组；layer=归属层（None=基础层，始终生效）

Action = Text { text: String, mode: TextMode }      // 文本粘贴到当前焦点（mode：原样 / 选中转大写 / 转小写）
       | Command { shell: Shell, command: String, show_output: bool, var: String }  // 执行命令；var 非空=把标准输出(去首尾空白)写入文本变量
       | Keys { keys: Vec<String> }                         // 组合键（如 ["Ctrl","C"]）
       | PauseMs { ms: u64 }                                // 暂停
       | Os { operation: OsOperation }                      // 文件动作（见下）
       | App { operation: AppOperation }                    // 应用动作（打开/关闭/状态/重启）
       | If { condition: Condition, then: Vec<Action>, otherwise: Vec<Action> }  // 条件判断（真→then，否则→otherwise）
       | Script { path: String, interpreter: Option<String>, show_output: bool, var: String }  // 执行脚本；可选解释器（如 python/node/bash），注入 KADA_TRIGGER/KADA_NAME/KADA_VARS 环境变量，var 非空=标准输出写入文本变量
       | OpenUrl { url: String }                          // 用系统默认浏览器打开网址（Windows explorer / Linux xdg-open）

TextMode = Input | ToUpper | ToLower          // ToUpper/ToLower：复制选中→读剪贴板→转换→粘贴
Shell = Cmd | Powershell                      // Cmd=cmd /C（Linux sh -c），Powershell 仅 Windows

OsOperation = Copy { source, dest } | Cut { source, dest } | Paste { dest }
            | Delete { path } | NewFile { path } | NewFolder { path }
            | OpenFolder { path } | Zip { source, dest } | Unzip { source, dest }
            | GetFileProps { path, var }                    // 取属性写入变量 var（FileObject）

AppOperation = Launch { program, args } | Close { program }
             | Status { program, var, retries, interval_ms } | Restart { program, args }
             // Status 写布尔变量；retries/interval_ms 未运行时轮询重试

Condition = Exists { path } | NotExists { path } | IsFile { path } | IsDir { path }
          | Equals { var, field, value } | NotEquals { var, field, value }  // field 空=完整路径
          | ModifiedWithin { path, minutes }                // 最近 N 分钟内被修改
          | FrontmostApp { app } | NotFrontmostApp { app }  // 前台进程名匹配（不区分大小写；含 * / ? 走通配，否则子串）
          | WindowTitleContains { text }                    // 前台窗口标题包含（不区分大小写）

// 旧版动作（Launch/CloseProgram/Cmd/Powershell/OpenFolder）在 Config::migrate 中自动迁移为
// App::Launch/App::Close/Command/Os::OpenFolder（幂等，递归处理 If）

Remap { from: String, to: String, tap: Option<String>, hold: Option<String>,
        layer: Option<String>, hold_layer: Option<String>, lock_layer: Option<String>, tap_timeout_ms: u64,
        oneshot: Option<String>, sticky: Option<String>, tap2: Option<String>, tap3: Option<String>,
        enabled: bool }
// 普通改键：其余形态字段都空 → from 按下改发 to
// tap-hold：tap（短按）/ hold（长按 ≥ tap_timeout_ms）至少一个非空 → 短按输出 tap、长按输出 hold
// 切层键两形态：hold_layer 非空 → 长按 from 进入该层、松开退回（momentary）；
//               lock_layer 非空 → 长按 from 切换该层开/关、层保持生效、再长按一次退出（切换式）
//               两者互斥，同设保留 lock_layer（层内放和弦/序列只有切换式用得起来）；与 hold 互斥
// 单次修饰：oneshot 非空（值域 Ctrl/Alt/Shift/Meta）→ 单击 from 武装该修饰、应用到下一个非修饰键后自动释放
// 粘滞修饰：sticky 非空（值域同上）→ 单击 from 锁定该修饰、再次单击解锁
// tap-dance：tap2（双击）/ tap3（三击）非空 → 短按升级为连击不同义（单击/双击/三击取 tap/tap2/tap3，缺省回落上一级）
// 形态互斥，优先级 sticky > oneshot > tap-hold > 普通 to；tap_timeout_ms 默认 200ms；layer=归属层（None=基础层）

TextExpansion { trigger: String, replace: String, enabled: bool }
// 热串（hotstring）：输入 trigger + 后缀（空格/回车/Tab）自动展开为 replace；replace 支持 {date}/{time}/{clipboard}

Settings { autostart: bool, paused: bool, wake_key: Option<String>, action_timeout_ms: u64 }
// wake_key：双击该键唤出主窗口（如 "Alt"）；None=关闭快速唤醒
// action_timeout_ms：命令/脚本动作的执行超时（毫秒），0=不限时；缺字段取默认 30000
// 启动显隐按来源区分：双击 exe 手动启动 → 默认打开主窗口；开机自启（注册命令带 --autostart 参数）→ 静默到托盘
```

- 动作自动化走 `automation` feature 门控（`kada-core`/`kada-actions`/`src-tauri` 均 `default = ["automation"]`）：`Command`/`Os`/`App`/`OpenUrl`/`If`/`Script` 及 `Condition`/`Vars` 属自动化动作，关闭 feature（`--no-default-features`）得「基础版」= 改键全形态/层/键序列/文本扩展/Text·Keys·PauseMs 注入；执行引擎在 `kada-actions` crate（壳层 `fire` → `kada_actions::run_actions`）。`Script` 是脚本扩展的「逃生舱」：先指向脚本文件（可选解释器），注入 `KADA_TRIGGER`/`KADA_NAME`/`KADA_VARS` 环境变量、输出可写变量，不内嵌脚本引擎。
- `Action::validate` 校验动作可执行：键名可解析、必要字段非空（非法返回中文错误）。
- `detect_conflicts` 检测内部冲突：硬冲突（重复触发键/重复改键来源/改键遮蔽快捷键）与软冲突（触发键超集重叠）；序列按「完整字符串」判重，序列 leader 遮蔽同层单组合（如序列 `"F9 J K"` 吞掉组合 `"F9"`）报硬冲突；超集软冲突仅对单组合生效（序列跳过）；**层可达性**：层里有启用的条目、却没有任何 `hold_layer`/`lock_layer` 切层键指向它 → 警告「层内条目永远不会生效」。另有 `SYSTEM_SHORTCUTS` 系统快捷键清单（中性键名），壳层 `get_conflicts` 在其上叠加「系统清单精确命中 + Windows `RegisterHotKey` 真实占用探测」。
- 变量占位符系统：`Value::{File,Bool,Text}` + `Vars = BTreeMap<String, Value>`；`GetFileProps` 写入 `File`（`FileObject`：name/path/dir/stem/ext/size/modified/is_dir）、`Status` 写入 `Bool`、命令动作 `var` 非空时写入 `Text`（`TextValue { text=标准输出去首尾空白, exit_code=退出码 }`）。`substitute_vars` 把 `{变量名}` 替换成完整路径（或 "true"/"false"/文本原文）、`{变量名.字段}` 取字段值（文本变量另支持 `{变量名.exit_code}` 取退出码），作用域=单次触发内的动作序列；复制/剪切记 `last_copied` 供「粘贴」动作使用；命令字符串/文件路径/条件路径同样支持 `{变量名}` 占位符。用法见 `docs/变量提取与引用指南.md`。
- `sanitize_config` 保存前逐条清洗：坏触发键/动作/改键被单独忽略并返回提示（`set_config`/`import_config` 返回 `Vec<String>`），硬冲突不再阻塞保存（仅 UI 提示）；目录做去重、断环、孤儿父置根级、无效引用清空（`clean_folders`）；层做去重、清空指向不存在层的 `layer`/`hold_layer`/`lock_layer` 引用（`clean_layers`），`hold_layer` 与 `lock_layer` 同设时保留 `lock_layer` 并提示。
- 层语义：快捷键/改键可归属某层（`layer`，`None`=基础层始终生效）；匹配时激活层条目优先、基础层条目兜底；`active_layer` 是运行时态（非持久化），由切层键驱动——`hold_layer` 按住期间生效（momentary）、`lock_layer` 长按切换后保持生效（层内放和弦/序列用这种）。
- tap-hold 判定：按下 `from` 吞掉进入待定，短按（阈值内松开）输出 `tap`、长按（≥ `tap_timeout_ms`）输出 `hold`；待定期间按下其它键立即判 hold（roll 判定，缩短等待）；`hold` 是修饰键时长按期间并入注入修饰集，让后续组合键携带该修饰键。
- 进阶修饰（oneshot / sticky / multi-tap，复用同一套 tap-hold 时序状态机）：`oneshot` 单击 `from` 后武装修饰（物理按下 + 记入注入集），应用到下一个非修饰键后自动释放；`sticky` 单击锁定修饰、再次单击解锁（锁存期间持续生效）；`tap2`/`tap3` 把短按升级为 tap-dance——tap 释放后不立即输出，进入 `TapDanceState`（`tap_count=1` + 等待窗），窗内再次 down 递增击数（≤3）、超时提交单击/双击/三击输出（缺省回落上一级；提交由壳层定时器线程每 60ms 推进，事件路径懒判定兜底——否则短按一次要等用户再敲键才输出）。注入修饰分三类统一走「物理注入 + mods 补全」通道：`hold`（长按期间）/`sticky`（锁存）/`oneshot`（武装待释放），合并为 `hold ∪ sticky ∪ oneshot`；`oneshot` 的 roll/长按当普通 hold 修饰（复用 `activate_hold`）。
- 文本扩展匹配：`Engine::hotstring` 在放行事件上累积最近可打印字符缓冲（`key_to_char`），命中「触发词 + 后缀」时吞掉后缀键、后台异步回删触发词 + 注入 `replace` + 补回后缀键（避免后缀先落盘与回删并发错位）；最长触发词优先（`match_expansion`）；非可打印键（方向键/功能键等）打断缓冲；注入失败记入消息中心。**依赖自动重复判定正确**：同键连打（`addr` 的双写 d）不能被当成按住连发丢掉，否则缓冲缺字永不命中（见 §4.1）。
- 手工编辑的配置允许缺字段、带未知字段（`#[serde(default)]`），加载时校验；解析失败回退默认空配置。

## 4. 钩子引擎（kada-hook）

职责：把系统键盘事件翻译成 `KeyEvent`，回调处理函数决定 `Action`（`Allow` 放行 / `Block` 吞掉 / `Replace` 注入目标键），注入由 `simulate` 完成。事件统一为轻量键盘事件，键模型在 `kada-core`。

### 4.1 Windows（`win`）

- `SetWindowsHookEx(WH_KEYBOARD_LL + WH_MOUSE_LL)` 全局低层钩子，同一线程跑消息循环；处理函数直接跑在回调内（不做跨线程调度，保证顺序与低延迟）。
- 鼠标钩子只翻译中键与 X 侧键（`WM_MBUTTON*`/`WM_XBUTTON*`，MB4=后退/XBUTTON1、MB5=前进/XBUTTON2）成统一 `KeyEvent`；左右键、滚轮、移动一律放行（不纳入键模型，避免全局误拦截点击）。鼠标键注入走 `SendInput` 鼠标事件（`MOUSEEVENTF_XDOWN/MIDDLEDOWN` 等，`mouseData` 高 16 位承载 X 按钮号）。
- 修饰键用 `GetKeyState` 实时读（事件键自身方向手动修正，避开队列滞后）；自动重复按「该键已按下且未抬起」（`HELD_KEYS` 集合）判定——不能用「同键 N 毫秒内再次 down」的时间窗：同一键快速连打两次是正常输入（热串触发词里的双写字母、双击/三击改键），按时间窗会被误判成自动重复而丢掉第二击，表现为文本扩展不触发、连击不计击数。
- `Block`/`Replace` 登记 `SWALLOWED`，后续 keyup 一并吞掉防幽灵按键；`Replace` 保持"按下-抬起"配对（按住原键 = 按住目标键）；**所有 keyup（含被吞掉的，键盘与鼠标同一套语义）都以观察者身份回调 handler**——录制宏要靠它转写时间线，状态机（和弦按住集合、tap-hold 短长按判定）要靠它维护「按键何时抬起」，漏掉被吞键的抬起会让该键与整个状态机永久卡死（键变哑）；handler 返回值对 keyup 忽略。
- 注入事件带 `LLKHF_INJECTED` 一律放行，杜绝自我回环。
- `Replace` 注入走 `SendInput`，键码为虚拟键码（US 布局语义，OEM 标点键实际位置因键盘布局而异）。
- **自愈看门狗**：低层钩子会**静默失效**——回调超过 `LowLevelHooksTimeout`（默认 300ms）被系统摘除、休眠唤醒后、会话解锁后都可能再也收不到事件，而托盘看着还活着（用户看到的是「快捷键全不响应」且不知为何）。`start` 随钩子线程另起一个 1s 巡检线程，三条触发路径：**回调失效**（回调每次被调用都刷新心跳时间戳，与系统 `GetLastInputInfo` 对照——系统收下了输入而钩子心跳落后 >1.5s 即判已被摘除）、**休眠唤醒**（`GetTickCount` 计入睡眠时间，相邻两次巡检间隔 >10s 即说明机器睡过）、**会话解锁**（`WTSInfoEx.SessionFlags` 读本会话锁屏状态，锁定→未锁定即触发）。命中后向钩子线程投递重装请求，由钩子线程**先卸旧、复位运行时状态、再装新**。机制与取舍见 `docs/架构设计.md` §3.15。
- **运行时状态复位**：`SWALLOWED` / `REPLACED_DOWN` / `HELD_KEYS` 在**重装钩子时**与退钩子时都清空，并把 `REPLACED_DOWN` 里「已注入且被认为按着」的目标键补一个 up。丢一次 keyup（钩子被摘除、锁屏、Alt-Tab、提权窗口吞键）就会留下脏状态：`HELD_KEYS` 里的键永远等不到抬起（自动重复判定把它的后续每次按下都当按住连发 → 该键变哑），被替换的目标键（常是 Ctrl 之类修饰键）在系统看来一直按着。

### 4.2 Linux（`linux`）

- evdev + uinput（内核输入层），X11 / Wayland 通用。
- 打开 `/dev/input/event*` 键盘设备并 `EVIOCGRAB` 独占抓取：被抓设备的所有按键事件只到达我们，原事件不再进应用。
- 用 `/dev/uinput` 建虚拟键盘 `kada-virtual-keyboard`，把 `Action` 结果转发给系统；事件全走 uinput 设备，天然无"收到自己注入事件"的回环。
- 自动重复：物理键长按时内核产生 `value=2` 事件，`Allow` 原样转发、`Replace` 按目标键转发，长按连发不丢。
- 修饰键状态按事件流维护（`MODS_DOWN`），吞键/改键不影响真实状态位，与 Windows `GetKeyState` 语义对齐。
- 授权要求：root 或 `input` 组 + udev 放开 `/dev/uinput`；无权限时 `start` 报错，能读到的其它键盘静默跳过。

### 4.3 注入（`simulate`）

- `down / up / tap / chord / type_text` 与 Windows 后端同接口。
- 文本走剪贴板 + `Ctrl+V`（中文等 Unicode 最稳）；副作用是短暂占用并恢复剪贴板。
- 组合键：全部按下 → 稍停（Windows 30ms）→ 逆序松开。
- `wait_modifiers_released`：触发带修饰键的快捷键时修饰键仍物理按住，直接注入会被污染成 `Ctrl+Alt+<键>`（粘贴 Ctrl+V 变成 Ctrl+Alt+V）；动作执行前轮询 `GetKeyState` 等修饰键全部释放（最多 300ms）再注入（Windows 实现；Linux 因 evdev 独占抓取 + 独立虚拟设备注入，无需等待，提供同接口空实现）。

### 4.4 已知天花板（升级路径）

- 低层钩子拦不住 UAC 提权进程 / 部分游戏 → 驱动级拦截（Interception）。
- 看门狗判「钩子是否还在收事件」用 `GetLastInputInfo`，而它是键盘与鼠标**合并**的信号：**键盘钩子单独被摘除、鼠标钩子还活着**这种半边失效发现不了（心跳一直被鼠标事件喂着）。两个钩子装在同一线程、共用同一处理函数，把回调拖慢的成因对两者是同一个，通常一起被摘掉；真正的根因（把耗时操作移出回调）见 §7.2-⑤。
- `type_text` 用剪贴板粘贴，会短暂占用剪贴板；目标程序吞粘贴（游戏/终端）的场景后续可加 `KEYEVENTF_UNICODE` 直发兜底（两者加开关）。
- Linux 热插拔键盘不在监听列表（重启应用即可）。

## 5. 桌面壳（src-tauri，crate `kada`）

配置驱动：启动时加载 JSON 配置 → 把平台钩子接入配置匹配 → 托盘常驻（关窗不退出）。命令层承载 UI 的读写配置。

- **窗口懒创建（冷启动零 WebView）**：启动时既不建主窗口也不建气泡窗口。主窗口由 `show_main_window()` 按需建出（不存在则 `WebviewWindowBuilder` 建 860×560 居中、已存在则 show+focus；托盘菜单「打开」/托盘双击/`show_output` 弹窗三处入口共用）；气泡窗口由 `ensure_toast()` 在首次触发快捷键时建出（右下角小浮层，点击穿透 + 定位）。

### 5.1 事件决策（`decide`）

- 改键优先于快捷键：先消耗原生键，避免改键后键再触发快捷键。
- 快捷键匹配：跳过 `enabled=false` 与自动重复（`repeat`）；`triggers` 里任一组命中即返回 `Outcome::Shortcut { actions, trigger, name }`（携带触发键与名称，供消息中心展示）。
- 命中快捷键的动作在异步线程执行（`fire` → `kada_actions::run_actions`，执行引擎已迁出到 `kada-actions` crate），避免阻塞钩子回调；执行前先 `wait_modifiers_released`（等触发键修饰键释放，见 §4.3）再跑动作串。
- **tap-hold 状态机（`taphold_step`）**：在 `decide` 之前运行——`from` 键按下即吞掉并延迟判定短按/长按/长按切层（momentary `hold_layer` 与锁定 `lock_layer` 两形态）/单次武装/粘滞切换/连击（见 §3），被吞的键不进 `decide`；其余事件（含并入注入修饰集 `hold ∪ sticky ∪ oneshot` 后的 mods）继续走 `decide`。
- **和弦状态机（`chord_step`）**：在 `taphold_step` 之后、`sequence_step` 之前运行——只处理非重复 Down；成员键按下即吞掉并计入「按住集合」（`ChordTracker::press`），凑齐某和弦所有成员立即 `fire` 触发对应 `ShortcutItem`（成员键就是触发键，不回放）、未凑齐返回 `Await` 继续吞掉。**没凑成和弦则原样回放**（见「吞键铁律」）：成员键全部抬起仍未凑齐 → 按按下顺序回放成员键；待定期间按下的其它键一并吞掉、排在成员键之后回放（保证回放顺序 = 用户输入顺序），修饰键例外（放行，否则 `Ctrl+X` 之类组合失效）；待定缓冲超过 16 项立即定论回放，避免打字被无限延迟。已触发/已回放但物理仍按住的成员键记入 `settling`，其 keyup 到达前抑制自动重复（防止重复回放多出字符）。和弦条目按「激活层优先、基础层兜底」收集（`collect_chord_items`），与 `match_shortcut` 层语义一致。
- **键序列状态机（`sequence_step`）**：在 `chord_step` 之后、`decide` 之前运行——只处理非重复 Down；`SequenceTracker::advance` 返回 `Advance` 吞掉（等待下一键）、`Complete` 复用 `fire` 触发对应 `ShortcutItem` 后吞掉（序列按键本身就是触发键，不回放）、`NoMatch` 断链。断链与超时（`SequenceState.timeout`，默认 1000ms；超时由壳层定时器线程每 60ms 推进一次 `Engine::tick`，事件路径另有懒判定兜底——只靠懒判定的话，单独按一下 leader 键、之后不按别的键就永远等不到回放，表现为该键按了没反应）都会**把已吞掉的 leader 与中间步按输入顺序回放**，当前键也一并回放（保证顺序）。不再单独吞掉 `Escape`——它按普通断链处理。序列触发条目按「激活层优先、基础层兜底」收集（`collect_sequence_items`），与 `match_shortcut` 层语义一致。
- **吞键铁律（序列 / 和弦 / tap-hold 通用）**：按键被吞就补不回来，所以「吞掉」只允许发生在「还在等下一个键来凑齐」的窗口内，**没组成快捷键的按键必须原样回放**。历史上和弦与序列只是「吞掉 + 超时丢弃」，导致用户一配置 `F&J`（成员是常用字母）、`F9 J K`，这些键就永久变哑：按下被吞、抬起被吞，目标程序收不到任何事件；tap-hold 同样有过这个洞——只设「长按进入层」的切层键短按无输出、按住超过阈值再松开（未 roll）也无输出，这个键按下去什么都不发生。现在 tap-hold 的两条无输出路径都回放原键：短按没设 `tap`（含只设 `tap2`/`tap3` 而单击缺省）、长按到底没设 `hold`（切层键 / 只设短按 / 只设双击三击）。回归测试见 `src-tauri/src/engine.rs` 的 `chord_lone_member_key_is_replayed` / `sequence_leader_alone_is_replayed_after_timeout` / `sequence_break_replays_in_input_order` / `hold_layer_key_without_other_key_replays_original_key` 等。
- **层语义匹配**：`match_shortcut` / `match_plain_remap` / `find_taphold_rule` / `collect_chord_items` / `collect_sequence_items` 均按「激活层条目优先、基础层条目兜底」；`active_layer` 由切层键驱动——`hold_layer` 按住生效、松开退回基础层；`lock_layer` 长按切换后保持生效、再长按一次退出。momentary 层只在 roll（按住切层键期间按下其它键）时真正进入——单独按住切层键、不按别的键再松开，层从没生效过，这个按键按吞键铁律回放原键；momentary 层要触发层内快捷键必须**按住切层键**的同时按该快捷键，锁定层则切换后随时可按（层内放和弦/序列只能用锁定层）。配了层内条目却没有任何切层键指向该层时，`detect_conflicts` 会给出「层内条目永远不会生效」的警告（见 §5）。
- **文本扩展（`Engine::hotstring`）**：`decide` 判为 `Pass` 的事件继续喂给热串缓冲（累积可打印字符 / 命中触发词后吞掉后缀键、异步回删+注入+补回后缀 / 非可打印键打断，见 §3）；注入失败（剪贴板等）记入消息中心而不是静默丢弃。
- **录入暂停是限时租约**：`set_paused(true)` 只生效 `PAUSE_LEASE_MS`（60 秒）——录入捕获被中断（失焦/关详情/收进托盘）时前端可能来不及解除暂停，布尔量会永久卡在暂停态，表现为快捷键/改键/文本扩展全部无响应且界面上看不出原因；前端同时在失焦、页面隐藏、关闭详情时主动 `set_paused(false)`。
- **输入状态复位（`Engine::reset`，钩子重装 / 前台切换触发）**：`Engine` 里那些以「按键抬起」或「时间窗」为终止条件的等待态，在「我们与物理键盘之间断过一次线」的场景下会永远等不到终止——和弦按住集合里的键再也收不到抬起（`chord_step` 判定「已在按住中」把它每次按下都吞掉 → 该键永久变哑）、已经**物理注入**的 `hold`/`oneshot`/`sticky` 修饰键配对的抬起丢了（系统层面 Ctrl/Alt 一直按着，「修饰键粘住」）、待定的 tap-hold / 连击 / 键序列与热串缓冲会在超时后回放/展开到一个已经换了主人的窗口。复位由定时器线程巡检两条路径触发（见下条），处理口径是**注入出去的东西收回来、缓冲里的东西丢弃不回放**：注入过的修饰键补一个 up，momentary 层退出，待定态与热串缓冲全部清空（这些键在钩子层已被吞，但复位时前台目标已变，注入到新窗口——可能是密码框——比丢掉更糟）；**锁定层保留**（用户显式切换的持续状态，与按键抬起无关）。返回「是否真的丢了东西」供调用方决定要不要留痕。
- **复位巡检（`ResetWatch`，跑在状态机定时器线程上）**：① **钩子已重装**——底座自愈看门狗修好被摘除 / 唤醒 / 解锁后的钩子时会复位 `HELD_KEYS` 等三张表，壳层这份镜像靠轮询底座单调递增的 `reinstall_count()` 跟着复位（不用回调：那要在钩子线程的消息循环里跑壳层代码，还得多一套跨线程注册；60ms 轮询足够且完全不碰钩子层）。② **前台窗口切换**——`input::foreground_window()`（Windows `GetForegroundWindow` 只读句柄，不查标题/进程名）经 `FocusTracker` **连续两轮看到同一个新窗口**才认切换：气泡/右键菜单/UAC 这类瞬态窗口只晃一轮，误判的代价是白复位一次（用户手上正凑的和弦被丢掉）；读不到句柄（锁屏、无前台窗口）一律不作数。两类触发都只在非暂停/非录制时落地（那段时间事件本来就不进状态机），且只在真的丢了状态时 `eprintln` 留痕，不进消息中心（无声兜底）。Linux 侧 `foreground_window()`/`reinstall_count()` 目前恒 `None`/0（evdev 层拿不到窗口，与前台类条件的受限一致，见 7.3-⑲）。
- **快速唤醒（`wake_double_tap` 判定 + 后台线程建窗）**：在事件决策前被动检测「双击 `Settings.wake_key` ≤400ms」（`None` = 关闭快速唤醒，是设置项的默认值），命中则唤出主窗口。只唤出窗口、不拦截按键（唤醒键常是修饰键，拦截会破坏 Alt+Tab / Alt+字母）；两次独立 down（非自动重复）判双击，其间按下其它键则取消上一次计数。**判定与建窗分开**：判定是不持有 `AppHandle` 的纯函数（结构上就不可能再在回调里建窗，顺带可单测），命中后由调用点 `std::thread::spawn` 到后台线程再 `show_main_window()`——冷启动建 WebView 要几百毫秒，同步建会把回调拖过系统的钩子超时线、钩子被摘掉（见 7.2-⑤，已落地）。

### 5.2 宏录制器（`Recorder`）

- 把全局键盘事件转录成 `Action` 时间线：重复 down 折叠；事件间时差 ≥20ms 补 `PauseMs`；组合键合并成一条 `Keys`，键名落盘为可读字符串。
- 录制中快捷键/改键全暂停，所有事件进时间线、放行；结束补全仍在按住的键的 keyup。

### 5.4 命令结果通知系统（消息中心）

- 命令类动作（`Cmd`/`Powershell`）触发后**一律**捕获输出（stdout/stderr/退出码）并记入消息中心（内存态，重启清空）。
- `show_output` 开关只决定展示方式：开 → 立即按需创建/显示主窗口并弹出结果弹窗；关 → 不弹窗，托盘图标 + 应用内「消息」入口亮红点。
- 进入「消息」页即标记已读、红点熄灭；消息中心以 tab 区分每条结果（标签 `CMD · 触发键` / `PowerShell · 名称`），`‹ ›` 切换。
- 「消息」页分「命令结果 / 冲突」两个标签：冲突标签常驻展示 `get_conflicts` 的冲突清单（`Conflict.name` 标识归属快捷键、severity 着色），标签角标显示冲突数；快捷键列表顶部另有可点击、可消除的冲突气泡（点击跳到冲突标签）。
- **中止与超时的结果也进这里**（`CommandResult.kind` 为 `abort`，标签「中止」）：用户点「停止执行」后剩余动作不再执行、正在跑的命令/脚本被强杀，此时补记一条结果作为可见回应（否则用户只能靠「它不再继续了」猜）；命令/脚本因超时被强杀则在原结果里把原因写进 stderr（`〔咔哒〕执行超时（超过 N 秒），已强制终止该进程及其子进程。`）并把退出码置空（被强杀的进程退出码没有语义）。两种都走消息中心而不是弹窗：用户此刻正在做别的事。
- **任何动作失败也进这里**（`CommandResult.kind` 为 `error`）：非命令类动作（文本/按键注入、启动程序、打开文件夹、复制/剪切/删除/新建、压缩/解压、大小写转换、打开网址……）失败此前只在 stderr 留一行日志，而 release 是不带控制台的 GUI 程序，用户看到的现象只是「按了没反应」。现统一转成结果记录：标签是**哪种动作失败**（`文件操作失败` / `文本注入失败` / `脚本失败` …，tab 渲染成「文件操作失败 · 宏名」，一眼看出坏在哪一步）；「命令」一栏是**动作摘要**（用户写的动作说明优先，其次渲染动作本体，如 `删除 D:\x.txt`；变量已按本次取值代入、换行压平并按 160 字截断——同一快捷键挂多个同类动作时，只给类型分不清是哪一条）；`stderr` 是原始错误、退出码置空。`show_output` **沿用动作自身的设置**：命令/脚本开了「显示输出」，那它**连启动都没成功**这件事同样弹窗；其余动作静默记入消息中心 + 未读红点。一步失败**不中断**后续动作。
- 中文不乱码：Windows 下 cmd 前缀 `chcp 65001>nul & `、PowerShell 前缀 `[Console]::OutputEncoding=...` 统一 UTF-8 解码；Linux 下 CMD 走 `sh -c`。

- 托盘：`打开咔哒`（显示主窗口）/ `检查更新`（手动查更新，见 §5.5）/ `退出`；关窗 = 隐藏到托盘，应用继续跑。
- 跨平台：事件管道用自有 `Ev`，各平台钩子都喂给 `decide` / `Recorder`；非 Windows/Linux 平台（macOS）用占位类型保证壳可编译（改键/快捷键/录制不可用，托盘与配置界面可用）。

### 5.5 软件更新（`update` 模块）

自动化动作之外的第二条「对外通道」：从 GitHub Releases 拉更新清单，验签后装新版本。实现集中在 `src-tauri/src/update.rs`（状态机与流程，与 Tauri 壳解耦、可单测），配置在 `tauri.conf.json` 的 `plugins.updater`，发布流水线在 `.github/workflows/release.yml`；完整发版步骤与密钥管理见 `docs/安装与更新-Windows.md` §2。

- **更新源与信任链**：端点 `https://github.com/chillyice/Kada/releases/latest/download/latest.json`（`releases/latest` 只解析**已发布**的 Release，故流水线默认发 draft 由人确认后再 Publish）；公钥内嵌 `plugins.updater.pubkey`（随仓库），安装包由私钥签名（只进 CI Secret/本机 `~/.tauri/`），客户端只认签名。打包侧靠 `bundle.createUpdaterArtifacts = true` 产出 `.sig`。
- **三种触发与各自的打扰等级**（`Mode::Auto` / `Manual` + 独立的 `spawn_install`）：启动后台检查（release 构建延迟 8 秒、**只在发现新版本**时弹一次气泡，其余情况包括网络失败全静默；dev 构建跳过）、托盘菜单「检查更新」/设置页按钮（无更新与出错都弹窗，发现新版本先确认再装）、设置页「下载并安装」（点击即确认）。
- **状态机在后端**：阶段 `idle`/`checking`/`up-to-date`/`available`/`downloading`/`installing`/`error` 由 Rust 持有并经 `update-status` 事件推送，前端只渲染 + `get_update_status` 兜底；`busy()`（检查/下载/安装中）挡住托盘连点造成的重复发起。
- **进度只在整数百分比变化时推事件**：下载分片回调极密集，每片都 emit 会刷爆 IPC 与前端渲染。
- **Windows 上「安装」会退出应用**（安装器限制）：NSIS 以 `passive` 模式带 `/R` 跑（小进度窗、装完自动重启）。这正是**启动检查只提示、不自动安装**的原因——自动安装等于替用户决定「现在关掉你正在用的应用」；同样地，安装失败保留当前版本、弹窗报错，不影响继续使用。
- **权限面**：更新逻辑全在 Rust 侧（`UpdaterExt`），前端**不直接调** updater，因此 capabilities 里**不开** `updater:*`（最小权限）；也不依赖 `@tauri-apps/plugin-updater`。
- **气泡复用**：`ToastPayload` 增可选的 `subtitle`——「发现新版本」这类通知用 `show_toast_note` 显示自定义副标题，不再拼「正在执行…」。

### 5.6 配置持久化（`config_io` 模块：原子写 + 损坏自愈）

配置是用户的全部劳动成果（快捷键 / 改键 / 层 / 文本扩展），所以落盘与读取按「数据安全」级别对待。实现集中在 `src-tauri/src/config_io.rs`（与 Tauri 壳解耦、带 10 条单测），`set_config` / `import_config` / 启动加载都走它。

- **写入原子**：写同目录唯一临时文件（`config.json.<pid>.<n>.tmp`）→ `fsync` → `rename` 覆盖目标（Windows 上目标被别的进程短暂持有时重试几次）。任何时刻磁盘上的 `config.json` 要么是旧的完整内容、要么是新的完整内容，不会出现崩在中间留下的半截 JSON；并发保存也不会互相踩同一份临时文件。`fsync` 不能省：只写不刷时 `rename` 可能先落盘、数据后落盘，断电后留下空文件。
- **上次良好副本**：每次保存前把现有 `config.json` 留一份 `config.json.bak`（**仅当现有内容可解析时才留**——否则损坏内容会把好备份盖掉，自愈就断了来源）。这份副本同时是手动回滚点。
- **损坏不静默清空**：解析失败先把原文件**改名留档**（`config.json.corrupt-<时间戳>`，不覆盖上一次事故的留档），再尝试用 `.bak` 自愈——恢复成功即回写主文件（真自愈，否则下次启动还是同一个坏文件）。原内容始终留在磁盘上，可人工修复后覆盖回 `config.json`。
- **告警进消息中心**：恢复 / 以空配置启动的经过（含留档路径、解析器原始报错）作为一条「配置 · 启动加载」结果在托盘建好后推给消息中心并亮红点，不再只 `eprintln` 到看不见的控制台。
- **主文件缺失**：与 `.bak` 一起缺失 = 首次启动（静默用默认配置，不打扰）；只剩 `.bak`（用户手工删了主文件 / 同步中断）→ 从备份恢复并告警，而不是给一份空配置。
- 边界口径：加载路径仍只做 `migrate()`（旧版动作迁移）**不做** `sanitize_config()`——加载时静默丢条目同样属于「悄悄改用户配置」；逐条清洗只在保存 / 导入路径做。
- **替换导入前先留档**（`config_io::archive_copy`）：`replace` 导入是这个应用里**唯一能一次换掉整份配置**的操作，所以覆盖前把现有配置**复制**一份成 `config.json.pre-import-<时间戳>`（同一秒重复导入加序号，绝不覆盖上一份）。与损坏留档的区别是**复制而非改名**——主文件还要继续用（随后才被导入内容覆盖）；内容是原样快照，不做解析校验（要的就是「覆盖前磁盘上是什么」这个事实）。留档是尽力而为：失败不中断导入，但会在导入结果里说明（此时 `config_io::save` 留下的 `.bak` 仍是回滚点）。注意 `.bak` 会被**下一次保存**覆盖，带名字的留档不会。
- **导入的两种方式**：`merge`（默认推荐）与 `replace`。`replace` 就是原来的行为（整份覆盖，含 `settings`）；`merge` 的口径在 `kada-core` 的 `merge_configs`（纯函数、可单测），三条铁律：
  - **只增不删**：现有条目一条不动——不改写、不删除，也**不跑清洗**（清洗会顺手丢掉用户手里那些不合规的老条目，那就成了「导入顺便帮你删东西」）。
  - **不制造新冲突**：改键按 `from`、文本扩展按 `trigger`、快捷键按**触发键有交集**判定「同一条」，撞车时保留现有的、跳过导入的那条并**逐条报出**；因此重复导入同一份文件是幂等的，也永远不会因为导入而冒出一堆用户没配过的红冲突。目录 / 层按 `id` 去重（保留现有的名字）。
  - **设置不合并**：`settings`（开机自启 / 快速唤醒键 / 超时 / 暂停）保留本机现值——导入别人分享的配置不该悄悄改掉本机开机自启。要连设置一起换就用 `replace`。
  - 引用完整性：先并目录与层、再并条目，所以导入的条目引用的 `folder` / `layer`（含改键的 `hold_layer` / `lock_layer`）一定已经存在，不会出现「层没进来、改键整条作废」。
- **导入结果要能逐条复盘**：`import_config` 返回 `notes`（被跳过的条目 + 被清洗掉的坏条目，逐条带名称 / 触发键），UI 用结果弹窗列出来。原先只回一个「忽略了几处」的计数——用户根本查不出是哪条没进来，也分不清「合并跳过」与「解析失败」。

### 5.7 动作执行边界（超时与中止）

一次触发就是一条独立的动作链（`fire` → 后台线程 → `kada_actions::run_actions`）。链里的命令与脚本是**外部进程**，它们能挂住（等输入、死循环、弹了个看不见的确认框），所以执行必须有边界——原来的 `Command::output()` 是无限等待，脚本一挂就永久占住这条触发的执行线程（后续动作永不执行、线程也收不回来）。实现集中在 `crates/kada-actions/`（`run_with_limits` + `abort` 模块，均与 Tauri 无关）。

- **超时可配**：`Settings.action_timeout_ms`（设置页「动作超时」，按秒录入，`0` = 不限时），缺字段取默认 30 秒——老配置（写于本字段出现之前）也要拿到保护，所以 serde 缺省用显式默认值而不是零值。超时值随触发一并传给 `run_actions`（`RunOptions`），调用点已持有配置读锁，不再进线程里二次加锁。
- **限时等待 + 边跑边读**：子进程用 `Stdio::piped()` 起，两个管道交给读线程，主线程每 `WAIT_POLL_MS`（20ms）`try_wait()` 判超时/中止。**管道必须边跑边读**：子进程输出超过管道缓冲（Windows 约 4~64KB）而没人读时它写阻塞、我们等它退出，双方互等，超时判定也就永远等不到。
- **杀整棵树**：`Child::kill` 只杀直接子进程，而我们跑的是 `cmd /C <临时批处理>`（Windows）、`powershell -Command`、`sh -c`——真正干活的是孙进程（脚本本体、被启动的程序）。Windows 用 `taskkill /PID <pid> /T /F` 杀整棵树（失败退回 `kill()`）；Linux 目前只 `kill()` 直接子进程（要杀树得让子进程自成进程组再 `kill(-pgid)`，已知缺口）。不杀树的话命令「看起来」结束了、脚本还在后台跑，而且它占着 stdout 管道，连读线程都不会结束。
- **中止开关是代数计数器**（`kada_actions::abort`）：`request()` 只递增代数，每轮执行开始时快照一次，两者不等即「这一轮被叫停了」。用代数而不是布尔量，是因为布尔量必须「新一轮开始时清零」，而清零与用户按下停止之间有竞态——停止可能落在清零之前被下一轮吞掉（点了停止没反应），不清零则一次停止会让之后**所有**触发一启动就自杀。中止发生在：动作链每一步执行前（剩余动作不再执行，避免继续注入按键/启动程序）、`run_with_limits` 的 20ms 轮询（正在跑的进程立刻被杀）、`PauseMs`（切小片睡，几十秒的暂停也停得下来）、`App::Status` 的等待重试循环。
- **反馈不假装成功**：`abort_actions` 返回请求时的「正在执行」链数量（`abort::running()`，由 `RunGuard` 在动作链入口自增减——链里有 `?` 提前返回，手工加减必然漏），前端据此提示「已请求停止（N 条正在执行）」或「当前没有正在执行的动作」；真的被中止的链会补记一条「中止」结果进消息中心（见 §5.4）。
- **测试**：`kada-actions` 从 0 测试补到 9 条——正常命令捕获输出、超时强杀并标注原因、**超时杀掉整棵进程树**（挂住的脚本 3 秒后该建标记文件，被杀则不会出现）、中止杀掉运行中的进程、中止停止剩余动作并记一条结果、上一次的中止不影响新开始的执行，以及 `abort` 模块的代数语义与 `RunGuard` 计数归零。

- **导入方式选择与结果明细**（见 7.2-⑨）：点「导入配置」选好文件后先弹**合并 / 替换**选择框（遮罩与 Esc = 取消，绝不替用户选一种），说明两种方式各自的后果（合并只新增、替换含设置整份覆盖并留档）；导入完成后弹**结果弹窗**：「新增 N 条、跳过 / 忽略 M 条」+ 逐条明细（哪条被跳过、为什么；被清洗掉的坏条目也在这），替换导入还给出**导入前配置的留档路径**（见 §5.6）。此前点一下就直接整份替换，提示文案只说「清洗无效项」，既没说会替换，也只报个数、查不出是哪条没进来。
- **未保存改动守卫**（快捷键 / 改键 / 文本扩展三个编辑页共用，见 7.2-⑧）：编辑只改**草稿副本**（`openDetail` 时深拷贝 / 新建模板），改动是否已落盘靠「与基线比对」判定——`draftBaseline` 记下打开编辑页（或上次保存）那一刻的**草稿签名**（`JSON.stringify`，并带上「只在保存时才读回草稿」的输入框：描述 / 所属层、改键的原键与长按阈值、文本扩展的触发词与替换文本）。有未保存改动时：动作行常驻黄色「● 未保存」标记（标记放动作行、不放标题——标题就是行内编辑的名称输入框，改文案会让光标跳）、「撤销改动」按钮由禁用转为可用（还原到基线内容并留在编辑页）；此时**点另一行 / 切页 / 点「取消」或「×」**都会先弹三态确认框「**保存并离开 / 放弃改动 / 继续编辑**」（遮罩与 Esc = 继续编辑）。「保存并离开」只在**真的落盘**后才放行：保存失败、或改键没设任何输出被判无效，都停在编辑页并把原因 toast 出来。保存落盘的是**草稿的副本**（`cfg` 与草稿从此各持一份），并把列表行的「启用」开关现值带过去——编辑页没有这个控件，否则用户刚点的开关会被草稿里的旧值悄悄盖回去。窗口关闭不设守卫：关窗只是 `hide()`（托盘常驻），WebView 与草稿都还在，没有可丢的东西。
