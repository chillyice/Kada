## 1. 产品概述

咔哒 Kada 是轻快跨平台快捷键工具：全局键盘快捷键、改键、宏，桌面托盘常驻（关窗不退出），配置以 JSON 落盘、可跨平台同步。

- 目标平台：Windows、Linux、macOS（三平台输入层均已实现；macOS 需要用户授予「辅助功能」权限，未授权时输入层起不来并会给出授权指引）。
- 无后端服务、无数据库，纯本地运行。
- 运行时配置落盘在 Tauri `app_data_dir()/config.json`；落盘是**原子写**（临时文件 → `fsync` → `rename` 覆盖，另留 `config.json.bak` 上次良好副本），读取遇到损坏**不静默清空**（原名留档 + 尝试从 `.bak` 自愈 + 消息中心告警）。见 §5.6。

## 2. 键模型（kada-core）

### 2.1 类型

| 类型 | 说明 |
|------|------|
| `Modifier` | `Ctrl / Alt / Shift / Meta`（跨平台中性名；macOS 的 ⌘ 即 Meta） |
| `Key` | 字母 A-Z、数字 0-9、F1-F24、标点（`,` `.` `/` `\` `;` `"` `` ` `` `-` `=` `[` `]`）、功能键（`Enter/Escape/Tab/Space/Backspace/Delete/Insert/CapsLock`）、修饰键本体（`Shift/Control/Alt/Meta`）、方向/编辑键（`Home/End/PageUp/PageDown/Up/Down/Left/Right`）、媒体键（`MediaPlayPause/MediaPrev/MediaNext/VolumeMute/VolumeDown/VolumeUp`）、NumPad 区（`Numpad0..9/NumpadAdd/NumpadSubtract/NumpadMultiply/NumpadDivide/NumpadDecimal/NumpadEnter`）+ `NumLock`、鼠标键（`MouseMiddle/MouseBack/MouseForward`，即中键/侧键 MB4/MB5） |
| `RawEvent` | `{ key, mods: BTreeSet<Modifier>, pressed }`，钩子层产出 |
| `Shortcut` | `{ mods: BTreeSet<Modifier>, key }`，一个快捷键组合 |
| `Trigger` | `Combo(Shortcut)` 单组合 \| `Sequence(Vec<Shortcut>)` 按键序列（首步即 leader 键）\| `Chord(Vec<Shortcut>)` 和弦（同时按住多键，成员可带修饰要求）；`is_sequence`/`is_chord`/`steps`/`first` |
| `SequenceTracker` | 键序列匹配时序状态机（纯逻辑）：`advance` → `NoMatch \| Advance \| Complete(usize)`，支持共享前缀 |
| `ChordTracker` | 和弦匹配状态机（纯逻辑）：`press(key, mods, chords)` → `NoMatch \| Await \| Complete(usize)` + `release` → 是否原本按住，无序「按住集合」凑齐判定（修饰键成员按 `mods` 判「按住」，不进集合） |

### 2.2 解析与匹配

- 解析 `"Ctrl+Alt+K"`：`+` 分隔；`Ctrl/Control/Cmd/Win`→Ctrl、`Alt/Option`→Alt、`Shift`→Shift、`Meta/Super`→Meta。单个部分（如 `"Shift"`）按按键处理（改键场景）。
- 渲染：`format_shortcut` / `key_name` 把 `Shortcut`/`Key` 渲染回 `"Ctrl+Alt+K"` 形式（UI 展示与配置落盘共用）。`Key` 枚举与 `key_name` 由同一个 `keys!` 宏生成（不可能漂移），并产出 `Key::ALL`（全键清单）；壳层测试 `frontend_key_table_matches_core` 按字面量解析 `ui/src/main.ts` 的 `KEY_OPTIONS` / `CODE_TABLE` / `CODE_PUNCT` 与 `Key::ALL` 逐项比对——Rust 新增键而前端手抄表漏改会测试红（见 7.1-㉘）。
- 匹配（`matches`）：主键一致 **且** 事件修饰键 ⊇ 快捷键修饰键——按下 `Ctrl+Shift+K` 也命中 `Ctrl+K`（宽松规则）。
- 键名别名：媒体/NumPad/鼠标键支持别名（`MB4`/`XButton1`→`MouseBack`、`VolUp`→`VolumeUp`、`NumpadPlus`→`NumpadAdd` 等），渲染统一回规范名。鼠标键不参与修饰键，`"MouseBack"` 即无修饰组合、`"Ctrl+VolumeUp"` 为带修饰组合，均可作快捷键主键或改键 from/to。
- 触发键解析（`Trigger::parse`）：按空白切分——1 个 token 是 `Combo`（`"Ctrl+K"`），≥2 个 token 是 `Sequence`（`"F9 J K"` 依次按下 F9→J→K），单 token 含 `&` 是 `Chord`（`"F&J"` 同时按住 F 和 J）；约定组合键用 `+` 且不含空格、序列步之间用空格、和弦成员之间用 `&`，`"Space"`（空格键）单 token 仍是组合、`"F9 Space"` 是序列；每步用 `Shortcut::parse`（组合键可作序列步，如 `"F9 Ctrl+K"`），任一步坏则整条丢弃。**和弦成员可带修饰要求**（`"Ctrl+F&J"` = 按住 Ctrl 的同时把 F、J 一起按住；`"Ctrl+Alt&J"` 的前半是纯修饰键要求，折叠成「要求按住 Ctrl+Alt + 成员键 Alt」以复用同一套 `Shortcut` 表示，显示原样渲染回 `Ctrl+Alt`）：成员重复（`"F&F"`）与「全是修饰键成员」（`"Ctrl&Alt"`，没有可吞的键就没有「同时按下」的判定时机）被拒；`"F&"`/`"F&&J"` 仍是空成员错误。单个修饰键成员写作裸键（`"F&Shift"` = 要求 Shift 按住）无需折叠。
- 序列匹配时序（`SequenceTracker`，纯逻辑、可单测）：空候选时命中任一序列首步即建立候选（leader 吞掉）；有候选时推进命中下一步的候选、任一条走完返回 `Complete`、全断链则重置返回 `NoMatch`；共享同一 leader 的多条序列（`"F9 J K"`/`"F9 J L"`）一并建候选，天然共存。超时由壳层 `sequence_step` 判定，窗口值来自 `Settings.sequence_timeout_ms`（默认 `DEFAULT_SEQUENCE_TIMEOUT_MS = 1000`，0 = 不限时）；**断链/超时的按键由壳层原样回放**，见 §4「吞键铁律」。
- 和弦匹配时序（`ChordTracker`，纯逻辑、可单测）：成员无序——按下任一成员键即计入「按住集合」，凑齐某和弦的所有成员返回 `Complete`、未凑齐返回 `Await`、该键不是任何成员则返回 `NoMatch`（集合不变）；`release` 在成员抬起时移出集合，保证「同时按住」判定准确。**修饰键成员按传入的 `mods` 判定而非按住集合**（`Ctrl+F&J` 里的 Ctrl 要求、`Ctrl+Alt&J` 里两个纯修饰键要求都走这里），且修饰键成员**从不进按住集合**（它们不会被吞，壳层也不把它们交给 tracker，core 另行挡一道保证集合里只有非修饰键）。凑齐的判定时刻是**某个非修饰键成员按下那一刻**，所以 `Ctrl+Alt&J` 要先把 Ctrl/Alt 按住再按 J。成员键的 keyup 被钩子层吞掉，但回调仍以观察者身份进入状态机；**没凑齐时由壳层原样回放**，见 §4「吞键铁律」。

## 3. 配置模型（kada-core）

配置是跨平台同步介质，直接以 JSON 落盘/交换；快捷键以 `"Ctrl+Alt+K"` 文本存放（人类可读、可编辑），加载时解析校验。

```rust
Config { folders: Vec<Folder>, layers: Vec<Layer>, shortcuts: Vec<ShortcutItem>,
```

- 动作自动化走 `automation` feature 门控（`kada-core`/`kada-actions`/`src-tauri` 均 `default = ["automation"]`）：`Command`/`Os`/`App`/`OpenUrl`/`If`/`Script` 及 `Condition`/`Vars` 属自动化动作，关闭 feature（`--no-default-features`）得「基础版」= 改键全形态/层/键序列/文本扩展/Text·Keys·Mouse·PauseMs 注入；执行引擎在 `kada-actions` crate（壳层 `fire` → `kada_actions::run_actions`）。`Script` 是脚本扩展的「逃生舱」：先指向脚本文件（可选解释器），注入 `KADA_TRIGGER`/`KADA_NAME`/`KADA_VARS` 环境变量、输出可写变量，不内嵌脚本引擎。
- `Action::validate` 校验动作可执行：键名可解析、必要字段非空（非法返回中文错误）。
- `detect_conflicts` 检测内部冲突：硬冲突（重复触发键/重复改键来源/改键遮蔽快捷键）与软冲突（触发键超集重叠、和弦之间「一个的要求被另一个全覆盖」）；序列按「完整字符串」判重，序列 leader 遮蔽同层单组合（如序列 `"F9 J K"` 吞掉组合 `"F9"`）报硬冲突；超集软冲突仅对单组合生效（序列跳过）；**和弦**按「排序后的成员（键 + 修饰要求）」判重（`F&J` 与 `J&F` 等价、`F&J` 与 `Ctrl+F&J` 是两条不同触发键），**修饰键成员不遮蔽**以它为「主键」的组合（它们从不被吞）；和弦间软冲突判「一个的要求被另一个全覆盖」——成员更少、或成员键相同而修饰要求更宽的那个会先凑齐触发，更严的那条**永远轮不到**（两边都是合法配置、只是有一条不生效，故是 Warn 不是 Error；同层内，且靠「成员更少必然先凑齐」这条覆盖书写顺序）；**层可达性**：层里有启用的条目、却没有任何 `hold_layer`/`lock_layer` 切层键指向它 → 警告「层内条目永远不会生效」。另有 `SYSTEM_SHORTCUTS` 系统快捷键清单（中性键名），壳层 `get_conflicts` 在其上叠加「系统清单精确命中 + Windows `RegisterHotKey` 真实占用探测」。
- 变量占位符系统：`Value::{File,Bool,Text}` + `Vars = BTreeMap<String, Value>`；`GetFileProps` 写入 `File`（`FileObject`：name/path/dir/stem/ext/size/modified/is_dir）、`Status` 写入 `Bool`、命令动作 `var` 非空时写入 `Text`（`TextValue { text=标准输出去首尾空白, exit_code=退出码 }`）。`substitute_vars` 把 `{变量名}` 替换成完整路径（或 "true"/"false"/文本原文）、`{变量名.字段}` 取字段值（文本变量另支持 `{变量名.exit_code}` 取退出码），作用域=单次触发内的动作序列；复制/剪切记 `last_copied` 供「粘贴」动作使用；命令字符串/文件路径/条件路径同样支持 `{变量名}` 占位符。用法见 `docs/变量提取与引用指南.md`。
- `sanitize_config` 保存前逐条清洗：坏触发键/动作/改键被单独忽略并返回提示（`set_config`/`import_config` 返回 `Vec<String>`），硬冲突不再阻塞保存（仅 UI 提示）；目录做去重、断环、孤儿父置根级、无效引用清空（`clean_folders`）；层做去重、清空指向不存在层的 `layer`/`hold_layer`/`lock_layer` 引用（`clean_layers`），`hold_layer` 与 `lock_layer` 同设时保留 `lock_layer` 并提示；触发条件（`when`）字段非法（如空进程名 / 空设备名）时**单条清掉并提示**，不拖垮整条快捷键 / 改键（`Condition::validate`，与 `If` 动作里的条件同一判据）。
- 层语义：快捷键/改键可归属某层（`layer`，`None`=基础层始终生效）；匹配时激活层条目优先、基础层条目兜底；`active_layer` 是运行时态（非持久化），由切层键驱动——`hold_layer` 按住期间生效（momentary）、`lock_layer` 长按切换后保持生效（层内放和弦/序列用这种）。
- **触发侧条件门控（`when`，7.1-㊶）**：`ShortcutItem` / `Remap` 的可选 `when: Condition` 在**触发前**求值（改键 `from` 按下时 / 快捷键匹配到该条时）；不成立时这条**与不存在等价**——不吞键、落到下一条同触发键 / 同 `from` 的条目，全部落空才按未命中处理（改键放行原键、快捷键继续走 `decide` 后续）。于是「同触发键 + 不同 `when`」是**按条件分流**（`detect_conflicts` 的判重指纹把 `when` 算进去，不报重复），只有「同触发键 + 相同 `when`（含都无）」才算硬冲突。触发时没有变量，`Vars` 为空表——`Equals` / `NotEquals` 这类依赖变量值的条件在门控里恒不成立，UI 的触发条件下拉因此只列路径类（存在 / 不存在 / 是文件 / 是目录 / 修改时间）/ 前台应用 / 前台非 / 窗口标题 / 设备共 9 类（`WHEN_CONDITION_TYPES`）。前台上下文走 `TriggerContext` **惰性获取**：只有真的判定到带 `when` 的条目时才查一次（macOS 的前台查询走 AX 调用，不该让每次按键都买单），同一次判定内缓存；设备取此次触发事件那台（Linux 真设备名，Windows/macOS 恒 `None`）。触发门控里的前台 / 设备条件在平台能力缺失时与 `If` 动作共用同一判据，由 `get_conflicts` 标为「恒不成立」（Warn 不拦保存）。
- tap-hold 判定：按下 `from` 吞掉进入待定，短按（阈值内松开）输出 `tap`、长按（≥ `tap_timeout_ms`）输出 `hold`；待定期间按下其它键立即判 hold（roll 判定，缩短等待）；`hold` 非空时长按期间一律并入注入集（任意键都可，修饰键才参与后续键的 mods 补全）。
- 进阶修饰（oneshot / sticky / multi-tap，复用同一套 tap-hold 时序状态机）：`oneshot` 单击 `from` 后武装**该键**（物理按下 + 记入注入集），应用到下一个非修饰键**抬起**后自动释放（武装键自己再抬起不算消费——否则「按住它的那一下」就被用掉了；已武装时重复按下直接忽略，避免目标程序看成连按两次）；`sticky` 单击锁定**该键**、再次单击解锁（锁存期间持续生效）；`tap2`/`tap3` 把短按升级为 tap-dance——tap 释放后不立即输出，进入 `TapDanceState`（`tap_count=1` + 等待窗），窗内再次 down 递增击数（≤3）、超时提交单击/双击/三击输出（缺省回落上一级；提交由壳层定时器线程每 60ms 推进，事件路径懒判定兜底——否则短按一次要等用户再敲键才输出）。**三者值域都是任意键**（修饰键是常见用法；非修饰键 = 替你按住它，如侧键做「按住说话」）；注入键分三类统一走「物理注入 + mods 补全」通道：`hold`（长按期间）/`sticky`（锁存）/`oneshot`（武装待释放），合并为 `hold ∪ sticky ∪ oneshot`，其中只有修饰键参与后续键的 mods 补全（非修饰键补不进 `Shortcut.mods`）；`oneshot` 的 roll/长按当普通 hold 键（复用 `activate_hold`）。
- 文本扩展匹配：`Engine::hotstring` 在放行事件上累积最近可打印字符缓冲（`key_to_char`），命中「触发词 + 后缀」时吞掉后缀键、后台异步回删触发词 + 注入 `replace` + 补回后缀键（避免后缀先落盘与回删并发错位）；最长触发词优先（`match_expansion`）；非可打印键（方向键/功能键等）打断缓冲；注入失败记入消息中心。**依赖自动重复判定正确**：同键连打（`addr` 的双写 d）不能被当成按住连发丢掉，否则缓冲缺字永不命中（见 §4.1）。
- 手工编辑的配置允许缺字段、带未知字段（`#[serde(default)]`），加载时校验；解析失败回退默认空配置。

## 4. 钩子引擎（kada-hook）

职责：把系统键盘事件翻译成 `KeyEvent`，回调处理函数决定 `Action`（`Allow` 放行 / `Block` 吞掉 / `Replace` 注入目标键），注入由 `simulate` 完成。事件统一为轻量键盘事件，键模型在 `kada-core`。

**三个平台后端（`win` / `linux` / `macos`）暴露同一套接口**——`start` / `KeyEvent` / `Action` / `simulate` / `foreground_window` / `reinstall_count`——所以壳层的 `decide` / `Recorder` / `Engine` 与动作层都不为平台分叉（差异只在 cfg 门控与各处平台分支，见 §4.3 与 §4.4）。

### 4.1 Windows（`win`）

- `SetWindowsHookEx(WH_KEYBOARD_LL + WH_MOUSE_LL)` 全局低层钩子，同一线程跑消息循环；处理函数直接跑在回调内（不做跨线程调度，保证顺序与低延迟）。
- 鼠标钩子只翻译中键与 X 侧键（`WM_MBUTTON*`/`WM_XBUTTON*`，MB4=后退/XBUTTON1、MB5=前进/XBUTTON2）成统一 `KeyEvent`；左右键、滚轮、移动一律放行（不纳入键模型，避免全局误拦截点击）。鼠标键注入走 `SendInput` 鼠标事件（`MOUSEEVENTF_XDOWN/MIDDLEDOWN` 等，`mouseData` 高 16 位承载 X 按钮号）。**鼠标钩子按需安装**（7.1-㉛）：只有配置引用了鼠标键作**触发侧**（快捷键 / 改键来源）才挂 `WH_MOUSE_LL`，否则不挂——缩小全局拦截面。壳层 `config_uses_mouse()` 判定（仅作注入目标不算），启动时设定、运行中配置变化由状态机定时器线程比对后调 `set_mouse_enabled`（值变才重装，重装在钩子线程上增删钩子）。**新增鼠标键用途时要同步 `config_uses_mouse`**，否则鼠标键静默失效。
- 修饰键用 `GetKeyState` 实时读（事件键自身方向手动修正，避开队列滞后）；自动重复按「该键已按下且未抬起」（`HELD_KEYS` 集合）判定——不能用「同键 N 毫秒内再次 down」的时间窗：同一键快速连打两次是正常输入（热串触发词里的双写字母、双击/三击改键），按时间窗会被误判成自动重复而丢掉第二击，表现为文本扩展不触发、连击不计击数。
- `Block`/`Replace` 登记 `SWALLOWED`，后续 keyup 一并吞掉防幽灵按键；`Replace` 保持"按下-抬起"配对（按住原键 = 按住目标键）；**所有 keyup（含被吞掉的，键盘与鼠标同一套语义）都以观察者身份回调 handler**——录制宏要靠它转写时间线，状态机（和弦按住集合、tap-hold 短长按判定）要靠它维护「按键何时抬起」，漏掉被吞键的抬起会让该键与整个状态机永久卡死（键变哑）；handler 返回值对 keyup 忽略。
- 注入事件带 `LLKHF_INJECTED` 一律放行，杜绝自我回环。
- `Replace` 注入走 `SendInput`，键码为虚拟键码（US 布局语义，OEM 标点键实际位置因键盘布局而异）。
- **自愈看门狗**：低层钩子会**静默失效**——回调超过 `LowLevelHooksTimeout`（默认 300ms）被系统摘除、休眠唤醒后、会话解锁后都可能再也收不到事件，而托盘看着还活着（用户看到的是「快捷键全不响应」且不知为何）。`start` 随钩子线程另起一个 1s 巡检线程，三条触发路径：**回调失效**（键盘 / 鼠标回调各刷**自己那一路**心跳，与系统 `GetLastInputInfo` 对照。该信号是键鼠**合并**的，故先**归因**再分路判失效：系统最后输入比鼠标心跳新出 >100ms ⇒ 那次输入不是鼠标（鼠标钩子活着必看得见它）⇒ 是键盘输入，此时键盘心跳仍落后 >1.5s 即判**键盘钩子**被摘；对称可判**鼠标钩子**（`dead_hook` 直接返回是哪一路）。鼠标钩子未装时退化为只看键盘心跳）、**休眠唤醒**（`GetTickCount` 计入睡眠时间，相邻两次巡检间隔 >10s 即说明机器睡过）、**会话解锁**（`WTSInfoEx.SessionFlags` 读本会话锁屏状态，锁定→未锁定即触发）。命中后向钩子线程投递重装请求，由钩子线程**先卸旧、复位运行时状态、再装新**。机制与取舍见 `docs/架构设计.md` §3.15。
- **运行时状态复位**：`SWALLOWED` / `REPLACED_DOWN` / `HELD_KEYS` 在**重装钩子时**与退钩子时都清空，并把 `REPLACED_DOWN` 里「已注入且被认为按着」的目标键补一个 up。丢一次 keyup（钩子被摘除、锁屏、Alt-Tab、提权窗口吞键）就会留下脏状态：`HELD_KEYS` 里的键永远等不到抬起（自动重复判定把它的后续每次按下都当按住连发 → 该键变哑），被替换的目标键（常是 Ctrl 之类修饰键）在系统看来一直按着。

### 4.2 Linux（`linux`）

- evdev + uinput（内核输入层），X11 / Wayland 通用。
- 打开 `/dev/input/event*` 中的键盘与鼠标设备并 `EVIOCGRAB` 独占抓取：被抓设备的所有事件只到达我们，原事件不再进应用。**触摸板 / 触摸屏 / 指点杆不抓取**（多点与 ABS 协议原样转发做不到，抓了等于废掉整个触摸板；它们的中键 / 侧键不能作触发键），判定 = 有 `REL_X`/`REL_Y` + `BTN_LEFT` 且不带 `INPUT_PROP_*` 触摸标记（老内核无属性时靠 `BTN_TOOL_FINGER` / `BTN_TOUCH` 兜底）。
- 用 `/dev/uinput` 建虚拟设备 `kada-virtual-input`（**键盘 + 鼠标合一**：键码 1..=0x2ff 已含 `BTN_*`，另声明相对轴 0x00..=0x0f 承载移动 / 滚轮），把 `Action` 结果与不进键模型的原始事件（左右键、移动、滚轮）全部转发给系统；事件全走 uinput 设备，天然无"收到自己注入事件"的回环。**鼠标键（中键 / 侧键 MB4/MB5）与键盘键走同一套状态机**（`BTN_MIDDLE` / `BTN_SIDE` / `BTN_EXTRA` ↔ `MouseMiddle` / `MouseBack` / `MouseForward`），可作触发键与改键目标、注入不再有缺口；左右键不进键模型（避免全局误拦截点击）。
- 自动重复：物理键长按时内核产生 `value=2` 事件，`Allow` 原样转发、`Replace` 按目标键转发，长按连发不丢。
- 修饰键状态按事件流维护（`MODS_DOWN`），吞键/改键不影响真实状态位，与 Windows `GetKeyState` 语义对齐。
- **权限与引导（7.1-⑱）**：root 或 `input` 组 + udev 放开 `/dev/uinput`。起不来时 `start` 的错误串**分诊并带能照抄的命令**：键盘全被 `EBUSY` 独占（另一个 Kada / keyd / xremap 在跑）→ 提示关掉它们；`/dev/input/event*` 存在却枚举不到（无打开权限，evdev 枚举阶段就静默跳过）→ `usermod -aG input`；`/dev/uinput` 缺失（`ENOENT`）→ `modprobe uinput` + 开机自动加载；`/dev/uinput` 无权限（`EACCES`/`EPERM`）→ udev 规则 `KERNEL=="uinput", MODE="0660", GROUP="input"`。**壳层起不来时照常启动**（同 macOS 口径）：错误串经消息中心推给用户（设置页进得去、照得到指引），修好权限重启即可——原先「setup 失败、应用报错退出」对首次装机的用户等于死路。`hooks_supported()` = `start` 是否成功，录制入口据此给出指引而不是「平台不支持」。
- **设备丢失复位（7.1-⑱）**：设备拔出即从监听列表移除，同时**就地复位** `SWALLOWED` / `REPLACED_DOWN` / `MODS_DOWN`（被替换、已注入的目标键补一个 up——与 Windows 重装钩子 `reset_runtime_state` 同口径），并递增 `reinstall_count()` 让壳层 `ResetWatch` 复位 `Engine` 的等待态（序列 / 和弦等）。否则拔掉的设备上还按着的键永远等不到抬起，之后所有快捷键按「Ctrl 还按着」误判。热插拔重扫（拔了再插自动恢复监听）仍是 7.2-㉜ 的规划。

### 4.3 macOS（`macos`）

- `CGEventTap`（**会话级** `kCGSessionEventTap` + `HeadInsertEventTap` + `Default` 选项）装在**独立线程的 CFRunLoop** 上，处理函数直接跑在回调里、不跨线程调度（保证顺序与低延迟）。**位置必须选会话级**：`CGEventTapCreate` 在 HID 位置只有 root 建得出来（Apple `CGEvent.h` 原话：普通进程拿到 NULL），而会话级是辅助功能权限覆盖得到的最前一层、仍早于窗口服务器把事件派发给应用，吞键 / 改键照常有效。
- 修饰键状态取**事件自带的 `flags`**（该事件生成那一刻的修饰键快照）而不是全局查询：少一次队列滞后，且「事件键本身是修饰键」的方向修正天然包含在内。`FlagsChanged` 的方向只能从 flags 读（事件里的修饰位是该键**变化之后**的状态）；CapsLock 例外——它只发 `FlagsChanged`、且 AlphaShift 位反映开关而非物理按下，故方向靠自记的翻转状态。
- 自动重复取 macOS 自己的 `kCGKeyboardEventAutorepeat` 字段，**并**叠加「该键已按下且未抬起」（`HELD_KEYS`）的本地判定，两者取或：字段缺失时不能把长按连发当连打，字段误报时也不能把连打当连发（热串触发词的双写字母、双击/三击改键都靠这个）。
- 鼠标只处理「其它键」（`OtherMouse*`：中键 = 2、MB4 = 3、MB5 = 4）；左/右键与滚轮不在事件掩码里，连回调都不会进。
- `Block`/`Replace` 登记 `SWALLOWED`，后续 keyup 一并吞掉防幽灵；`Replace` 保持「按下-抬起」配对；**所有 keyup（含被吞掉的）仍以观察者身份回调 handler**（状态机靠抬起维护按住集合，漏一次就永久卡死）。
- **注入识别（防回环）**：两条独立判据取或——① 事件源是 Private（我们注入的默认形态）；② **创建该事件的进程就是本进程**（`kCGEventSourceUnixProcessID`；硬件事件由窗口服务器创建、其它应用注入的事件带它们的 pid，都不可能等于我们）。②是兜底：①依赖的系统行为在非 macOS 开发机上无法验证，而它不成立时自己注入的 ⌘V 会被自己处理（用户恰好绑了 ⌘V 就是无限触发）。
- **自愈**：tap 回调太慢 / 输入过载时系统会**主动**回调 `kCGEventTapDisabledByTimeout` / `kCGEventTapDisabledByUserInput`，当场重新启用并复位运行时状态（同 Windows 的「先复位、再启用」口径）；另有 1s 看门狗兜住「休眠唤醒后收不到事件」与没有任何通知的静默失效——`CGEventSourceSecondsSinceLastEventType` 与本进程心跳对照（等价于 Windows 的 `GetLastInputInfo`）、相邻巡检间隔 >10s 判唤醒，连续触发按 1s→16s 指数退避。`reinstall_count()` 供壳层发现「输入层断过一次线」并复位状态机（见 §5.1）。
- **权限**：监听（建 tap）与注入都需要「辅助功能」权限，而且是**运行时授权**的。未授权时 `start` 返回一句能照做的错误并顺手弹一次系统授权框；壳层的 `hooks_supported()` 直接就是 `AXIsProcessTrusted()`。未授权时的处置与另两个平台不同：Windows / Linux 起不来是异常（让 setup 失败、用户能看见报错），macOS **照常启动**并把授权指引记进消息中心——首次启动必然没权限，若让 setup 失败用户连设置页都进不去，也就永远拿不到那份权限。
- **前台上下文**：走辅助功能接口取前台应用 pid 与焦点窗口标题（属性名 `AXFocusedApplication` / `AXFocusedWindow` / `AXTitle`），**粒度是应用不是窗口**（同应用内换窗口不会触发输入状态复位）。`CGWindowList` 那条路拿窗口标题要「屏幕录制」权限、比辅助功能更难拿，故不用。属性名用**字面量字符串**而不是链 `kAX*` 符号（后者在某些 SDK 版本里是 `CFSTR` 宏，写成 `extern static` 是链接期未定义符号）；AX 返回值先用 `CFGetTypeID` 验明确实是字符串再当字符串用。
- **注入**：事件投递到 HID 位置（`CGEventPost(kCGHIDEventTap, ..)`）——注意这与「建 tap」的要求相反：建 tap 在 HID 位置要 root，**投递**事件不需要（这正是合成按键的常规做法）；投出去的事件仍会顺流经过我们自己那个会话级 tap，靠注入识别放行。文本走剪贴板 + ⌘V；组合键「全部按下 → 稍停 30ms → 逆序松开」，每个键都把该带的修饰位显式写进事件 flags（否则部分应用读 flags 时看不到修饰键）。
- 已知天花板见 §4.5（媒体键走 `NX_SYSDEFINED` 系统定义事件、不是虚拟键码，本版本不识别、原样放行；F21~F24 无此硬件）。

### 4.4 注入（`simulate`）

- `down / up / tap / chord / type_text` 与 Windows 后端同接口。
- 文本走剪贴板 + `Ctrl+V`（中文等 Unicode 最稳）；副作用是短暂占用并恢复剪贴板。macOS 的粘贴是 ⌘V（键模型里 `Meta` 承载 ⌘）。
- 组合键：全部按下 → 稍停（Windows 30ms）→ 逆序松开。
- `wait_modifiers_released`：触发带修饰键的快捷键时修饰键仍物理按住，直接注入会被污染成 `Ctrl+Alt+<键>`（粘贴 Ctrl+V 变成 Ctrl+Alt+V）；动作执行前轮询 `GetKeyState` 等修饰键全部释放（最多 300ms）再注入（Windows 与 macOS 都有实现，macOS 查 `CGEventSourceFlagsState`；Linux 因 evdev 独占抓取 + 独立虚拟设备注入，无需等待，提供同接口空实现）。

### 4.5 已知天花板（升级路径）

- 低层钩子拦不住 UAC 提权进程 / 部分游戏 → 驱动级拦截（Interception，见 7.2-㉑）；macOS 侧同样拦不住**提权**进程与**安全输入**（Secure Input——终端里输密码时系统会关掉所有事件 tap，见 7.2-㊸）。
- 看门狗判「钩子是否还在收事件」用 `GetLastInputInfo`，它是键盘与鼠标**合并**的信号；Windows 已靠键盘 / 鼠标**分路心跳 + 归因**发现「键盘钩子单独被摘除、鼠标钩子还活着」这类半边失效（7.1-㊵），但**鼠标持续移动**时系统最后输入始终约等于鼠标心跳、键盘输入被夹在两次鼠标事件之间归因不出来，这半边失效要等到某次键盘输入处于两次巡检之间且其后没有鼠标事件时才探到（残余，见 §4.1 与 `docs/架构设计.md` §3.15）。真正的根因仍是把耗时操作移出回调（见 `docs/架构设计.md` §3.6）。
- 文本注入两条通道已随 7.1-㉒ 落地（`Settings.text_inject_mode`，见 §4.4）：剪贴板粘贴（默认，会短暂占用并恢复剪贴板）与 unicode 逐字直发（不经键盘布局、不被物理修饰键污染）。仍存的边界：Linux 无字符通道（uinput 只有键码、XTEST 在 Wayland 不可用），直发模式在 Linux 回落剪贴板粘贴；目标程序连粘贴都吞（游戏 / 终端）时两条通道都无效。
- Linux 热插拔键盘不在监听列表（重启应用即可；设备拔出的**状态复位**已随 7.1-⑱ 落地，重扫见 7.2-㉜）；macOS 媒体键（`NX_SYSDEFINED` 系统定义事件，不是虚拟键码）与 F21~F24 无法绑定（前者原样放行、原生功能不受影响；升级路径见 7.2-㊹）。
- `DeviceIs` 在 Windows / macOS 恒不成立（低层钩子拿不到设备，见 7.2-㊷）。

## 5. 桌面壳（src-tauri，crate `kada`）

配置驱动：启动时加载 JSON 配置 → 把平台钩子接入配置匹配 → 托盘常驻（关窗不退出）。命令层承载 UI 的读写配置。

- **窗口懒创建（冷启动零 WebView）**：启动时既不建主窗口也不建气泡窗口。主窗口由 `show_main_window()` 按需建出（不存在则 `WebviewWindowBuilder` 建 860×560 居中、已存在则 show+focus；托盘菜单「打开」/托盘双击/`show_output` 弹窗三处入口共用）；气泡窗口由 `ensure_toast()` 在首次触发快捷键时建出（右下角小浮层，点击穿透 + 定位）；**输入状态悬浮指示窗**由 `ensure_hud()` 在有层或注入键生效时建出（`index.html#hud`，底部居中小胶囊，见 §5.1）。
- **透明小浮窗一律 `focusable(false)`**（`toast` 与 `hud`）：Windows 上就是 `WS_EX_NOACTIVATE`。`focused(false)` 只保证**首次** `show()` 不抢焦点——tao 首次用 `SW_SHOWNOACTIVATE`，之后清掉该标记退回 `SW_SHOW`，而这两个窗每次都要 show 好几次。抢焦点的后果不只是打断用户打字：`GetForegroundWindow` 会变成我们自己的浮窗，① 前台条件（前台应用 / 窗口标题）全部读错，② `ResetWatch` 把它当成「前台切换」→ 复位输入状态（按住的 momentary 层当场被踢掉）。它俩都只是看板，不接受点击（`set_ignore_cursor_events`）、不接焦点。
- **托盘常驻**：菜单 = `打开咔哒`（显示主窗口）/ `暂停快捷键触发`（勾选开关，与设置页「暂停」同一字段 `settings.paused`，勾选态由定时器线程对齐，见 7.1-㉗）/ `快捷键提示`（勾选开关提示框，见 §5.8）/ `重载配置`（立即从磁盘再读一份，见 §5.6 与 7.1-㉗）/ `检查更新`（手动查更新，见 §5.5）/ `退出`；关窗 = 隐藏到托盘，应用继续跑。托盘图标承担两种状态提示：消息中心有未读时亮红点（见 §5.4）、输入状态摘要随 `set_tooltip` 同步（见 §5.1）。
- **跨平台**：事件管道用自有 `Ev`，各平台钩子（Windows / Linux / macOS，见 §4.1~§4.3）都喂给 `decide` / `Recorder`，快捷键 / 改键 / 序列 / 和弦 / 层 / 文本扩展 / 宏录制在三个平台都可用，托盘与配置界面不受平台影响。平台差异只在两处：**能力**（macOS 的「辅助功能」权限未授予时 `hooks_supported()` 为 false，录制等入口给授权指引而不是「平台不支持」；Linux 的前台类条件受 Wayland 限制恒不成立，设备类条件则相反——只有 Linux 能拿到真实设备名）与**动作层的命令**（打开目录 / 网址、关闭程序、CMD 的 shell 各自换平台命令，见 §5.7）。

### 5.1 事件决策（`decide`）

- 改键优先于快捷键：先消耗原生键，避免改键后键再触发快捷键。
- 快捷键匹配：跳过 `enabled=false` 与自动重复（`repeat`）；`triggers` 里任一组命中即返回 `Outcome::Shortcut { actions, trigger, name }`（携带触发键与名称，供消息中心展示）。
- **触发侧 `when` 门控（7.1-㊶）**：`match_shortcut` / `match_plain_remap` / `find_taphold_rule` / `collect_chord_items` / `collect_sequence_items` 在层语义之外再按 `when` 过滤（语义见 §3）——条件不成立的条目当作不存在，匹配继续落到下一条。上下文由壳层构造**一份** `TriggerContext::lazy`（惰性前台 + 此次事件设备）传入，`Engine::step`（tap-hold / 和弦 / 序列）与 `decide` 共用它，同一次按键判定内前台最多查一次。
- 命中快捷键的动作在异步线程执行（`fire` → `kada_actions::run_actions`，执行引擎已迁出到 `kada-actions` crate），避免阻塞钩子回调；执行前先 `wait_modifiers_released`（等触发键修饰键释放，见 §4.4）再跑动作串。
- **tap-hold 状态机（`taphold_step`）**：在 `decide` 之前运行——`from` 键按下即吞掉并延迟判定短按/长按/长按切层（momentary `hold_layer` 与锁定 `lock_layer` 两形态）/单次武装/粘滞切换/连击（见 §3），被吞的键不进 `decide`；其余事件（含并入注入修饰集 `hold ∪ sticky ∪ oneshot` 后的 mods）继续走 `decide`。
- **和弦状态机（`chord_step`）**：在 `taphold_step` 之后、`sequence_step` 之前运行——只处理非重复 Down；**成员键（非修饰键）**按下即吞掉并计入「按住集合」（`ChordTracker::press`，同时传入当前按住的 `mods` 供成员修饰要求判定），凑齐某和弦所有成员立即 `fire` 触发对应 `ShortcutItem`（成员键就是触发键，不回放）、未凑齐返回 `Await` 继续吞掉；**修饰键成员**（`Ctrl+F&J` 里的 Ctrl 要求、`Ctrl+Alt&J` 里的 Ctrl/Alt）只表示「凑齐那一刻要按着」，按下/抬起一律放行、既不吞也不进按住集合（吞掉修饰键会把 `Ctrl+Alt+Tab` 变成 `Ctrl+Tab`，登记进集合还会让「按着 Ctrl 打字」全被压进待定缓冲）。**没凑成和弦则原样回放**（见「吞键铁律」）：成员键全部抬起仍未凑齐 → 按按下顺序回放成员键；**等待窗（`Settings.chord_timeout_ms`，默认 1000ms、0 = 不限时）过期**同样判定「不是和弦」并回放（成员键按下后用户打的每个字都在缓冲里排队，这个窗口就是给那段滞留时间设上限）——过期判定由事件路径懒判 + 定时器线程 `Engine::tick` 双路落地；待定期间按下的其它键一并吞掉、排在成员键之后回放（保证回放顺序 = 用户输入顺序），修饰键例外（放行，否则 `Ctrl+X` 之类组合失效）；待定缓冲超过 16 项立即定论回放，避免打字被无限延迟。已触发/已回放但物理仍按住的成员键记入 `settling`，其 keyup 到达前抑制自动重复（防止重复回放多出字符）。和弦条目按「激活层优先、基础层兜底」收集（`collect_chord_items`），与 `match_shortcut` 层语义一致。
- **键序列状态机（`sequence_step`）**：在 `chord_step` 之后、`decide` 之前运行——只处理非重复 Down；`SequenceTracker::advance` 返回 `Advance` 吞掉（等待下一键）、`Complete` 复用 `fire` 触发对应 `ShortcutItem` 后吞掉（序列按键本身就是触发键，不回放）、`NoMatch` 断链。断链与超时（`Settings.sequence_timeout_ms`，默认 1000ms、0 = 不限时；超时由壳层定时器线程每 60ms 推进一次 `Engine::tick`，事件路径另有懒判定兜底——只靠懒判定的话，单独按一下 leader 键、之后不按别的键就永远等不到回放，表现为该键按了没反应）都会**把已吞掉的 leader 与中间步按输入顺序回放**，当前键也一并回放（保证顺序）。不再单独吞掉 `Escape`——它按普通断链处理。序列触发条目按「激活层优先、基础层兜底」收集（`collect_sequence_items`），与 `match_shortcut` 层语义一致。
- **吞键铁律（序列 / 和弦 / tap-hold 通用）**：按键被吞就补不回来，所以「吞掉」只允许发生在「还在等下一个键来凑齐」的窗口内，**没组成快捷键的按键必须原样回放**。历史上和弦与序列只是「吞掉 + 超时丢弃」，导致用户一配置 `F&J`（成员是常用字母）、`F9 J K`，这些键就永久变哑：按下被吞、抬起被吞，目标程序收不到任何事件；tap-hold 同样有过这个洞——只设「长按进入层」的切层键短按无输出、按住超过阈值再松开（未 roll）也无输出，这个键按下去什么都不发生。现在 tap-hold 的两条无输出路径都回放原键：短按没设 `tap`（含只设 `tap2`/`tap3` 而单击缺省）、长按到底没设 `hold`（切层键 / 只设短按 / 只设双击三击）。回归测试见 `src-tauri/src/engine.rs` 的 `chord_lone_member_key_is_replayed` / `sequence_leader_alone_is_replayed_after_timeout` / `sequence_break_replays_in_input_order` / `hold_layer_key_without_other_key_replays_original_key` 等。
- **层语义匹配**：`match_shortcut` / `match_plain_remap` / `find_taphold_rule` / `collect_chord_items` / `collect_sequence_items` 均按「激活层条目优先、基础层条目兜底」；`active_layer` 由切层键驱动——`hold_layer` 按住生效、松开退回基础层；`lock_layer` 长按切换后保持生效、再长按一次退出。momentary 层只在 roll（按住切层键期间按下其它键）时真正进入——单独按住切层键、不按别的键再松开，层从没生效过，这个按键按吞键铁律回放原键；momentary 层要触发层内快捷键必须**按住切层键**的同时按该快捷键，锁定层则切换后随时可按（层内放和弦/序列只能用锁定层）。配了层内条目却没有任何切层键指向该层时，`detect_conflicts` 会给出「层内条目永远不会生效」的警告（见 §3 冲突检测）。
- **文本扩展（`Engine::hotstring`）**：`decide` 判为 `Pass` 的事件继续喂给热串缓冲（累积可打印字符 / 命中触发词后吞掉后缀键、异步回删+注入+补回后缀 / 非可打印键打断，见 §3）；注入失败（剪贴板等）记入消息中心而不是静默丢弃。
- **录入暂停是限时租约**：`set_paused(true)` 只生效 `PAUSE_LEASE_MS`（60 秒）——录入捕获被中断（失焦/关详情/收进托盘）时前端可能来不及解除暂停，布尔量会永久卡在暂停态，表现为快捷键/改键/文本扩展全部无响应且界面上看不出原因；前端同时在失焦、页面隐藏、关闭详情时主动 `set_paused(false)`。
- **输入状态复位（`Engine::reset`，钩子重装 / 前台切换触发）**：`Engine` 里那些以「按键抬起」或「时间窗」为终止条件的等待态，在「我们与物理键盘之间断过一次线」的场景下会永远等不到终止——和弦按住集合里的键再也收不到抬起（`chord_step` 判定「已在按住中」把它每次按下都吞掉 → 该键永久变哑）、已经**物理注入**的 `hold`/`oneshot`/`sticky` 键配对的抬起丢了（系统层面 Ctrl/Alt 一直按着，「修饰键粘住」）、待定的 tap-hold / 连击 / 键序列与热串缓冲会在超时后回放/展开到一个已经换了主人的窗口。复位由定时器线程巡检两条路径触发（见下条），处理口径是**注入出去的东西收回来、缓冲里的东西丢弃不回放**：注入过的键补一个 up，momentary 层退出，待定态与热串缓冲全部清空（这些键在钩子层已被吞，但复位时前台目标已变，注入到新窗口——可能是密码框——比丢掉更糟）；**锁定层保留**（用户显式切换的持续状态，与按键抬起无关）。返回「是否真的丢了东西」供调用方决定要不要留痕。
- **复位巡检（`ResetWatch`，跑在状态机定时器线程上）**：① **钩子已重装**——底座自愈看门狗修好被摘除 / 唤醒 / 解锁后的钩子时会复位 `HELD_KEYS` 等三张表，壳层这份镜像靠轮询底座单调递增的 `reinstall_count()` 跟着复位（不用回调：那要在钩子线程的消息循环里跑壳层代码，还得多一套跨线程注册；60ms 轮询足够且完全不碰钩子层）。② **前台窗口切换**——`input::foreground_window()`（Windows `GetForegroundWindow` 只读句柄，不查标题/进程名）经 `FocusTracker` **连续两轮看到同一个新窗口**才认切换：气泡/右键菜单/UAC 这类瞬态窗口只晃一轮，误判的代价是白复位一次（用户手上正凑的和弦被丢掉）；读不到句柄（锁屏、无前台窗口）一律不作数。两类触发都只在非暂停/非录制时落地（那段时间事件本来就不进状态机），且只在真的丢了状态时 `eprintln` 留痕，不进消息中心（无声兜底）。Linux 侧**前台切换**路径恒不触发（`foreground_window()` 恒 `None`，evdev 层拿不到窗口句柄，与前台类条件受限同因）；**设备拔出**会递增 `reinstall_count()` 走同一复位通道（见 §4.2）。
- **快速唤醒（`wake_double_tap` 判定 + 后台线程建窗）**：在事件决策前被动检测「双击 `Settings.wake_key` ≤400ms」（`None` = 关闭快速唤醒，是设置项的默认值），命中则唤出主窗口。只唤出窗口、不拦截按键（唤醒键常是修饰键，拦截会破坏 Alt+Tab / Alt+字母）；两次独立 down（非自动重复）判双击，其间按下其它键则取消上一次计数。**判定与建窗分开**：判定是不持有 `AppHandle` 的纯函数（结构上就不可能再在回调里建窗，顺带可单测），命中后由调用点 `std::thread::spawn` 到后台线程再 `show_main_window()`——冷启动建 WebView 要几百毫秒，同步建会把回调拖过系统的钩子超时线、钩子被摘掉（见 7.1-⑤，已落地）。
- **输入状态可视指示（`Engine::status` → `publish_status`，见 7.1-⑬）**：`Engine::status()` 是一份**只读快照**（当前激活层 id + 该层是否来自「长按锁定层」+ `hold`/`sticky`/`oneshot` 三类注入**键**；键由 `BTreeSet` 转 `Vec`，迭代顺序固定，于是两份快照可直接 `==` 比出「变了没有」）。壳层把它与配置合成指示载荷（层 id → 显示名、注入键分形态与键名、拼一句摘要），由**状态机定时器线程**每 60ms 比一次、**变了才推**——钩子回调一行都不改（在回调里推 UI 等于把输入层挂在界面上；快照是拷贝，也不把 `Engine` 锁带出去）。推送 = 换托盘提示（`set_tooltip`，空状态回到应用名）+ 按需显示/隐藏悬浮窗（**建窗那一步另起线程**，不占住落地超时回放的这条线程；机制见 `架构设计.md` §3.18）；**指示开关也参与变化比对**，否则关掉悬浮指示要等到下次状态变化才生效（锁定层能让它一直挂着）。暂停 / 录制期间**照常推**（那段时间事件不进状态机，但已经按住的层不该因为「暂停」这个动作从指示里消失）。状态变化只发生在人手上，推送频率与按键同数量级。窗口尺寸与位置由前端量完内容宽高后回报（命令 `hud_ready`）：指示窗宽度取决于内容（层名 + 几条注入键），位置又取决于宽度（贴底部居中），所以只能在渲染完之后定；`get_status_payload` 供懒创建后兜底渲染（与气泡的 `get_toast_payload` 同一套路——首次建窗时事件早于前端监听器注册）。

### 5.2 宏录制器（`Recorder`）

- 把全局键盘事件转录成 `Action` 时间线：重复 down 折叠；事件间时差 ≥20ms 补 `PauseMs`；组合键合并成一条 `Keys`，键名落盘为可读字符串。
- 录制中快捷键/改键全暂停，所有事件进时间线、放行；结束补全仍在按住的键的 keyup。

### 5.4 命令结果通知系统（消息中心）

- 命令类动作（`Cmd`/`Powershell`）触发后**一律**捕获输出（stdout/stderr/退出码）并记入消息中心（内存态，重启清空）。
- **定长上限（7.1-㉖）**：消息中心保留最近 **200** 条（超出丢最旧，`MAX_RESULTS`），单条 stdout/stderr 各截 **16KB**（`truncate_text` 落字符边界并附「输出过长，已截断」提示）——常驻数周不设限会把每条命令的全量输出都留在内存里（热串缓冲早有 64 上限，此处对齐）。读取（`get_command_results`）直接倒序产出，不再克隆整表再 reverse。
- `show_output` 开关只决定展示方式：开 → 立即按需创建/显示主窗口并弹出结果弹窗；关 → 不弹窗，托盘图标 + 应用内「消息」入口亮红点。
- 进入「消息」页即标记已读、红点熄灭；消息中心以 tab 区分每条结果（标签 `CMD · 触发键` / `PowerShell · 名称`），`‹ ›` 切换。
- 「消息」页分「命令结果 / 冲突」两个标签：冲突标签常驻展示 `get_conflicts` 的冲突清单（`Conflict.name` 标识归属快捷键、severity 着色），标签角标显示冲突数；快捷键列表顶部另有可点击、可消除的冲突气泡（点击跳到冲突标签）。
- **中止与超时的结果也进这里**（`CommandResult.kind` 为 `abort`，标签「中止」）：用户点「停止执行」后剩余动作不再执行、正在跑的命令/脚本被强杀，此时补记一条结果作为可见回应（否则用户只能靠「它不再继续了」猜）；命令/脚本因超时被强杀则在原结果里把原因写进 stderr（`〔咔哒〕执行超时（超过 N 秒），已强制终止该进程及其子进程。`）并把退出码置空（被强杀的进程退出码没有语义）。两种都走消息中心而不是弹窗：用户此刻正在做别的事。
- **任何动作失败也进这里**（`CommandResult.kind` 为 `error`）：非命令类动作（文本/按键注入、启动程序、打开文件夹、复制/剪切/删除/新建、压缩/解压、大小写转换、打开网址……）失败此前只在 stderr 留一行日志，而 release 是不带控制台的 GUI 程序，用户看到的现象只是「按了没反应」。现统一转成结果记录：标签是**哪种动作失败**（`文件操作失败` / `文本注入失败` / `脚本失败` …，tab 渲染成「文件操作失败 · 宏名」，一眼看出坏在哪一步）；「命令」一栏是**动作摘要**（用户写的动作说明优先，其次渲染动作本体，如 `删除 D:\x.txt`；变量已按本次取值代入、换行压平并按 160 字截断——同一快捷键挂多个同类动作时，只给类型分不清是哪一条）；`stderr` 是原始错误、退出码置空。`show_output` **沿用动作自身的设置**：命令/脚本开了「显示输出」，那它**连启动都没成功**这件事同样弹窗；其余动作静默记入消息中心 + 未读红点。一步失败**不中断**后续动作。
- **配置类事件也记在这里**（`CommandResult.kind` 为 `config`，标签「配置」）：启动时加载 / 自愈的告警（`trigger = 启动加载`，见 §5.6），以及运行期**外部修改**的两条——成功采纳（`trigger = 外部修改`，「检测到配置文件被外部修改，已重新加载生效」，并报出采纳后各类条目数量，让用户确认「生效的确实是我写的那份」）与内容坏掉无法解析（同样只记一次，说明磁盘内容未被改动、改好会自动重载、可用 `config.json.bak` 放弃这次外部改动）。
- 中文不乱码：Windows 下 cmd 前缀 `chcp 65001>nul & `、PowerShell 前缀 `[Console]::OutputEncoding=...` 统一 UTF-8 解码；Linux 下 CMD 走 `sh -c`。

### 5.5 软件更新（`update` 模块）

自动化动作之外的第二条「对外通道」：从 GitHub Releases 拉更新清单，验签后装新版本。实现集中在 `src-tauri/src/update.rs`（状态机与流程，与 Tauri 壳解耦、可单测），配置在 `tauri.conf.json` 的 `plugins.updater`，发布流水线在 `.github/workflows/release.yml`；完整发版步骤与密钥管理见 `docs/安装与更新-Windows.md` §2。

- **更新源与信任链**：端点 `https://github.com/chillyice/Kada/releases/latest/download/latest.json`（`releases/latest` 只解析**已发布**的 Release，故流水线默认发 draft 由人确认后再 Publish）；公钥内嵌 `plugins.updater.pubkey`（随仓库），安装包由私钥签名（只进 CI Secret/本机 `~/.tauri/`），客户端只认签名。打包侧靠 `bundle.createUpdaterArtifacts = true` 产出 `.sig`。**签名带版本号校验已开**（`plugins.updater.requireSignedVersion = true`）：安装包签名里记录其所签版本，客户端校验它与端点声明的 `version` 一致——端点响应本身不走签名，不开这项时任何人可拿旧版的有效签名冒充新版强制降级；发版 CLI 必须把版本号写进签名（本地 2.11.4 / CI `tauri-action@v0` 都会写），缺版本号的老签名包被拒（`MissingSignedVersion`）。
- **三种触发与各自的打扰等级**（`Mode::Auto` / `Manual` + 独立的 `spawn_install`）：启动后台检查（release 构建延迟 8 秒、**只在发现新版本**时弹一次气泡，其余情况包括网络失败全静默；dev 构建跳过）、托盘菜单「检查更新」/设置页按钮（无更新与出错都弹窗，发现新版本先确认再装）、设置页「下载并安装」（点击即确认）。
- **状态机在后端**：阶段 `idle`/`checking`/`up-to-date`/`available`/`downloading`/`installing`/`error` 由 Rust 持有并经 `update-status` 事件推送，前端只渲染 + `get_update_status` 兜底；`busy()`（检查/下载/安装中）挡住托盘连点造成的重复发起。
- **进度只在整数百分比变化时推事件**：下载分片回调极密集，每片都 emit 会刷爆 IPC 与前端渲染。
- **Windows 上「安装」会退出应用**（安装器限制）：NSIS 以 `passive` 模式带 `/R` 跑（小进度窗、装完自动重启）。这正是**启动检查只提示、不自动安装**的原因——自动安装等于替用户决定「现在关掉你正在用的应用」；同样地，安装失败保留当前版本、弹窗报错，不影响继续使用。
- **权限面**：更新逻辑全在 Rust 侧（`UpdaterExt`），前端**不直接调** updater，因此 capabilities 里**不开** `updater:*`（最小权限）；也不依赖 `@tauri-apps/plugin-updater`。
- **气泡复用**：`ToastPayload` 增可选的 `subtitle`——「发现新版本」这类通知用 `show_toast_note` 显示自定义副标题，不再拼「正在执行…」。

### 5.6 配置持久化（`config_io` 模块：原子写 + 损坏自愈）

配置是用户的全部劳动成果（快捷键 / 改键 / 层 / 文本扩展），所以落盘与读取按「数据安全」级别对待。实现集中在 `src-tauri/src/config_io.rs`（与 Tauri 壳解耦、带 10 条单测），`set_config` / `import_config` / 启动加载都走它。

- **写入原子**：写同目录唯一临时文件（`config.json.<pid>.<n>.tmp`）→ `fsync` → `rename` 覆盖目标（Windows 上目标被别的进程短暂持有时重试几次）。任何时刻磁盘上的 `config.json` 要么是旧的完整内容、要么是新的完整内容，不会出现崩在中间留下的半截 JSON；并发保存也不会互相踩同一份临时文件。`fsync` 不能省：只写不刷时 `rename` 可能先落盘、数据后落盘，断电后留下空文件。
- **上次良好副本**：每次保存前把现有 `config.json` 留一份 `config.json.bak`（**仅当现有内容可解析时才留**——否则损坏内容会把好备份盖掉，自愈就断了来源）。这份副本同时是手动回滚点。
- **损坏不静默清空**：解析失败先把原文件**改名留档**（`config.json.corrupt-<时间戳>`，不覆盖上一次事故的留档），再尝试用 `.bak` 自愈——恢复成功即回写主文件（真自愈，否则下次启动还是同一个坏文件）。原内容始终留在磁盘上，可人工修复后覆盖回 `config.json`。
- **告警进消息中心**：恢复 / 以空配置启动的经过（含留档路径、解析器原始报错）作为一条「配置 · 启动加载」结果在托盘建好后推给消息中心并亮红点，不再只 `eprintln` 到看不见的控制台。
- **主文件缺失**：与 `.bak` 一起缺失 = 首次启动（静默用默认配置，不打扰）；只剩 `.bak`（用户手工删了主文件 / 同步中断）→ 从备份恢复并告警，而不是给一份空配置。
- 边界口径：加载路径仍只做 `migrate()`（旧版动作迁移）**不做** `sanitize_config()`——加载时静默丢条目同样属于「悄悄改用户配置」；逐条清洗只在保存 / 导入路径做。
- **替换导入前先留档**（`config_io::archive_copy`）：`replace` 导入是这个应用里**唯一能一次换掉整份配置**的操作，所以覆盖前把现有配置**复制**一份成 `config.json.pre-import-<时间戳>`（同一秒重复导入加序号，绝不覆盖上一份）。与损坏留档的区别是**复制而非改名**——主文件还要继续用（随后才被导入内容覆盖）；内容是原样快照，不做解析校验（要的就是「覆盖前磁盘上是什么」这个事实）。留档是尽力而为：失败不中断导入，但会在导入结果里说明（此时 `config_io::save` 留下的 `.bak` 仍是回滚点）。注意 `.bak` 会被**下一次保存**覆盖，带名字的留档不会。
- **导入的两种方式**：`merge`（默认推荐）与 `replace`。`replace` 就是原来的行为（整份覆盖，含 `settings`）；`merge` 的口径在 `kada-core` 的 `merge_configs`（纯函数、可单测），三条铁律：
  - **只增不删**：现有条目一条不动——不改写、不删除，也**不跑清洗**（清洗会顺手丢掉用户手里那些不合规的老条目，那就成了「导入顺便帮你删东西」）。
  - **不制造新冲突**：改键按 `from`、文本扩展按 `trigger`、快捷键按**触发键有交集**判定「同一条」，撞车时保留现有的、跳过导入的那条并**逐条报出**；因此重复导入同一份文件是幂等的，也永远不会因为导入而冒出一堆用户没配过的红冲突。目录 / 层按 `id` 去重（保留现有的名字）。
  - **设置不合并**：`settings`（开机自启 / 快速唤醒键 / 超时 / 暂停）保留本机现值——导入别人分享的配置不该悄悄改掉本机开机自启。要连设置一起换就用 `replace`。
  - 引用完整性：先并目录与层、再并条目，所以导入的条目引用的 `folder` / `layer`（含改键的 `hold_layer` / `lock_layer`）一定已经存在，不会出现「层没进来、改键整条作废」。
- **导入结果要能逐条复盘**：`import_config` 返回 `notes`（被跳过的条目 + 被清洗掉的坏条目，逐条带名称 / 触发键），UI 用结果弹窗列出来。原先只回一个「忽略了几处」的计数——用户根本查不出是哪条没进来，也分不清「合并跳过」与「解析失败」。
- **外部修改监听**（`config_watch` 模块：运行期「发现外部改动 → 采纳」，见规划 7.1-⑩）：配置原先只在启动时读一次，手改 JSON / 用 `.bak` 恢复备份 / 同步客户端在别处落盘都不生效，而且下一个应用内保存会把整份内存配置写回去、**悄悄盖掉外部改动**。现在壳层另起一条巡检线程（每 `POLL_MS` = 1 秒），四条口径：
  - **按内容比对，不按 `mtime`**：整份读进来算指纹（配置只有几 KB）。`mtime` 粒度粗（FAT 系 2 秒）、同步客户端可能保留原时间戳、还会被「同一秒内改两次」骗过去。
  - **语义相同不算改动**：解析出来与内存里那份相等就静默放过（重新排版、`migrate()` 补字段都会让字节不同而配置相同），免得红点白闪一次。
  - **能解析就采纳**：替换内存配置（`get_config` 与钩子查表随即反映新内容，这是「外部修改生效」的全部意义）→ 整份换掉 `Engine` 的时序状态（与旧配置绑定的按住层 / 待定和弦 / 注入中的修饰键都该作废，沿用 `Engine::reset` 那套口径）→ 开机自启跟着系统同步一次 → 记一条「配置 · 外部修改」进消息中心（见 §5.4）→ 广播 `config-changed` 事件让界面重绘。
  - **解析不动就原地不动**：外部内容坏了（编辑器写到一半）**不采纳、不清理、不回写**，只在同一份坏内容上提示一次（`reported` 记账，改好后指纹变了自然重新解析）。这条是刻意与启动路径分家的：`load` 的损坏自愈（留档 + 从 `.bak` 回写）在启动时是对的，搬到运行期就变成「用户改到一半，监听把文件挪走、拿旧备份盖回来」；所以监听走新增的**只读入口** `config_io::read_only`（同样解析，但一个字节都不写盘）。文件消失（用户删了主文件）也保持现状——既没内容可采纳，也不该把用户正在用的配置清掉；等它再出现（恢复备份 / 同步补回）即按改动采纳。
  - **自己的写入要销账**：`set_config` / `import_config` 写完盘把新内容认成已知基线（`adopt_own_write`），而且「写盘 + 改内存 + 销账」**同持 `cfg_watch` 一把锁**——否则巡检线程可能插在中间，把应用自己刚写的配置当成外部修改再加载一遍。
  - 测试：`config_watch` 7 条（基线静默 / 外部改动报一次后采纳 / 自己的写入不算外部修改 / 走 `config_io::save` 的真实时序 / 只换排版不算改动 / 坏内容只提示一次且磁盘未被动过 / 文件消失保持现状再出现即采纳）。
- **手动重载**（托盘菜单「重载配置」，见 7.1-㉗）：与巡检同口径——`config_io::read_only`「能解析才采纳、解析不动就一个字节都不碰磁盘」；区别是用户主动触发，**无论结果如何都记一条「配置 · 重载配置」进消息中心**（成功报快捷键 / 改键 / 文本扩展 / 层条数，失败报「当前配置保持不变」），否则点了像没反应。采纳时与外部改动走同一条复位通道（`cfg_stale` 整份换 `Engine` 时序状态 + 同步开机自启），并广播 **`config-changed`**（不是 `config-updated`）——内存配置真被整份换掉，界面若有未保存草稿须按「外部改动」流程问用户。内存配置与磁盘内容相等时只销账（`adopt_own_write`）并提示「已是最新」。

### 5.7 动作执行边界（超时与中止）

一次触发就是一条独立的动作链（`fire` → 后台线程 → `kada_actions::run_actions`）。链里的命令与脚本是**外部进程**，它们能挂住（等输入、死循环、弹了个看不见的确认框），所以执行必须有边界——原来的 `Command::output()` 是无限等待，脚本一挂就永久占住这条触发的执行线程（后续动作永不执行、线程也收不回来）。实现集中在 `crates/kada-actions/`（`run_with_limits` + `abort` 模块，均与 Tauri 无关）。

- **超时可配**：`Settings.action_timeout_ms`（设置页「动作超时」，按秒录入，`0` = 不限时），缺字段取默认 30 秒——老配置（写于本字段出现之前）也要拿到保护，所以 serde 缺省用显式默认值而不是零值。超时值随触发一并传给 `run_actions`（`RunOptions`），调用点已持有配置读锁，不再进线程里二次加锁。
- **限时等待 + 边跑边读**：子进程用 `Stdio::piped()` 起，两个管道交给读线程，主线程每 `WAIT_POLL_MS`（20ms）`try_wait()` 判超时/中止。**管道必须边跑边读**：子进程输出超过管道缓冲（Windows 约 4~64KB）而没人读时它写阻塞、我们等它退出，双方互等，超时判定也就永远等不到。
- **杀整棵树**：`Child::kill` 只杀直接子进程，而我们跑的是 `cmd /C <临时批处理>`（Windows）、`powershell -Command`、`sh -c`——真正干活的是孙进程（脚本本体、被启动的程序）。不杀树的话命令「看起来」结束了、脚本还在后台跑，而且它占着 stdout 管道，连读线程都不会结束。两侧各自的办法（见 7.1-㊴）：Windows 用 `taskkill /PID <pid> /T /F` 遍历进程树（失败退回 `kill()`）；Linux / macOS 在 spawn 时 `process_group(0)` 让子进程自成进程组，超时 / 中止时 `kill(-pgid)` 一次打整组（失败退回 `kill()`）。残余天花板：unix 下孙进程若自己 `setsid`（nohup 守护、服务化）就脱离了组，追不到。
- **中止开关是代数计数器**（`kada_actions::abort`）：`request()` 只递增代数，每轮执行开始时快照一次，两者不等即「这一轮被叫停了」。用代数而不是布尔量，是因为布尔量必须「新一轮开始时清零」，而清零与用户按下停止之间有竞态——停止可能落在清零之前被下一轮吞掉（点了停止没反应），不清零则一次停止会让之后**所有**触发一启动就自杀。中止发生在：动作链每一步执行前（剩余动作不再执行，避免继续注入按键/启动程序）、`run_with_limits` 的 20ms 轮询（正在跑的进程立刻被杀）、`PauseMs`（切小片睡，几十秒的暂停也停得下来）、`App::Status` 的等待重试循环。
- **反馈不假装成功**：`abort_actions` 返回请求时的「正在执行」链数量（`abort::running()`，由 `RunGuard` 在动作链入口自增减——链里有 `?` 提前返回，手工加减必然漏），前端据此提示「已请求停止（N 条正在执行）」或「当前没有正在执行的动作」；真的被中止的链会补记一条「中止」结果进消息中心（见 §5.4）。
- **测试**：`kada-actions` 从 0 测试补到 9 条——正常命令捕获输出、超时强杀并标注原因、**超时杀掉整棵进程树**（挂住的脚本 3 秒后该建标记文件，被杀则不会出现）、中止杀掉运行中的进程、中止停止剩余动作并记一条结果、上一次的中止不影响新开始的执行，以及 `abort` 模块的代数语义与 `RunGuard` 计数归零。7.1-㊴ 落地时把该用例的 unix 分支改成**孙进程建标记**（`sh -c 'sleep 3; touch …' & wait`）：原形状的标记由直接子进程（外层 `sh`）来建，只杀 `sh` 同样建不出来——「没建出文件」区分不了杀没杀到树，是一条假阳性用例（有对照组才能发现，见 `人工验证清单.md` §6 的同款提醒）。

### 5.8 快捷键提示框（常显速查浮窗，见 7.1-㊳）

- 独立窗口 `index.html#hints`（懒创建，`decorations(false)` / `transparent` / `skip_taskbar` / `always_on_top` / `focusable(false)` / `zoom_hotkeys_enabled(false)`）。**必须 `focusable(false)`**（同 §5.1 状态指示窗那条铁律：常显窗一旦能被激活就成了前台窗口，前台条件全读错、`ResetWatch` 误判「前台切换」复位输入状态）；**与 toast / hud 的关键差别：不能 `set_ignore_cursor_events(true)`**——拖动、滚轮、关闭按钮都靠鼠标事件（`WS_EX_NOACTIVATE` 只挡激活、不挡鼠标消息，已真机证实）。`zoom_hotkeys_enabled(false)` 是因为 Chromium 默认把 Ctrl+wheel 当浏览器缩放，会和「调透明度」打架。
- 内容由前端取 `get_config` 渲染：按层分组列出所有**已启用**的快捷键（基础层在最上、层按配置顺序；层内条目指向已不存在的层时回落基础层），一行 = 触发键 kbd 片段 + 名称/描述；停用条目不列（提示框回答的是「现在能按什么」）。渲染完量内容宽高调 `hints_ready`（同 `hud_ready` 套路）；列表上限按**屏幕**可用高度算，**不能按 `100vh`**——窗口高度正是要量出来的东西，用 vh 做上限会形成「量出高度→撑大窗口→上限变高」的自增长循环。
- 外观与位置持久化在 `Settings.hints`：滚轮调字号（±5%，60~220）、Ctrl+滚轮调不透明度（±4%，20~100），前端就地应用、400ms 节流 `hints_prefs` 落盘；拖标题栏用 pointer events + 指针捕获自己搬窗口（`hints_move` 不落盘，松手 `hints_commit` 记一次）。首摆位置 = 保存坐标；不在任何显示器工作区（配置跨平台同步，双屏拖到副屏再同步到单屏就落在屏外）→ 回主显示器工作区右侧垂直居中。
- 可见性有四个入口（窗口 × / 设置页勾选 / 托盘菜单勾选项 / 替换导入），无论从哪进来都统一走 `apply_hints_visible` 对齐：建窗或隐藏 + 抹平托盘勾选 + 广播 `hints-state`；关掉只置 `visible=false`，位置与外观留着。
- **应用内配置写盘广播 `config-updated`**（`set_config` / `import_config` / `save_settings_patch` 都发）：提示框窗口据它重画列表，主界面只取 `settings.hints` 跟上（不整份 `syncSettings`，免得盖掉用户正在输入的字段）。与 `config-changed`（**外部**改动，界面有未保存草稿要问用户）语义不同，不可混用；提示框自己的小改动走 `save_settings_patch`（`cfg_watch` 锁 + 原子写 + `adopt_own_write`，与 `set_config` 同口径），**不回传整份配置**——那个窗口手上没有、也不该有用户正在编辑的草稿。

## 6. UI（ui，kada-ui）

Vanilla TypeScript + Vite，深色主题。左栏图标导航四个页面：

- **快捷键**：列表按目录树分组展示（多层嵌套、按深度缩进、折叠/展开、拖拽排序、三点菜单「新建子目录/重命名/粘贴到/删除」、条目复制/剪切/粘贴）；编辑器支持录入组合键与录入序列（`set_paused` 暂停防自触发；组合键 Esc 取消，序列逐键累积空格拼接实时预览、Enter 提交 / Esc 取消）、动作类型切换（文本 / 命令 / 脚本 / 应用 / 打开网址 / 文件动作 / 按键组合 / 鼠标操作 / 延迟 / 条件判断）、宏录制（`start_record`/`stop_record` 落成动作时间线）、所属层下拉、**触发条件（可选，见下）**。文本动作带「原样 / 转大写 / 转小写」模式；命令动作统一 CMD/PowerShell（Shell 下拉）并带「弹窗显示结果」开关 + 存为变量；打开网址动作输入 URL（支持 `{变量名}` 占位符，用系统默认浏览器打开）；文件动作带子操作下拉（含 新建文件夹/解压/打开文件夹）+ 文件/目录浏览，应用动作带程序浏览 + 参数，条件判断支持递归嵌套 then/otherwise 分支，条件类型含路径/变量/时间/前台应用/窗口标题/设备（前台进程名支持 `*`/`?` 通配或子串匹配，设备名同款匹配；设备条件仅 Linux 生效）。动作列表以**流程管线视图**呈现（可视化编排）：`⚡ 触发（附触发键摘要）→ 序号节点卡片 → ✓ 执行完成` 的时间线脊柱；十类动作各配主题色（卡片左边框 / 脊柱圆点 / 类型名 / 图标底色一致）；卡片头部带变量流向标签（`⇒ var` = 该动作写出变量，`{var}` = 引用变量，只扫承载占位符的字符串字段、排除 `{date}/{time}/{clipboard}`，最多显示 3 个）；条件判断渲染为 `✓ 满足条件时执行`（绿泳道）/ `✗ 否则执行`（灰泳道）双分支，空分支显示虚线占位提示；拖拽排序 / 拖入拖出分支、收起态（类型名+描述+变量标签）、展开态三行（标题 / 类型筛选 / 输入）保留。编辑器排布：描述与所属层并排栅格，内容限宽 880px。**触发条件（`when`）编辑器**（见 7.1-㊶，快捷键与改键共用 `renderWhenEditor`）：一个「无条件（始终触发）/ 条件类型」下拉 + 选中条件后的字段，与 `If` 动作的条件共用同一套字段渲染（`conditionFields`）；只列触发时可求值的类型（`Equals`/`NotEquals` 依赖变量值、恒不成立故不列）。
- **改键**：列表展示（开关 / from 下拉 / → / 摘要 / 删除）；编辑器扩成「普通改键（改为）+ tap-hold（短按/双击/三击/长按 + 阈值滑块）+ 长按进入层 / 长按锁定层（切层键两形态，互斥）+ 单次键/粘滞键（值域**任意键**，用与其它字段同一套全键下拉）」+ 所属层下拉 + **触发条件（可选，同上）**，键名下拉对齐 `kada-core` 的 `key_name`；按所选形态条件显隐（选单次/粘滞时隐藏短按/双击/三击/长按/切层/改为，选 tap-hold 时才显示双击/三击）；短按/长按/切层可组合（都空则退化为普通改键）。全键下拉对「手写但不在表里的值」（`Escape`/`Control` 这类规范名与表里的 `Esc`/`Ctrl` 是别名关系）会补一个选项兜住，否则下拉一片空白、一保存就把用户写的值丢掉。和弦录入支持**按住修饰键**录入为 `Ctrl+F&J`（修饰键写在第一个成员上，等价于「凑齐那一刻按着它」）。
- **文本扩展**：列表（开关 / 触发词 / → / 替换文本 / 删除）+ 编辑（触发词、替换文本，替换支持 `{date}`/`{time}`/`{clipboard}` 动态片段提示）；触发词非空校验。
- **消息**：命令结果中心 + 冲突清单（见 §5.4），顶层「命令结果 / 冲突」两个标签切换，tab 条 + `‹ ›` 切换 + 清空按钮 + 未读红点徽标；`show_output` 开的结果弹窗复用模态样式；头部另有「停止执行」（`abort_actions`，见 §5.7）——中止正在跑的动作链，点击后按后端返回的「正在执行」数量提示结果。
- **设置**：开机自启 / 暂停所有快捷键 / 启动后最小化到托盘 / 快速唤醒键 / **动作超时**（按秒录入，`0` = 不限时，默认 30 秒，见 §5.7）/ **序列等待**与**和弦等待**（按毫秒录入，`0` = 不限时，默认各 1000 毫秒，见 §5.1 与 7.1-⑫；输入框下方文案说明两者分别是什么、超时的后果是「被吞掉的键原样补回」，因为 1000 这种亚秒粒度用秒表达不了）/ **显示输入状态悬浮指示**（开关，默认开，见下条与 7.1-⑬）/ 键位层（新建/重命名/删除，删除时清空归属该层的快捷键与改键）/ 导出导入配置。／**文本注入**（剪贴板粘贴 / 逐字直发，缺字段按剪贴板，见 §4.4 与 7.1-㉒）／**显示快捷键提示框**（开关，**默认关**——常挂屏幕的浮层不请自来比找不到入口更烦人，见下条与 7.1-㊳）
- **输入状态悬浮指示与托盘提示**（见 7.1-⑬）：`index.html#hud` 是一个独立的透明小窗（底部居中、点击穿透、永不接焦点），只在**有东西生效**时出现：一条 `层 · <层名>（按住/锁定）` 胶囊 + 每个注入中的键一条胶囊，用词与配色区分三种释放时机——**按住**（跟着切层/改键键松开，蓝）、**粘滞**（再击该键解锁，绿）、**单次**（下一个非修饰键后释放，琥珀）；键名与触发键同一套用词（`Ctrl`/`Shift`/`A`/`MouseBack`…），值域是任意键（见 7.1-⑭）。长按锁定层会让指示一直挂着，这是有意的：锁定层生效期间基础层按键会被遮蔽，「看不见状态」正是最容易被误判成「按键失灵」的时候。关掉设置里的开关就只剩托盘提示（托盘图标悬停可见同一句摘要，没东西生效时是应用名）。页面可纯浏览器直开预览（演示模式给一份「层 + 三种注入键」的样例载荷）。
- **快捷键提示框**（见 7.1-㊳）：`index.html#hints` 是一块**常显**的速查小窗（置顶、不接焦点、可拖动可关闭），把所有**已启用**的快捷键按层列出来（基础层在最上）；拖标题栏移动、滚轮调大小、Ctrl+滚轮调透明度、Shift+滚轮滚长列表；点 × 关闭后，设置页重新勾选或托盘菜单「快捷键提示」都能再打开。位置、字号、透明度随配置保存，下次启动还在原地；内容变化（应用内保存走 `config-updated`、外部改动走 `config-changed`）实时重画。
- **危险操作确认**（见 7.1-⑨）：删除**目录 / 层 / 快捷键 / 改键 / 文本扩展**一律先弹确认框（`ask()`，`kind: "warning"`）——原先只有「删除目录 / 删除层」问一句，同为破坏性操作的单条删除却是点了就没了，同类实体的安全级别不一致。文案带上**要删的是哪一条**（快捷键用名称、无名时退回触发键；改键用 `原键 → 摘要`；文本扩展用触发词）与后果：正在编辑的那条若还有未保存改动，会明说「会一并丢弃」；删除目录会报出**波及多少条快捷键**。**未落盘的新增项不弹**——删除它等同「取消」，没有已保存的内容会丢。
- **导入方式选择与结果明细**（见 7.1-⑨）：点「导入配置」选好文件后先弹**合并 / 替换**选择框（遮罩与 Esc = 取消，绝不替用户选一种），说明两种方式各自的后果（合并只新增、替换含设置整份覆盖并留档）；导入完成后弹**结果弹窗**：「新增 N 条、跳过 / 忽略 M 条」+ 逐条明细（哪条被跳过、为什么；被清洗掉的坏条目也在这），替换导入还给出**导入前配置的留档路径**（见 §5.6）。此前点一下就直接整份替换，提示文案只说「清洗无效项」，既没说会替换，也只报个数、查不出是哪条没进来。
- **未保存改动守卫**（快捷键 / 改键 / 文本扩展三个编辑页共用，见 7.1-⑧）：编辑只改**草稿副本**（`openDetail` 时深拷贝 / 新建模板），改动是否已落盘靠「与基线比对」判定——`draftBaseline` 记下打开编辑页（或上次保存）那一刻的**草稿签名**（`JSON.stringify`，并带上「只在保存时才读回草稿」的输入框：描述 / 所属层、改键的原键与长按阈值、文本扩展的触发词与替换文本）。有未保存改动时：动作行常驻黄色「● 未保存」标记（标记放动作行、不放标题——标题就是行内编辑的名称输入框，改文案会让光标跳）、「撤销改动」按钮由禁用转为可用（还原到基线内容并留在编辑页）；此时**点另一行 / 切页 / 点「取消」或「×」**都会先弹三态确认框「**保存并离开 / 放弃改动 / 继续编辑**」（遮罩与 Esc = 继续编辑）。「保存并离开」只在**真的落盘**后才放行：保存失败、或改键没设任何输出被判无效，都停在编辑页并把原因 toast 出来。保存落盘的是**草稿的副本**（`cfg` 与草稿从此各持一份），并把列表行的「启用」开关现值带过去——编辑页没有这个控件，否则用户刚点的开关会被草稿里的旧值悄悄盖回去。窗口关闭不设守卫：关窗只是 `hide()`（托盘常驻），WebView 与草稿都还在，没有可丢的东西。
- **外部修改后的界面刷新**（见 7.1-⑩）：后端监听配置文件时若发现被外部改动（手改 JSON / 恢复备份 / 同步落盘），采纳后广播 `config-changed` 带上新配置，前端换成它并重绘（列表 / 设置项 / 冲突检测一起跟），toast 一句「已重新加载」。触达编辑页时算一次「离开当前编辑上下文」，所以与 leave 守卫同一套口径：**有未保存改动**先弹两态框「**加载新配置** / **保留我的改动（下次保存会覆盖外部改动）**」——两个按钮各自写明后果，绝不静默丢掉用户正在改的东西（选保留则界面与内存都不动，消息中心里留着那条外部改动记录）；只是**打开了编辑页却没改**（干净草稿）就不问，直接关掉它——什么都不会丢，而留着反而危险：外部内容里的同一下标可能已经是另一条，草稿一保存就写到别人身上去。
- **纯浏览器演示模式**（`ui/src/mock.ts`，见 7.1 P2-⑯）：没有 Tauri 壳时（直接开浏览器，或 `index.html#hud` / `#hints` / `#toast` 独立窗）注入一套模拟 IPC——配置读写、冲突检测、命令结果、录制、文件对话框、更新状态、窗口事件都有桩，界面能离线跑起来调布局与样式。桩是「诚实」的：冲突恒空、录制返回空数组、文件对话框一律取消、更新检查不推事件，所以纯浏览器验收时别把「没数据」当成「功能坏了」，真机行为一律以 §1~§5 为准。
