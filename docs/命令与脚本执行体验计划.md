**读代码前先记住四条边界**（踩过的坑，别重犯）：

1. **Kada 不是 AHK**：本次只改善「命令 / 外部脚本」这一条逃生舱，不引入图灵完备脚本宿主，不推翻图形化动作链。
2. **默认语义不变**：一个动作失败**不中断**后续动作；`on_error: stop` 是可选开关，缺字段 = 继续。
3. **命令 / 脚本仍归 `automation` feature**：基础版（`--no-default-features`）必须照常编译，字段与实现都要在门控内。
4. **执行永远在 `fire` 的后台线程**：不许进钩子回调，不许在回调里做 IO / 等待 / 建窗。

## 2. 目标与非目标

**目标**：让脚本作者在三件事上不用猜——

- **跑得对**：工作目录、参数、解释器、PATH、超时、哪些退出码算成功，都能在编辑器里说清楚。
- **看得见**：动作一开始就显示「执行中」；结束后有完整输出、退出码、耗时；长输出能复制 / 打开完整日志。
- **接得下**：命令结果能稳定写进变量（返回值优先）、脚本能拿到触发上下文；失败时可以选择停下，而不是继续跑后面的危险动作。

**非目标**（本次不做，别顺手扩）：

- 不做 shell 词法解析 / 引号展开 / 管道语法高亮；`args` 是 argv，不是一整条命令行。
- 不做常驻进程守护、端口管理、日志轮转服务；`wait=false` 只表示「启动后不管」。
- 不把内置 Rhai 脚本改成可读文件 / 联网 / 起进程；沙箱边界见 `crates/kada-actions/src/script.rs` 顶部注释。
- 不新增云同步 / 远程执行 / 结果上传。
- 不改 `Engine`、钩子线程、注入链路；这些是另一条稳定性红线。

## 4. 数据模型（先定形状，别边写边改）

### 4.1 配置形状

`Command`（批次一字段标 `①`，批次二标 `②`）：

```json
{
  "type": "command",
  "shell": "cmd",
  "command": "python -V",
  "working_dir": "D:\\work",          // ① 空 = 继承 Kada cwd；支持 {变量} 与 ~
  "timeout_ms": 5000,                  // ① 缺省 = 跟 Settings.action_timeout_ms；0 = 不限时
  "ok_exit_codes": [0, 3010],          // ① 空/缺省 = [0]
  "show_output": false,
  "hide_window": false,
  "var": "",
  "wait": true,                        // ② 缺省 = true；false = 启动后不管
  "on_error": "continue",              // ② 缺省 = continue；"stop" = 本步失败后停整条链
  "description": null
}
```

`Script`（在 `Command` 的基础上多三个字段）：

```json
{
  "type": "script",
  "path": "D:\\scripts\\backup.py",
  "interpreter": "python",
  "interpreter_args": ["-u"],          // ① 放在脚本路径之前
  "args": ["--dest", "{drive}:\\backup"], // ① 放在脚本路径之后；逐项 {变量} 替换
  "working_dir": "D:\\work",          // ①
  "timeout_ms": 5000,                  // ①
  "ok_exit_codes": [0],                // ①
  "show_output": false,
  "hide_window": false,
  "var": "",
  "wait": true,                        // ②
  "on_error": "continue",              // ②
  "description": null
}
```

### 4.2 Serde 与兼容

- 所有新字段都 `#[serde(default)]`，老配置缺字段 = 新默认值；**不加版本号、不改顶层结构**。
- `working_dir` / `args` / `interpreter_args` / `ok_exit_codes` 为空时 `skip_serializing_if`，避免把默认值写进每一份配置。
- `timeout_ms: Option<u64>`：`None` = 跟全局，`Some(0)` = 不限时；序列化时 `None` 不落盘。
- `wait: bool`：`#[serde(default = "default_true", skip_serializing_if = "is_true")]`，缺字段 = 等。
- `on_error: OnError`：`#[serde(rename_all = "snake_case")]`，缺省 `Continue`，`Continue` 不落盘。
- `Config::migrate` 把旧 `Cmd` / `Powershell` 折成 `Command` 时，新字段一律填默认值（`working_dir: String::new()`、`timeout_ms: None`、`ok_exit_codes: vec![]`、`wait: true`、`on_error: Continue`）。
- `Action::validate()` 只做静态校验：`timeout_ms` 无范围限制（0 合法）、`ok_exit_codes` 逐项在 `i32` 内、`args` 不校验存在性；**工作目录不存在不在保存时拦**（移动硬盘 / 网络盘可能稍后才挂上），执行时报清楚。
- 所有构造点（`kada-core` 测试、`kada-actions` 测试、壳层 `CommandResult` 组装、`ui/src/main.ts` 类型与 `newAction`）一次性补齐；不要用「先留个 TODO 字段」。

### 4.3 批次二才动的字段

`show_output` 的三态、`wait`、`on_error` 都在批次二加。**别在批次一提前塞**：没实现的字段会变成永远不生效的配置，比没有更糟。

- `show_output` 三态建议用 `#[serde(untagged)] enum ShowOutput { Bool(bool), Mode(ShowOutputMode) }`：老配置的 `true` / `false` 照旧读，新模式序列化成 `"always"` / `"on_error"` / `"never"`；`CommandResult.show_output` 仍是 `bool`（线格式不变）。
- 退路（如果构造点改动太大）：保留 `show_output: bool`，另加 `show_output_on_error: bool`。两条都能接受，但**只选一条**，别两套并存。

### 5.1 CS-01 工作目录

- 新增小助手（模块名落地时定；也可以直接放 `crates/kada-actions/src/lib.rs`，别为几个助手单开很多层）：
  - `expand_home(&str) -> PathBuf`：`~` / `~/` 用 `HOME`（Unix）或 `USERPROFILE`（Windows）展开；不做 `$VAR` / `%VAR%` 展开（那是 shell 的事）。
  - `resolve_working_dir(&str, vars) -> Result<Option<PathBuf>, String>`：先 `substitute_vars`、再 `expand_home`；空 = `None`；相对路径按 `std::env::current_dir()` 拼；`is_dir()` 不成立返回中文错误。
- `run_cmd` / `run_script` 都接受 `Option<&Path>`；`std::process::Command::current_dir(dir)`。
- **Script 的 `path` 仍按 Kada cwd 解析**（相对路径先转绝对），不跟 `working_dir` 走——`path` 是「配置里指到哪个文件」，`working_dir` 是「脚本运行时把哪个目录当 cwd」，两者混在一起会让改工作目录顺手改坏脚本定位。执行前检查 `path` 存在且是文件，错误文案带完整路径。
- `KADA_WORKDIR` = 实际工作目录（未设则 Kada cwd 的绝对路径）。
- 测试：临时目录里 `cd` / `pwd` 写到文件；`working_dir` 不存在 → `Err` 含路径；`~` 展开（Windows 用 `USERPROFILE`）。

### 5.2 CS-02 PATH / 解释器 / 环境变量

- `resolve_program(name) -> PathBuf`：
  - 空 → 错误；`~` 展开；绝对路径或带分隔符 → 原样（存在性由 spawn 报错，解释器路径额外检查）。
  - 裸名：先查当前 `PATH`，再查补充目录；Windows 按 `PATHEXT`（`.COM;.EXE;.BAT;.CMD`）补扩展名，Unix 检查可执行位。
  - 补充目录：macOS `/opt/homebrew/bin`、`/usr/local/bin`、`/opt/local/bin`、`/usr/bin`、`/bin`、`/usr/sbin`、`/sbin`；Linux `/usr/local/bin`、`/usr/bin`、`/bin`、`/usr/local/sbin`、`/usr/sbin`、`/sbin`、`/snap/bin`、`$HOME/.local/bin`；Windows 不加（PATH 通常够）。
  - 兜底：`python` ↔ `python3` 互为候选（只在裸名时）；仍找不到就回原名，让系统错误原样露出。
- `run_script` 用 `resolve_program` 解析 `interpreter`；`interpreter` 为空时，`path` 也走同一解析（裸名才查 PATH）。
- 子进程环境统一由 `apply_child_env` 设置：
  - `KADA_TRIGGER`（触发组合）、`KADA_NAME`（快捷键名）、`KADA_VARS`（变量表 JSON，沿用 `vars_to_json`）、`KADA_OS`（`windows` / `macos` / `linux`）、`KADA_WORKDIR`。
  - `PATH` = 当前 PATH + 补充目录（去重、保持顺序）；**不改 Kada 自己的进程环境**。
- `run_cmd` 也要拿到 `vars`（`Action::Command` 分支本来就有），把环境变量补上；`Command` 与 `Script` 从此同一套。内部 helper 用 `Option<&Vars>`：`close_program` / 输入框这类内部命令传 `None`，不注入 `KADA_*`（它们不是用户脚本）。
- **不往用户变量表塞 `_kada_*`**：环境变量是脚本的天然接口；保留变量会和 `set_var` / `Ask` / 卡带合并抢命名空间。若以后确实需要 `{_kada_trigger}` 这种占位符，单独立项，别在本次顺手加。
- 测试：临时目录放一个假解释器（Windows `.bat` / Unix 可执行脚本），从 `PATH` 之外调用；`KADA_*` 由脚本写到文件后断言；`PATH` 补充目录不影响父进程 `std::env::var("PATH")`。

### 5.4 CS-04 每动作超时

- `Ctx.timeout` 仍是全局；`run_action` 在命令 / 脚本分支算：
  ```
  let timeout = timeout_ms.map(Duration::from_millis).unwrap_or(ctx.timeout);
  run_with_deadline(&mut cmd, label, ctx, timeout)
  ```
- `Some(0)` → `Duration::ZERO` = 不限时（与全局 `0` 同义）；缺省 → `ctx.timeout`。
- 超时原因仍写 stderr 前缀 `〔咔哒〕执行超时（超过 N 秒）…`，退出码置空、杀整棵树；行为与现在完全一致，只是数值来源变了。
- 测试：全局 10 秒、动作 300ms 的 30 秒 sleep → 300ms 左右被杀；全局 300ms、动作 0 的 1 秒 sleep → 正常结束。

### 5.5 CS-05 `ok_exit_codes`

- 字段 `ok_exit_codes: Vec<i32>`；空 = `[0]`。
- 抽 `fn exit_ok(action: &Action, code: Option<i32>) -> bool`：`None`（没跑起来 / 被强杀）→ false；`Some(c)` → `codes.contains(&c)`。
- `run_chain` 的 `failed` 改成：`!exit_ok(action, result.exit_code) || result.stderr.starts_with("〔咔哒〕")`。
  - 被强杀时 `exit_code = None`，仍然失败；`〔咔哒〕` 前缀仍然失败（防用户命令自己打印这个前缀——这是既有的小坑，本次不拆）。
- UI：逗号分隔输入，解析成 `i32` 列表；空 = `[0]`；非法数字 / 超范围保存时提示。帮助文案给两个真实例子：`robocopy` 的 `1`（有文件复制成功）、MSI 的 `3010`（需要重启）。
- 测试：退出 1 + `[0]` → error；退出 1 + `[0,1]` → ok；退出 1 + 空（默认）→ error；被强杀 + `[0,1]` → 仍 error。

### 5.6 CS-06 修 `ScriptOutput::value()`

- `ScriptOutput` 加 `ret: Option<String>`：
  - `None` = 脚本返回 `()`；`Some(s)` = 返回了值（`s` 可以是空串）。
  - `stdout` 仍是「`print` 行 + 返回值」的展示文本，保持消息中心现状。
  - `value()`：`ret.clone().unwrap_or_else(|| self.stdout.clone())`。
- 这样 `print("debug"); 42` 的 `var` 得到 `42`，不是 `debug\n42`；`print("debug")` 仍得到 `debug`；返回 `""` 得到空串（不会退回 prints）。
- 错误分支 `ret: None`，`value()` 仍是 prints（失败时不写变量，`run_action` 已有 `if !out.failed` 闸门）。
- 测试补三条：返回值优先 / 无返回值用 prints / 返回空串与无返回值的区别；现有 `print_and_return_are_both_kept` 保留（它验的是 `stdout`）。
- **这是行为变更**：以前把 `print` + 返回值一起塞进变量的配置会变。归档里写明，并在 `docs/变量提取与引用指南.md` 加一句「`var` 只拿返回值；调试信息看消息中心」。

### 5.7 CS-07 动作开始即上报 `running`

- `step_begin` 的 `status` 从 `"ok"` 改成 `"running"`，`end_ms = start_ms`。
- `run_chain` 在每个动作开始执行前 `rep.on_step(step.clone())`；`Group` / `If` / `Parallel` 也一样（先报容器在跑，再报成员）。
  - `If`：先算 `branch` 再报，界面能立刻显示走了哪条。
  - `Parallel`：先报父步骤，再 `run_parallel`；成员步骤在 `run_parallel` 里是**本地收集**，组汇合后才提交（现有结构），所以并形成员的 `running` 不会实时刷到消息页——父步骤的 `running` 会。别为这条去改并行收集架构。
- 执行结束仍用同一个 `id` 再报一次最终状态（`ok` / `error` / `abort`）；壳层 `add_step` 改成按 `id` upsert：
  ```
  if let Some(existing) = run.steps.iter_mut().find(|s| s.id == step.id) {
      *existing = step;
  } else {
      run.steps.push(step);
  }
  ```
  `run.duration_ms` / `run.status` 的逻辑保持：`error` 步把 `running` 记录标成 `error`，`abort` 优先。
- 注意 `MAX_RUN_STEPS` 的裁剪：极端长链里正在跑的步骤可能被裁掉，最终 upsert 找不到就 push 一条完整结果（时间线少一个起点，但不丢结论）。这条记进 §9，不在本批加复杂度。

### 6.3 CS-12 `wait=false`

- `wait` 缺省 true；false 时：
  - `stdout` / `stderr` 设 `Stdio::null()`（不能留管道没人读）；spawn 后起一个 reaper 线程 `child.wait()`，只负责回收 / 清理临时文件。
  - `CmdOutput.detached = true`，`stdout` / `stderr` 空、`exit_code = None`；`CommandResult` / `ActionStep` 加 `detached: bool`（UI 显示「已启动，不等待完成；未捕获输出」）。**`detached` 不参与退出码判定**（否则 `None` 会被 `exit_ok` 当失败），步骤记 `ok`；只有 spawn 失败才是 `error`。
  - **不可中止**：这条进程不在 `run_with_deadline` 的轮询里，「停止执行」不会杀它；编辑器必须用醒目提示写清。
  - 临时批处理：`run_cmd` 的 `.bat` 不能在 spawn 后立刻删（`cmd` 可能还没打开它）。把 `Option<PathBuf>` 传进 `run_with_deadline`：正常等待时结束后删；detached 时交给 reaper 线程在 `wait()` 返回后删。
  - `show_output` 强制 false（没有输出可弹）；结果卡只显示 detached 提示。
- UI：命令 / 脚本编辑器加「等它跑完再执行下一步」复选框（默认勾）；取消勾选时显示警告文案。
- 测试：`wait=false` 的 5 秒 sleep 在 1 秒内返回、`detached=true`、stdout 空；正常 `wait=true` 仍捕获输出。

### 6.4 CS-13 `on_error: stop`

- `Ctx` 加 `stop: AtomicBool`；`run_chain` 每轮开头、每个容器递归返回后检查；失败且 `on_error == Stop` 时置位，当前步结束后不再执行后续动作。
- 中止（用户点停止）仍走 `abort`，优先于 `stop`；`RunStatus` 仍是 `Finished`，记录结论由失败步骤定 `error`。
- `Parallel`：成员共享 `ctx.stop`，但已开跑的兄弟**不取消**（没有安全的取消机制）；组结束后整条链停。文档写清。
- UI：命令 / 脚本编辑器加「失败时停止后续动作」复选框（默认不勾）；帮助文案说明「默认仍继续，和以前一样」。
- 测试：失败命令 + `on_error=stop` + 后面的文本动作 → 文本步骤不存在；默认 continue → 文本步骤存在。

### 6.5 CS-14 单动作试运行

  - `const preview = structuredClone(action); preview.show_output = true;`
  - `invoke("run_entry", { actions: [preview], name: "试运行" })`。
  - **不改草稿、不落盘、不执行前置动作**；提示「只跑这一条，前面动作产生的变量不会存在」。
- 若该动作依赖 `{变量}`，预览时变量为空、命令可能报错——这是预期，提示里写明。
- 这条几乎零后端改动；如果批次二做了 `show_output` 三态，预览时直接传 `always`。

## 8. 设计口径（已定格，别翻案）

| 决定 | 理由 |
|---|---|
| `working_dir` 空 = 继承 Kada cwd；相对路径按 Kada cwd 解析；`~` 展开；不存在执行前报错 | 保持老行为可预测；脚本 `path` 的定位语义不跟着工作目录漂 |
| `args` 是 argv，一行一个；不做 shell 拆分 / 引号解析 | 空格路径不会被拆坏；跨平台语义一致；需要 shell 语法就写进 `command` |
| 解释器 / PATH 解析在 `kada-actions` 里做，不全局改 `PATH` | 只影响子进程；不污染 Kada 自身；macOS GUI 启动缺 Homebrew 路径是真实问题 |
| 统一 `KADA_*` 环境变量，不塞 `_kada_*` 用户变量 | 环境变量是脚本的天然接口；变量表要留给用户动作，避免命名空间与 `set_var` / 卡带合并打架。`KADA_VARS` 含本次变量表的明文（包括「隐藏内容」），只交给用户自己写的命令 / 脚本，**不写日志、不发外部服务** |
| `timeout_ms`：缺省跟全局，`0` = 不限时，只覆盖本步 | 与全局设置同义；不需要全局改设置就能给一条命令更短 / 更长的边界 |
| `ok_exit_codes` 空 = `[0]`；不支持通配 / 范围 | 简单、可读；范围需求可以用 `[0,1,2]` 明写 |
| `ScriptOutput::value()` 返回值优先，`print` 兜底 | 与文档一致；调试输出不该混进变量 |
| 每个动作先报 `running` 再报最终状态；壳层按 `id` upsert | 用户能在消息页看到「现在跑到哪」；不新增事件类型，复用现有 `run-update` |
| 完整日志落盘、内存仍截 16KB | 消息中心不撑爆内存；要全文去日志文件 |
| `wait=false` = 启动后不管，不捕获、不可中止 | 语义诚实；不要假装它能被「停止执行」收回 |
| `on_error` 默认 continue | 保持既有「一步失败不中断」的语义；stop 是显式选择 |
| 单动作试跑复用 `run_entry`，不另写执行器 | 一条执行路径；试跑与真跑不会分叉 |
| `show_output` 三态对老 bool 兼容 | 老配置照读；线上 `CommandResult.show_output` 不变 |

## 9. 已知坑与边界

- **`ScriptOutput::value()` 是行为变更**：依赖「print + 返回值」当变量的人会看到不同结果；归档与变量指南必须写明。
- **`〔咔哒〕` 前缀仍是失败判据**：用户命令自己往 stderr 打这个前缀会被误判；本次不拆（拆它要改 `CmdOutput` → `CommandResult` 的失败字段，属于另一条线）。
- **`MAX_RUN_STEPS` 可能裁掉正在跑的步骤**：最终 upsert 找不到就 push 完整结果，时间线少起点但不丢结论；要彻底解决得给运行中步骤留位，别在批次一加。
- **`KADA_VARS` 受系统环境块大小限制**（Windows 约 32KB）：变量表很大时可能设置失败；批次三的结果文件是长期解。
- **`wait=false` 的临时批处理**：删早了 `cmd` 读不到脚本；必须由 reaper 在 `wait()` 返回后删，别在 `run_cmd` 返回时删。
- **`wait=false` 的进程不在「停止执行」范围**：编辑器必须明说；不要给用户「能停」的错觉。
- **`on_error=stop` 不取消并行兄弟**：已开跑的成员会跑完；文档写清「组结束后才停」。
- **PATH 解析不是万能的**：Windows 的 App Execution Aliases（`python.exe` 商店别名）、Unix 的 shebang 解释器缺失，仍可能失败；错误文案要把「试过哪些目录」写出来。
- **macOS / Linux 只能交叉 check**：壳层窗口 / 剪贴板 / 文件管理器行为要真机；别把「交叉编译过」当「功能验证过」。
- **i18n**：所有新中文文案必须 `tr()` / `trt()` + `i18n.en.json`；后端（Rust）文案仍是中文，沿用现状。
- **基础版**：新字段 / 新分支都在 `automation` 门控内；`--no-default-features` 编译失败会挡住基础版发布。
- **构造点很多**：`Action::Command` / `Action::Script` 的 struct literal 散在 core / actions / shell / tests；加字段时用编译器找全，别只改主路径。
