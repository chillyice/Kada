# Kada 人工验证清单

> **这份文档解决什么问题**：Kada 有一批改动**只能在真机、由真人操作**才能确认（锁屏、睡眠唤醒、Alt-Tab 切窗口、GUI 点击），自动化测试覆盖不到——单测能证明「复位函数写对了」，证明不了「真锁屏那一下确实触发了它」。这些验收项此前散落在 `docs/变更归档.md` 各条目的「**未验证**」句里，只有一句话，接手的人不知道从哪下手。
>
> 这里把它们收成**可照做、可复跑**的步骤：每条都有前置配置、操作步骤、预期现象、以及「出现什么就算失败」。默认从**最新的可靠性项**往回排。
>
> **谁该读**：要验收这些改动的人（目前就是作者本人）。**什么时候跑**：改到钩子 / 状态机 / 动作执行后跑相关那几条（不必每次全跑）；发版前若时间允许，跑第 1~8 条。

## 0. 通用准备（每条都要用）

### 0.1 怎么看到日志

壳层留痕走 `eprintln!`，**只有带控制台的构建才看得到**：`src-tauri/src/main.rs` 是 `#![cfg_attr(not(debug_assertions), windows_subsystem = "windows")]`——release 版没有控制台，stderr 会直接丢掉；**debug 版从终端启动才有输出**。

```powershell
# 先退出正在运行的那一个（托盘右键 → 退出）；两个实例会抢同一套全局钩子
taskkill /IM kada.exe /F

# 需要时先构建 debug 版
cargo build -p kada

# 从终端启动，日志就打在窗口里
.\target\debug\kada.exe
```

要验证的复位留痕是这一行（`_` 处是原因）：

```
kada: 输入状态已复位（前台窗口切换）
kada: 输入状态已复位（钩子已重装）
```

**注意**：这行**只在壳层真的丢了状态时才打印**（`Engine::reset` 返回 `false` 就什么都不打）——所以「没看到日志」不等于「复位没跑」；能看到它时是好消息，看不到时要靠下面的**功能现象**判断。

### 0.2 两条纪律

- **debug 版与 release 版共用同一份配置**（`%APPDATA%\com.kada\config.json`）。测试期间加的测试条目（改键 / 文本扩展 / 快捷键）测完记得删掉，否则会一直生效。
- **关主窗口 ≠ 退出**（托盘常驻是设计）。退出只能走托盘菜单「退出」，或 `taskkill /IM kada.exe /F`。

### 0.3 通用观测位置

| 要看什么 | 在哪看 |
|---------|-------|
| 复位留痕、注入失败、创建窗口失败 | 启动它的那个终端窗口（仅 debug 版） |
| 命令 / 脚本结果、中止记录 | 主窗口左侧「消息」页（托盘图标红点 = 有未读） |
| 动作超时设置 | 主窗口左侧「设置」页 →「动作超时」（**按秒**录入，0 = 不限） |
| 打开主窗口 | 双击托盘图标（左键），或托盘右键 →「打开咔哒」，或双击你设的快速唤醒键 |

## 1. 前台切换 → 收回注入的修饰键（P1-④） ✅ 2026-09-29 通过

**要证的事**：按住切层/长按键期间注入出去的 Ctrl，在 Alt-Tab 切窗口时被**补一个 up** 收回来。不复位的后果是「修饰键粘住」——系统层面 Ctrl 一直按着，新窗口里敲什么都成组合键。

**前置配置**：改键页新增一条，`from` = `CapsLock`，「长按」（长按输出）= `Ctrl`，保存。
（短按输出留空即可——留空时短按会按吞键铁律回放原键，不影响本测试。）

**步骤**：

1. 打开记事本（或任意能输入文本的窗口），让它在最前台。
2. **按住 CapsLock 不放**，再按一下 `K`。
   这一步让状态机判定为「长按」（roll 判定），把 Ctrl **物理注入**下去——此刻系统层面 Ctrl 是按下状态。
3. **保持按住 CapsLock**，按 `Alt+Tab` 切到另一个窗口（另一个记事本 / 浏览器地址栏）。
4. 等大约 **0.5 秒**，让新窗口稳定在前台。
   前台切换要**连续两轮**巡检（各 60ms）才认，所以给足两轮以上。
5. 松开 CapsLock。
6. 在新窗口里敲一下字母 `a`（**不要**碰 Ctrl）。

**预期**：新窗口里正常出现 `a`。

**判失败**：敲 `a` 没有任何字符出现，或触发了 **Ctrl+A 全选**（浏览器地址栏 / 记事本会全选）——说明注入的 Ctrl 从未被收回，**修饰键粘住了**，本项不通过。

**顺带确认**：终端里应出现 `kada: 输入状态已复位（前台窗口切换）`（在切窗口后约 120ms 内；若此前没有任何待定状态则可能不打，见 §0.1）。

**万一 Ctrl 真的粘住了怎么恢复**：按一下物理 `Ctrl` 键再松开——真实的一对 down/up 会把系统状态冲正，不用重启应用。

## 2. 前台切换 → 热串缓冲不回放（P1-④） ✅ 2026-09-29 通过

**要证的事**：在 A 窗口敲了一半的文本扩展触发词，切到 B 窗口后敲后缀**不会**在 B 里展开成替换文本。复位口径是「缓冲里的东西一律丢弃不回放」——因为复位时前台目标已经变了，把旧按键注入到新窗口（可能是密码框）比丢掉更糟。

**前置配置**：确认「文本扩展」页有一条触发词，比如 `addr`（替换文本随便是什么都行）。没有就加一条，保存。

**步骤**：

1. 打开窗口 A（记事本），点击进入可输入状态。
2. 在 A 里敲 `add`（**不要**再敲空格 / 回车 / Tab，也不要敲完整触发词）。
3. `Alt+Tab` 切到窗口 B（另一个记事本，或浏览器里的输入框），等约 0.5 秒。
4. 在 B 里敲 `r`，紧接着敲一下空格。

**预期**：B 里看到的就是你亲手敲的 `r `（或连上 B 里原本的内容）——**不展开**成替换文本。

**判失败**：B 里突然变成替换文本（触发词被回删、注入了替换内容）——说明在 A 窗口敲了一半的缓冲被带过了窗口边界，本项不通过。

> 这条测试的价值在于它**能被肉眼立刻分辨**：成功与失败输出的是两段完全不同的文字，不需要任何工具辅助。

## 3. 锁屏 → 解锁（P0-① 重装 + P1-④ 复位） ✅ 2026-09-29 通过

**要证的事**：`Win+L` 锁屏再解锁后，钩子被看门狗判为「已重装」（判据是 `WTSInfoEx.SessionFlags` 的 锁定→未锁定 跃迁：反直觉字段 0=锁定、1=未锁定），壳层跟着复位。

**步骤**：

1. 保持 debug 版从终端运行（§0.1）。
2. 按 `Win+L` 锁屏，等 2 秒以上，再解锁回到桌面。
3. 解锁后**立刻**做两件事：按一次你配好的快捷键（如 `Alt+X`）；再敲一次文本扩展（触发词 + 空格）。
4. 看一眼终端输出。

**预期**：快捷键与文本扩展都正常生效；若解锁前壳层有残留状态，终端会多出 `kada: 输入状态已复位（钩子已重装）`。

**判失败**：解锁后快捷键 / 改键 / 文本扩展**全部无响应**（说明钩子没被重装，看门狗这条判据失效），或出现「修饰键粘住」——都算不通过。

**说明**：看门狗巡检 1 秒一次，所以解锁后最多约 1 秒才重装并复位落地，属正常；这一步同时也是 P0-① 看门狗唯一能由真人稳定复现的触发路径。

## 4. 休眠 → 唤醒（P0-①） ⬜ 未执行

**要证的事**：看门狗能用 `GetTickCount` 的跃变（**该计数把睡眠时间也算进去**）发现机器睡过，并重装钩子。

**状态**：**未执行**——2026-09-29 首轮人工验证唯一没跑的一条。看门狗的重装动作本身已由 §3（解锁路径）在真机确认，但「相邻巡检间隔 > 10s ⇒ 机器睡过」这条判据仍只由单测覆盖，没在真机上跑过。可以下次休假前顺手做。

**步骤**：

1. 保持 debug 版从终端运行。
2. 开始菜单 → 电源 → 睡眠。**睡够 10 秒以上**（判据是「相邻两次巡检间隔 > 10s」，睡太短不足以越过阈值）。
3. 唤醒机器（动鼠标 / 按键盘）。
4. 唤醒后立刻按一次快捷键 + 敲一次文本扩展。

**预期**：都正常生效；终端可能出现 `kada: 输入状态已复位（钩子已重装）`。

**判失败**：唤醒后所有触发无响应，或修饰键粘住。

## 5. 冷启动双击唤醒（P1-⑤） ✅ 2026-09-29 通过

**要证的事**：唤醒路径的**建窗**跑在后台线程，不会把钩子回调拖过系统超时线（约 300ms）而被摘钩。这条最凶险的形态是**开机自启**：主窗口没预建，首次双击唤醒要冷启动 WebView（几百毫秒），正好撞在那条路上。`--autostart` 参数就是用来复现这个状态的。

**前置配置**：设置页「快速唤醒」选一个键（如「双击 Alt」），保存。

**步骤**：

1. 完全退出 Kada（托盘 →「退出」）。
2. **用静默模式启动**（模拟开机自启，主窗口不预建——这是本测试的关键）：

   ```powershell
   .\target\debug\kada.exe --autostart
   ```

   观察：不应有任何窗口出现（只有托盘图标）。
3. 随便点开一个别的窗口（如记事本），让**主窗口处于未创建状态**。
4. 快速双击你设的唤醒键（两击间隔 ≤ 400ms）。
5. 看主窗口是否出现、终端是否报错。
6. **重复第 3~5 步 3~5 次**，其中至少一次是「不等待、连点两轮双击」——用于撞「并发建窗」那条竞态。
7. 再验证唤醒键本身**不被拦截**：在记事本里，`Alt+Tab`、`Alt+字母` 应照常可用。

**预期**：主窗口每次都正常出现；终端**没有** `创建主窗口失败`；`Alt+Tab` / `Alt+字母` 正常。

**判失败**：唤醒键按了没反应；终端出现 `创建主窗口失败`（并发建窗的回查分支没生效）；或唤醒后**快捷键全部失效**（钩子被回调超时摘掉了，这正是本项要防的）。

## 6. 动作超时 + 杀整棵进程树（P1-⑦） ✅ 2026-09-29 通过

**要证的事**：命令挂住时被**限时**终止（不再是无限等待），而且是连**孙进程**一起杀（`Child::kill` 杀不掉 `cmd /C` 下面真正干活的那层）。

**前置配置**：

1. 设置页「动作超时」填 `2`（秒），保存。改完立即生效，不用重启（超时值在触发时从配置读出）。
2. 新建一条快捷键（如 `Alt+F9`），动作 = **执行命令**（Shell 选 CMD），命令填：

   ```
   powershell -NoProfile -Command "Start-Sleep -Seconds 30; New-Item -Path '%TEMP%\kada_tree_marker.txt' -ItemType File | Out-Null"
   ```

   这条命令的结构是刻意选的：我们的进程 → `cmd /C <临时批处理>` → `powershell`（**孙进程**）→ 睡 30 秒后建标记文件。只杀直接子进程的话，标记文件照样会出现。
3. 先手工删掉 `%TEMP%\kada_tree_marker.txt`（若存在）。在资源管理器地址栏输入 `%TEMP%` 回车即可打开该目录。

**步骤**：

4. 触发 `Alt+F9`。
5. 观察动作何时结束（命令本身要跑 30 秒，被超时终止应在约 **2 秒**就返回）。
6. 打开主窗口 →「消息」页，看新增的那条结果。
7. **再等 35 秒**，回到 `%TEMP%` 目录看标记文件在不在。
8. **对照组（很重要）**：把「动作超时」改成 `0`（不限），再触发一次，等到命令自然结束（约 30 秒）——这次标记文件**应该**出现。

**预期**：

- 第 5 步：约 2 秒返回（不是 30 秒）。
- 第 6 步：结果里 `stderr` 含一句 `〔咔哒〕执行超时（超过 2 秒），已强制终止该进程及其子进程。`；**退出码显示「—」**（被强杀的进程退出码没有语义，程序置空，前端渲染成「—」）。
- 第 7 步：标记文件**不存在**。

**判失败**：

- 第 5 步等了 30 秒才结束 → 超时没生效。
- 第 6 步没有「执行超时…」这句 → 原因没写进 stderr（用户看不到归因）。
- **第 7 步文件出现了 → 只杀了直接子进程、孙进程还在跑**，这是本项最关键的验收点，出现即不通过。
- 第 8 步对照组的文件也没出现 → 说明是命令本身没跑起来（比如引号被转义坏），前面的「没出现」是假阳性，要重新验证。

> 第 8 步的对照不能省：没有它，「文件不存在」这个结果无法区分「杀干净了」和「命令压根没执行」。

## 7. 停止执行按钮（P1-⑦） ✅ 2026-09-29 通过

**要证的事**：用户点「停止执行」能真的叫停正在跑的动作链，且**不假装成功**——没有在跑的东西时如实说「当前没有正在执行的动作」。

**前置配置**：

1. 设置页「动作超时」填 `0`（不限）——避免 30 秒自动超时结束干扰本测试。
2. 新建一条快捷键（如 `Alt+F10`），动作 = 执行命令（CMD）：`ping -n 60 127.0.0.1 >nul`（约跑 59 秒）。

**步骤**：

3. 触发 `Alt+F10`（命令开始跑）。
4. 立刻打开主窗口（双击托盘图标）→「消息」页 → 点右上角「**■ 停止执行**」。
5. 看提示与命令是否停。
6. **再点一次**「■ 停止执行」（此刻没有在跑的动作）。

**预期**：

- 第 4~5 步：提示 **`已请求停止（1 条正在执行）`**；命令**立刻**结束（判定粒度 20ms，最多迟 20ms 就开始杀进程）；「消息」页新增一条 kind 为 abort 的记录，内容是 `已停止执行：剩余动作不再执行，正在运行的命令 / 脚本已强制终止。`
- 第 6 步：提示 **`当前没有正在执行的动作`**。

**判失败**：

- 第 5 步提示「当前没有正在执行的动作」（说明「正在执行」计数没加上去，`RunGuard` 漏了），或提示了「已请求停止」但命令还在跑（中止判定点失效）。
- 第 6 步仍然提示「已请求停止（N 条正在执行）」→ 计数泄漏（动作链结束没减回去），之后 UI 会永远显示「有东西在跑」。

> 第 6 步就是「反馈不假装成功」这条设计的验收：什么都不跑的时候点停止，也必须得到诚实的回答。

## 8. 动作失败上报消息中心（P1-⑥） ✅ 2026-09-29 通过

**要证的事**：一个必然失败的动作，用户能在消息中心看到「**哪一步**失败、拿**什么值**去做的、**为什么**失败」，而不是只有「按了没反应」。（release 版没有控制台，stderr 日志看不到，所以只能靠消息中心判断。）

**前置配置**：

1. 新建一条快捷键（如 `Alt+F10`），动作 = 文件操作 → 删除，路径填一个**不存在**的路径（如 `D:\没有这个目录\x.txt`）。
2. 同一条快捷键后面再追加一个动作：暂停 100 毫秒（它不会产生任何记录，用来顺带看「一步失败不中断后续动作」——触发一次应当只多**一条**记录）。
3. 再新建一条快捷键（如 `Alt+F11`），动作 = 执行脚本，路径填一个**不存在**的脚本文件，并把该动作的「弹窗显示结果」**打开**。

**步骤**：

4. 触发 `Alt+F10`（坏路径动作）。
5. 打开主窗口（双击托盘图标）→「消息」页，看新增的那条记录。
6. 触发 `Alt+F11`（起不来的脚本，开了「弹窗显示结果」）。

**预期**：

- 第 4 步：托盘图标出现**红点**，应用内「消息」入口亮红点。
- 第 5 步：tab 标题是 **`文件操作失败 · 名称`**（没填名称则是 `文件操作失败 · Alt+F10`）；卡片里「命令」一栏是 **`删除 D:\没有这个目录\x.txt`**（若该动作填了「描述」，则显示 `描述（删除 …）`）；stderr 是失败原因（`删除失败：「…」不存在`）；退出码 `—`。
- 第 6 步：**弹窗自动出现**（因为该动作开了「弹窗显示结果」），标题 `命令结果 · 脚本失败`，stderr 里是脚本起不来的系统错误。

**判失败**：

- 第 5 步消息中心**没有任何新记录** → 失败仍只在 stderr 日志里（本项未生效）。
- 第 5 步记录里「命令」一栏为空、或原样留着 `{变量名}` 这类占位符 → 摘要没渲染 / 变量没代入。
- 第 6 步**没有弹窗** → `show_output` 被失败路径一律降级成静默了（应当沿用动作自身的设置）。
- 若第 5 步出现不止一条记录 → 说明有别的动作也在报（本例的第二个动作是暂停，没有失败路径）。

> 第 6 步是「命令/脚本连启动都没成功也该弹窗」这条设计的验收；第 4~5 步的红点则是所有非弹窗类失败的默认表现。

这条不属于上面那批可靠性改动，但同样是「只有真人能确认」的验收项，一并记在这里：客户端更新链路（启动静默检查 / 手动检查 / 下载安装 / 签名校验）到目前**一次端到端都没跑过**（远端零 tag、本机无安装包）。

**状态**：未验证（截至 2026-09-29）。

发版步骤（打 tag、Secrets、draft 发布、`requireSignedVersion`）见 `docs/安装与更新-Windows.md` §2，这里只写**验收判据**：

1. 发一个 `v0.1.1`（tag 推上去后由 CI 构建、签名、生成 `latest.json`、产出 **draft** Release），确认无误后在 GitHub 上 **Publish**（流水线默认发 draft，因为 `releases/latest` 只解析已发布的 Release）。
2. 在装着旧版（0.1.0）的机器上启动 Kada，**等 8 秒**（启动检查是延迟 8 秒 + 只在发现新版本时弹一次气泡）。
3. 托盘右键 →「检查更新」：应能进入下载 → 安装。
4. 安装后确认版本号已变（「安装」在 Windows 上会**退出应用**，NSIS 以 passive + `/R` 装完自动拉起新版，属预期）。
5. 反向用例：若客户端**拒绝安装**，优先怀疑公钥/私钥不匹配（客户端拿内嵌公钥验安装包签名，验不过直接拒装，是设计使然）。

## 目前做不到的验证（不必尝试）

- **「回调超时被系统摘除」**：需要钩子回调真的卡住超过 `LowLevelHooksTimeout`（约 300ms）才会被系统摘掉，人为触发不了。这条路径的判据（心跳停摆）由单测 `watchdog_spots_hook_that_stopped_receiving_events` 覆盖，重装动作由冒烟测试走 `request_reinstall()` 走同一条代码路径。
- **Linux 侧杀进程树**：Linux 分支目前只 `kill()` 直接子进程（孙进程杀不掉），是**已记录在案的已知缺口**（见 `需求设计说明书.md` §5.7）。本机是 Windows，Linux 分支只能保证编译通过。
- **「键盘钩子单独被摘、鼠标钩子还活着」**：`GetLastInputInfo` 是键盘与鼠标的合并信号，这种半边失效发现不了（心跳一直被鼠标事件喂着），是看门狗的已知天花板。
