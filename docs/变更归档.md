| 文件 | 改动 |
|------|------|
| `Cargo.toml` | workspace 定义：members `crates/kada-core`/`crates/kada-hook`/`src-tauri`；release profile `lto=true`/`strip=true`/`codegen-units=1` |
| `src-tauri/` | Tauri 2 壳脚手架（`Cargo.toml` crate `kada`、`build.rs`、`tauri.conf.json`、`src/main.rs`、图标） |

**规则/决策**：workspace 三成员职责切分——`kada-core` 只做纯逻辑（可独立测试、无平台依赖）、`kada-hook` 只做平台钩子、`src-tauri` 只做壳与命令层；平台相关代码用 `#[cfg]` 门控，保证非目标平台仍可编译。

##### M1 核心键模型 + Windows 钩子引擎

| 文件 | 改动 |
|------|------|
| `crates/kada-core/src/lib.rs` | `Key`/`Modifier`/`RawEvent`/`Shortcut` 类型；`parse::shortcut`/`parse::key`（`"Ctrl+Alt+K"`）；`format_shortcut`/`key_name`；`matches`（主键一致 + 修饰键超集） |
| `crates/kada-hook/src/win.rs` | `SetWindowsHookEx(WH_KEYBOARD_LL)` 全局低层钩子；`start`/`HookHandle`（Drop 发 WM_QUIT 回收）；`keyboard_proc`/`swallow` 状态机（`Block`/`Replace`/`SWALLOWED`/`REPLACED_DOWN`/`LAST_DOWN`）；`GetKeyState` 修饰键 + 250ms 自动重复识别；`LLKHF_INJECTED` 防回环；`key_to_vk`/`vk_to_key` 映射 |
| `crates/kada-hook/src/win/simulate.rs` | `SendInput` 注入 `down`/`up`/`tap`/`chord`；`type_text` 剪贴板 + `Ctrl+V` |
| `crates/kada-hook/examples/demo.rs` | M1 冒烟 demo：`Ctrl+Alt+K` 输文本、`Ctrl+Alt+M` 改键、`Ctrl+Alt+Q` 退出（仅 Windows） |
| `crates/kada-hook/tests/hook_smoke.rs` | 钩子安装 → 消息循环 → 卸载回收冒烟（仅 Windows） |

**规则/决策**：
- 处理函数直接跑在回调内（不做跨线程调度），保证顺序与低延迟；注入事件带 `LLKHF_INJECTED` 一律放行杜绝回环。
- `Block`/`Replace` 登记 `SWALLOWED`，后续 keyup 一并吞掉防幽灵按键；`Replace` 保持"按下-抬起"配对。
- 未吞掉的 keyup 以观察者身份回调 handler（录制宏用），返回值忽略、永远放行。
- `type_text` 用剪贴板粘贴（中文最稳），会短暂占用剪贴板。

##### M2 配置模型与动作/宏

| 文件 | 改动 |
|------|------|
| `crates/kada-core/src/lib.rs` | `Config`/`ShortcutItem`/`Remap`/`Action`（`Text`/`Sequence`）/`Step`（`Text`/`Tap`/`Keys`/`Down`/`Up`/`PauseMs`）；`Action::validate`（键名可解析校验）；`#[serde(tag="type", rename_all="snake_case")]` 序列化；`Default` 实现 |

- 手工编辑的配置允许缺字段、带未知字段（`#[serde(default)]`），配置缺失字段回落默认值（如 `enabled` 缺省 `false`）。

##### M3 Tauri 桌面壳 + 宏录制 + 配置界面

| 文件 | 改动 |
|------|------|
| `src-tauri/src/lib.rs` | `KadaState`/`Ev`/`Outcome`/`decide`（改键优先于快捷键）/`fire`/`run_action`/`Recorder`（转录 `Step` 时间线）/`load_config`/`save_config`/`validate`；Tauri 命令 `get_config`/`set_config`/`set_paused`/`start_record`/`stop_record`；`setup` 接钩子 + 托盘常驻（关窗隐藏） |
| `ui/src/main.ts` | 配置界面：快捷键列表（开关/编辑/删除/录入组合键）、动作类型切换（文本/宏）、宏录制（`start_record`/`stop_record`）、改键列表（from/to 下拉） |
| `ui/src/style.css` | 深色 UI 样式 |

**规则/决策**：
- 改键优先于快捷键（先消耗原生键，避免改键后键再触发快捷键）；命中动作在异步线程执行，避免阻塞钩子回调。
- 录制器中重复 down 折叠、事件间时差 ≥20ms 补 `PauseMs`；录制中快捷键/改键全暂停。
- 组合键录入时调 `set_paused(true)` 暂停触发，避免自触发；Esc 取消。
- 关窗 = 隐藏到托盘（`CloseRequested` 阻止关闭并 hide），应用继续跑。

##### M4 Linux 钩子引擎（evdev + uinput）

| 文件 | 改动 |
|------|------|
| `crates/kada-hook/src/linux.rs` | evdev + uinput 钩子：`start` 抓取键盘设备 + 建虚拟键盘 `kada-virtual-keyboard`；`poll_loop` 轮询；`handle`/`press`/`release` 状态机（`SWALLOWED`/`REPLACED_DOWN`/`MODS_DOWN`）；`key_to_code`/`code_to_key` 映射；`simulate` 子模块（`type_text` 剪贴板 + `Ctrl+V`） |
| `crates/kada-hook/src/lib.rs` | 增加 `#[cfg(target_os = "linux")] pub mod linux;` |
| `crates/kada-hook/Cargo.toml` | Linux 目标加 `evdev = "0.13"`；`arboard`/`windows` 依赖改为 `cfg(any(windows, target_os = "linux"))` |
| `Cargo.lock` | 新增 evdev 依赖树 |
| `src-tauri/src/lib.rs` | 增加 Linux `input` 模块（`kada_hook::linux`）+ `to_ev` 映射 |

**规则/决策**：
- 独占抓取（`EVIOCGRAB`）使被抓设备按键事件只到达我们，原事件不再进应用；用 uinput 虚拟键盘转发，天然无注入回环。
- 修饰键状态按事件流维护（`MODS_DOWN`），吞键/改键不影响真实状态位，与 Windows `GetKeyState` 语义对齐。
- 需要 root 或 `input` 组 + udev 放开 `/dev/uinput`；无权限时 `start` 报错，能读到的其它键盘静默跳过。
- 热插拔键盘不在监听列表（重启应用即可）。

| `ui/index.html` | 「消息」导航（红点徽标）+ 消息详情区（tab 条 + `‹ ›` + 清空）+ 结果弹窗模态 |
| `ui/src/main.ts` | `listen` 监听 `command-result`；消息页/tab/红点/弹窗渲染；Cmd/PowerShell 动作「弹窗显示结果」复选框；TS `Action` 类型加 `show_output` |
| `ui/src/style.css` | 红点徽标、消息 tab/卡片、结果弹窗、动作复选框样式 |

**规则/决策**：

- `show_output` 开 → 唤起主窗口 + 结果弹窗；关 → 托盘图标 + 应用内「消息」入口亮红点。两种情况都 `emit("command-result")`。
- 中文不乱码：Windows cmd 前缀 `chcp 65001>nul & `、PowerShell 前缀 `[Console]::OutputEncoding=...` 统一 UTF-8 解码；Linux 下 CMD 走 `sh -c`。
- 进入「消息」页即标记已读（`mark_results_read`），红点熄灭、托盘图标还原。

| 文件 | 改动 |
|------|------|

| `src-tauri/src/lib.rs` | `run_actions` 递归驱动（拦截 If 按条件分支执行）；`run_os`/`run_app`（文件动作走 std::fs、应用动作用 taskkill/tasklist/启动）；`close_program` 统一记入消息中心；`set_config`/`import_config` 改为清洗后返回 `Vec<String>` 忽略提示 |
| `ui/src/main.ts` | 动作类型新增「文件动作 / 应用动作 / 条件判断」；文件动作子操作下拉 + 文件/目录浏览、应用动作程序浏览 + 参数、条件判断递归渲染 then/otherwise 分支；TS 类型对齐 |
| `ui/src/style.css` | 条件判断分支样式（`.branch-label`/`.action-branch`/`.add-inline`） |

**规则/决策**：
- 变量作用域 = 单次触发内的动作序列：`GetFileProps`/`Status` 写入变量，后续动作（含 If 条件）用 `{变量名}`/`{变量名.字段}` 引用；复制/剪切记 `last_copied` 供「粘贴」用。
- 动作链不引入 `Sequence` 包装：`If` 的 `then`/`otherwise` 直接是 `Vec<Action>`，运行器递归展开，嵌套条件任意层。
- 保存语义从「校验失败整体拒绝」改为「逐条清洗 + 提示」：坏触发键/动作/改键单独忽略，硬冲突不再阻塞保存（仅 UI 提示），避免「一条坏配置拖垮整份保存」。
- 旧版 `Launch`/`CloseProgram` 保留为兜底变体（加载时已迁移到 `App`，正常不出现）。

| 文件 | 改动 |
|------|------|
| `src-tauri/capabilities/default.json` | `windows: ["main"]` → `["main", "toast"]`：把气泡窗口纳入 capability，修复「触发快捷键后右下角气泡无内容」（`toast` 窗口无 `core:default` 导致 `plugin:event|listen` 被 ACL 拒绝） |
| `src-tauri/tauri.conf.json` | `windows` 清空为 `[]`：纯托盘冷启动，启动时零 WebView |
| `src-tauri/src/lib.rs` | 新增 `ensure_toast()`（首次触发才建气泡窗口 + 点击穿透/定位）、`show_main_window()`（主窗口不存在则建 860×560 居中、已存在则 show+focus）；`KadaState` 增 `toast` 暂存载荷 + `get_toast_payload` 命令；`setup` 删启动时气泡创建，`launch_minimized`/托盘菜单/双击/`show_output` 三处改走 `show_main_window` |
| `ui/src/main.ts` | `bootstrapToast()` 加载后主动 `get_toast_payload` 拉取一次，兜底「事件早于监听器注册」的首触发竞态 |
| `ui/src/style.css` | `body:has(.toast-bubble) { background: transparent }`：transparent 窗口的 body 必须透明，否则显示成实心深色矩形 |

**规则/决策**：
- 冷启动零 WebView：主窗口与气泡窗口都不在启动时创建，首次用到才 `WebviewWindowBuilder` 建出；`default_window_icon` 来自 `bundle.icon`（非 `windows` 数组），清空 windows 不影响托盘图标。
- 气泡懒创建有首触发竞态（窗口刚建好、事件早于前端监听器注册）→ 后端 `KadaState.toast` 暂存载荷 + 前端加载后拉取兜底，保证第一次触发也有内容。
- 主窗口按需创建后「关窗」仍隐藏到托盘（`CloseRequested` 阻止关闭），不销毁 WebView，后续打开即时、状态保留。
- 已知边界：主窗口从未打开时若 `show_output` 结果触发，弹窗可能错过（主窗口刚建、`command-result` 监听器未注册），但结果仍进消息中心。

**规则/决策**：

**规则/决策**：

- 注入修饰分三类、释放时机各不同：`hold`（`from` 松开释放）、`sticky`（再次单击 `from` 解锁）、`oneshot`（下一个非修饰键释放）；`oneshot` 的 roll/长按复用 `activate_hold` 当普通 hold 修饰按下/释放。mods 补全 = `hold ∪ sticky ∪ oneshot`，让「长按 CapsLock=Ctrl」「粘滞 Shift」「单次 Ctrl」都能让后续组合键携带该修饰。

**规则/决策**：
- **吞键铁律**：被吞的键补不回来，「吞掉」只允许发生在「还在等下一个键凑齐」的窗口内；没组成快捷键的按键（和弦没凑齐/序列断链超时/tap-hold 两条无输出路径）必须按输入顺序原样回放，否则配置 `F&J`、`F9 J K` 或只设切层键后这些键永久变哑。
- **自动重复判定不能用时间窗**：同键 250ms 内两次 down 是正常输入（热串双写字母、双击连击），按时间窗会被误判成自动重复丢掉第二击；「按下未抬起集合」与真实语义一致。
- **keyup 一律观察者回调**：状态机靠抬起维护「按住集合」；被吞键的 keyup 若不同步回调，该键的抬起状态永久丢失、整个状态机卡死（键变哑）。
- **状态机拆 `engine.rs` 的动机**：这批时序逻辑互相纠缠且全是纯决策（输入事件 → 吞/放/回放/触发），与 Tauri 无耦合；拆出后用假注入单测覆盖（真实注入绝不进测试），`lib.rs` 从 ~2400 行瘦身到纯接线。
- **锁定切层 vs momentary**：`hold_layer` 按住生效（单组合场景快），`lock_layer` 长按切换保持生效（层内放和弦/序列唯一可行形态）；两者互斥、`sanitize` 裁决保留 `lock_layer`；层可达性检测同时认两种切层键，层内条目没有任何切层键指向时在冲突清单里直说「永远不会生效」。

**规则/决策**：
- **写入必须原子**：原 `fs::write` 先截断再写，崩溃 / 断电即留半截 JSON。改为「临时文件 → `fsync` → `rename` 覆盖」，任何时刻磁盘上的 `config.json` 要么是旧的完整内容、要么是新的完整内容。`fsync` 不可省——只写不刷时 `rename` 可能先落盘、数据后落盘，断电后留下空文件（「配置凭空消失」的另一条路径）。临时文件名带 pid + 序号（`create_new`），并发保存（连点保存、导入与保存同时进行）不会互踩同一份临时文件写出半截内容。
- **损坏绝不静默清空**（原行为：解析失败 `eprintln` 一句 + 回退空配置，用户随手一保存就把空配置写回磁盘 → 快捷键 / 改键 / 层 / 文本扩展「凭空消失」）：留档原文件（**改名**而非复制，后续保存盖不掉）→ 尝试 `.bak` 恢复 → **恢复成功即回写主文件**（否则下次启动还是同一个坏文件，且「主文件缺失」会被当成首次启动、告警消失）→ 都失败才空配置启动。原内容始终留在磁盘上可人工修回。
- **`.bak` 只存「上次良好副本」，损坏原件另名留档**：保存前写的 `.bak` 必须是可解析的配置——否则用户在主文件损坏期间保存一次，就把好备份的位置装进了坏内容、自愈就此断源；损坏原件用 `config.json.corrupt-<时间戳>`（带时间戳，不与上一次事故的留档互相覆盖）。这样 `.bak` 的语义始终是「从这里恢复」。（需求原文写「损坏时原名留档（`.bak`）」，实现按上述理由拆成两个名字。）
- **告警走消息中心、且必须在托盘建好之后推**：`commit_result` 会叠托盘红点，早于托盘就是 no-op；`show_output: false` 走红点而非弹窗（前端启动只 `get_command_results` + `get_unread`，此刻弹窗也不可靠，且开机自启场景不该被弹窗打断）。只 `eprintln` 到看不见的控制台等于没有告警。
- **加载路径仍只 `migrate()` 不 `sanitize_config()`**：加载时静默丢条目同样属于「悄悄改用户配置」，与本次「不静默丢数据」的原则一致；逐条清洗只留在保存 / 导入路径（原先审计把这一致性差异列为问题，现定为有意口径）。
- **`export_config` 保持 `fs::write`**：导出到用户指定路径的是导出文件、不是活配置，不加原子写、不产生 `.bak`。

**验证**：`cargo test --workspace` 全绿（壳 53，含新增 8 条：首次启动静默默认、保存-加载往返、损坏留档且原内容仍在盘上、损坏从 `.bak` 自愈并回写主文件、主文件缺失从备份恢复、损坏内容不污染 `.bak`、保存失败不留临时文件且不破坏原目标、并发保存各自独立临时文件）；`cargo check -p kada --no-default-features` 编译通过；clippy 无新增告警（仅剩 3 条既有）。**未跑 GUI**：改动是纯文件 I/O、单测覆盖全部路径；另核对本机真实配置 `%APPDATA%/com.kada/config.json` 为合法 JSON（10 条快捷键），加载不会误判损坏。实测路径：写坏 `config.json` 后重启 → 托盘红点 + 消息中心一条「配置 · 启动加载」。

**规则/决策**：
- **看门狗只「发现」，装钩子永远归钩子线程**：`SetWindowsHookEx` 装上的钩子其回调跑在**安装它的那个线程**上，所以重装也必须在那个线程做。看门狗线程只 `PostThreadMessageW` 一个自定义消息（`WM_APP + 1`），钩子线程的消息循环里识别它并落地——跨线程直接装会把回调挪到别的线程上（顺序与低延迟的前提就没了）。
- **必须「先卸旧再装新」**：钩子已被系统摘除时 `UnhookWindowsHookEx` 只是返回失败（无害）；但若旧钩子还活着而不卸就装新的，旧钩子会留在钩子链里**每个按键被处理两遍**（快捷键触发两次），比失效更难查。
- **重建时一并复位钩子层状态，并把被替换的目标键补一个 up**：重装意味着中间丢过事件，那些物理键的抬起不可能再经过我们。不复位的后果有两条且都很隐蔽：`HELD_KEYS` 里的键永远等不到抬起，自动重复判定会把它的后续**每次按下**都当成按住连发（该键彻底变哑）；`REPLACED_DOWN` 里已注入的目标键（常是 Ctrl 这类修饰键）永远收不到配对的 up，在系统看来一直按着。这一条也让 7.2-④ 的钩子层那半顺带落地。
- **装完必须把心跳重新起算**：否则「最后一次钩子事件」还停在很久以前，看门狗下一轮就把刚装好的钩子再判成失效，陷入每秒重装（每次重装都会短暂卸掉钩子、吃掉窗口里的按键）。
- **`HEARTBEAT_GRACE_MS` 必须大于 `WATCHDOG_INTERVAL_MS`**：判据里「输入够新」那一项只在输入发生在最近一个宽限内才成立，若宽限小于巡检间隔，两轮巡检之间的输入会整段落空、永远不被发现。
- **误判的方向是「多装一次」而非「漏判」**：所有阈值都取宽松侧（唤醒阈值 10s、连续的第二次触发才退避），一次多余的重装只值几毫秒的空窗，比漏掉一次真失效（快捷键全哑直到用户重启应用）便宜得多。看门狗在**闲置时一声不吭**是硬要求：判据只看「系统收下的输入」与「钩子心跳」的先后，不看绝对时间，所以没人碰键盘时两个时间戳一起停在原处、不构成失效。
- **以轮询替代原规划建议的事件订阅**：规划写的是订阅 `WM_POWERBROADCAST` / `WTSRegisterSessionNotification`。实现改为轮询，因为这两条都要在钩子线程上再建一个隐藏窗口（`WTSRegisterSessionNotification` 要 HWND；而**消息专用窗口收不到广播消息**，得建真实隐藏顶层窗口，还得引 `Win32_Graphics_Gdi`/`Win32_System_LibraryLoader` 等 feature 并管理窗口生命周期）。轮询同样能拿到「解锁」「唤醒」两个跃迁，且能在真机上验证（见下），代价是解锁最多迟 1s 被发现。
- **自愈不打扰用户**：只在 stderr 留痕 + `reinstall_count()` 计数，**不进消息中心**——用户此刻没有动作可做（已经自动修好了），弹窗/红点只会制造困惑。这与「命令结果一律记入消息中心」并不冲突：那条针对的是用户主动触发的动作。
- **已知局限写进代码注释与文档**：`GetLastInputInfo` 是键盘与鼠标**合并**的信号，「键盘钩子单独被摘除、鼠标钩子还活着」这种半边失效发现不了（心跳一直被鼠标事件喂着）。两个钩子装在同一线程、共用同一处理函数，把回调拖慢的成因对两者是同一个，通常一起被摘掉；真正的根因（把耗时操作移出回调）见 7.2-⑤，本看门狗只是兜底。

**规则/决策**：
- **复位口径：注入出去的东西收回来，缓冲里的东西一律丢弃不回放，锁定层保留**。三条各有反面教材：不收回注入的 `hold`/`sticky` → 系统层面 Ctrl 一直按着（后面敲什么都成组合键）；回放缓冲里的键 → 复位场景（钩子被摘 / 锁屏唤醒 / 切窗口）下前台目标**已经变了**，把旧按键注入到新窗口（可能是密码框、可能是别的程序）比丢掉它们更糟，用户会看到「一串莫名其妙的字符被打进当前窗口」；连锁定层一起清 → 用户显式切过去的层在 Alt-Tab 后莫名失效（锁定层与「按键抬起」无关，和 CapsLock 同理，跨前台切换应当继续生效）。
- **触发通道用轮询而不是回调（也不扩展 `HookHandle`）**：底座已经有单调递增的 `reinstall_count()`，壳层在**状态机定时器线程**上顺带看一眼就行（那个线程本来就每 60ms 跑一次、本来就要拿 `engine` 锁）。做成回调要动钩子 crate 的公开 API 并在钩子线程的消息循环里跑壳层代码，收益为零。代价是复位最多迟一个 tick（60ms），而复位本身是无声兜底，无体感。
- **前台切换必须「连续两轮看到同一个新窗口」才算**：`GetForegroundWindow` 会被瞬态窗口抖一下——我们自己的触发气泡、右键菜单、UAC 提示、桌面切换瞬间。误判的代价是**白复位一次**：用户手上正凑的和弦 / 刚按的序列 leader 会被丢掉。多等一个 tick 就能把这些只晃一轮的窗口全滤掉。另一条对称的坑是**读不到句柄时不能推进 `confirmed`**：锁屏瞬间读空、解锁回到同一个窗口，若把 `None` 当成「换了窗口」，用户每次解锁都要被白复位一次。
- **复位是无声兜底，不进消息中心**：用户此刻没有动作可做（已经自动好了），弹窗/红点只制造困惑。这与「命令结果一律记入消息中心」不冲突——那条针对用户主动触发的动作。只有真的丢了状态（`reset` 返回 `true`）才 `eprintln` 留痕，且复位原因写进日志（钩子重装 / 前台切换）。
- **Linux 两条路径恒不触发是已知受限、不是漏配**：evdev 层拿不到前台窗口（要接 X11/Wayland 协议，见 7.3-⑲），也不存在「被系统摘除后重装」。壳层照旧调用同一接口，占位实现返回 `None`/0，行为是「不复位」——比编造一个假窗口句柄安全。

**验证**：`cargo test --workspace` 159 项全绿（壳 66 / core 73 / 钩子单测 10 + 1 ignored / 钩子冒烟 1 / kada-actions 9）；`cargo check -p kada` 与 `cargo check -p kada --no-default-features` 两版通过；`cargo clippy --workspace --all-targets` 无新增告警（基线清单见下条 P1-⑦）。新增测试覆盖：按住切层键 roll 后复位要「补一个 up」且该键能重新判 hold（不卡在「已按住」）、sticky 锁定后复位也要收回、和弦待定期复位后既**不回放**又能重新凑成同一个和弦、序列待定期复位后 `tick()` 也不再回放而普通键照常放行、锁定层不被复位清掉而 momentary 层退出后回到锁定层、干净状态返回 `false`（不白刷日志）、热串缓冲被清空后不再展开。**未验证**：真实锁屏 → 解锁、真实 Alt-Tab 切换后的复位（需要真人操作 GUI 壳；`reinstall_count` 那条路径依赖看门狗判出「解锁」，其端到端验证现状见本文件 P0-① 条目）。可单测的部分（复位动作本身、前台切换判定）已全覆盖。**逐步操作（含前置配置、预期现象、判失败）见 `docs/人工验证清单.md` §1~§4。** **【2026-09-29 更新】人工验证：§1 / §2 / §3 已通过（前台切换的收回注入与热串不回放、锁屏解锁后的复位），**§4「休眠→唤醒」未执行**——见本节末「人工验证首轮」。**

##### 动作执行超时与中止（P1-⑦）

原 `run_cmd`/`run_script` 用 `Command::output()` **无限等待**：脚本挂住（等输入、死循环、弹了个看不见的确认框）就永久占住这条触发的执行线程——后续动作永不执行、线程也收不回来；同时没有任何「停止正在运行的宏」入口。

**规则/决策**：
- **中止用代数计数器，不用布尔量**：布尔量必须在「新一轮执行开始时清零」，而清零与用户按下停止之间存在竞态——停止请求落在清零之前会被下一轮吞掉（表现为「点了停止没反应」）；反过来不清零则一次停止会让之后**所有**触发一启动就自杀。改成只递增的代数、每轮开始时快照比对，两个问题同时消失：新一轮天然拿到新代数，与旧的停止请求互不干扰。这条有专门的回归（`abort_requested_before_run_does_not_stop_it`）——「点一次停止毒死之后的每一次触发」是最容易写出来的那种 bug。
- **不许用 `.output()` 无限等，且管道必须边跑边读**：`output()` 内部正是用读线程避开「写端阻塞、双方互等」的，所以手写限时循环时这一步**不能省**——子进程输出超过管道缓冲（Windows 约 4~64KB）而没人读时它写阻塞、我们等它退出，超时判定永远等不到，所谓「超时保护」就成了空话。
- **杀进程必须杀整棵树**：我们跑的是 `cmd /C <临时批处理>`、`powershell -Command`、`sh -c`，真正干活的是**孙进程**（脚本本体、被它启动的程序）。`Child::kill` 只杀直接子进程 → 命令「看起来」结束了、脚本还在后台继续跑，而且它占着 stdout 管道，连读线程都不会结束（`wait()` 之后 join 会永远挂住）。Windows 用 `taskkill /T /F`；Linux 要杀树得让子进程自成进程组（`setsid`）再 `kill(-pgid)`，**目前只 `kill()` 直接子进程，列为已知缺口**（本项的可靠性目标是「不再永久占住执行线程」，这一点已达成）。
- **反馈不假装成功**：`abort_actions` 返回的是**请求发出时**正在执行的链数量，前端据此区分「已请求停止（N 条）」与「当前没有正在执行的动作」。若只返回 `Ok(())`，用户在什么都没跑的时候点一下也会看到「已停止」，这属于假的确定性。
- **被强杀的结果要有可见的归因**：超时/中止会把原因写进 `stderr` 前缀、并把 `exit_code` 置 `None`（被强杀的进程退出码不再有语义，留着会被误读成「脚本自己返回了非零」）；真的被中止的链另外补记一条 `kind="abort"` 结果进消息中心，让「点了停止」有回应。
- **超时默认值必须「老配置也拿到」**：字段的零值语义正好是「不限时」，所以 serde 缺省和 `Settings::default()` 都走 `DEFAULT_ACTION_TIMEOUT_MS`（30 秒），不能用 `#[serde(default)]` 的零值——否则本次改动对存量用户等于没生效。

**规则/决策**：
- **失败必须走「结果」这条既有通道，不要另开一套提示**：消息中心已有完整展示（卡片字段、未读红点、托盘红点、弹窗开关），失败只是同一种结果的另一个 `kind`。另开一条路径 = 用户得去两个地方看「刚才那下到底干了什么」。
- **「哪种动作失败」当标签、动作摘要当内容，两者都要**：只给类型（「文件操作失败」）在同一个快捷键挂了多个同类动作时分不清是哪一条；只给摘要则扫一眼 tab 看不出性质。摘要里变量按**本次实际取值**代入（`{target}` → `D:\nope.txt`），因为用户要认的是「刚才那一步拿什么值去做」。
- **`show_output` 沿用动作自身设置，不因为「这是失败路径」就一律静默**：命令/脚本开了「显示输出」，那它**连启动都没成功**（脚本路径不存在这类走 `Err` 而非非零退出码）同样该弹窗——否则用户会觉得「我明明开了显示输出」。
- **失败不中断后续动作（保留原语义）**：动作链是用户排的顺序，某一步失败就中止会把「这一步没成」放大成「后面全没跑」这种更大的意外。这条加了回归固定住。
- **`restart_program` 的容错继续保留**：`let _ = close_program(..)`（关闭失败不阻断重启）。「程序本来就没在运行」是靠退出码非零表达、不进 `Err`，所以这里的忽略是刻意的；`taskkill` / `pkill` 起不来属环境损坏，不为它改变重启语义。
- **失败记录不做去重 / 限流**：同一条坏动作重复触发就重复记（与命令结果一致）；真到刷屏属于 7.4-㉖「消息中心上限与截断」要解决的问题。

**验证**：`cargo test --workspace` 全绿（kada-actions **14**（9 → 14）/ 壳 66 / core 73 / 钩子 10 + 1 ignored / 冒烟 1）；`cargo check -p kada`、`cargo check -p kada --no-default-features`、`cargo check -p kada-actions --no-default-features` 三处通过。新增 5 条：失败记录的类型 / 摘要 / stderr / 退出码 / 触发键字段齐全；失败**不吞掉**后续动作（两条都是失败 → 恰好两条记录）；脚本文件不存在也上报且尊重 `show_output`；摘要代入变量（不留 `{target}`）；超长文本压单行 + 截断（直接调 `action_summary` 验渲染，绕开「文本注入在本机通常成功」的问题）。**未验证**：GUI 里触发一个坏动作看红点与 tab 文案——逐步操作（前置配置 / 步骤 / 预期 / 判失败）见 `docs/人工验证清单.md` §8。**【2026-09-29 更新】人工验证已通过（红点 + tab 文案 + 摘要渲染 + `show_output` 弹窗对照），见本节末「人工验证首轮」。**
